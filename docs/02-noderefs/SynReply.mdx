# SynReply

`SynReply` is a configurable internal node for the middle of a Layer 3 chain.
Place it between two Layer 3 nodes that use the chain-owned worker packet line.

```text
RawSocket -> SynReply -> TunDevice
```

It forwards each original packet unchanged. A complete, unfragmented,
payload-free opening IPv4 TCP SYN received upstream qualifies for a reply if
its headers, options, and IPv4 and TCP checksums are valid. SYNs with valid
options or ECN flags can qualify. Checksum validation uses the bytes as
received and preserves any pending checksum repair request on the original
packet.

If either endpoint is the unspecified address (`0.0.0.0`), the limited
broadcast address (`255.255.255.255`), or multicast (`224.0.0.0/4`), the
packet passes through without a reply.

For each qualifying SYN, including each retransmission, SynReply hands the
original packet upstream before sending one fresh SYN-ACK downstream while the
worker's path is open. The reply goes to the observed sender. Downstream
traffic, including responses from a TCP listener, passes through unchanged.

Handing off the SYN-ACK completes the response. TCP connection state and later
handshake steps belong to the TCP endpoints. The node is built by default with
`INCLUDE_SYN_REPLY`.

## Settings

| Setting | Behavior |
| --- | --- |
| `reply-source-ip` | Optional IPv4 literal to use as the source of every generated SYN-ACK. By default, each reply uses the current SYN's destination address. |
| `ttl` | Optional JSON integer from 1 to 255. Sets the IPv4 TTL of generated SYN-ACKs only. Defaults to 64. |

A configured `reply-source-ip` must belong to the server running SynReply.
The node rejects unspecified, limited broadcast and multicast addresses
for this setting at startup. An empty string, `null`, a
hostname, an IPv6 address, a CIDR, and unknown or duplicate settings cause
startup to fail.

## Examples

These are node fragments. Define `packet-out` as the next Layer 3 node in the
surrounding configuration.

With `settings` omitted or set to `{}`, an upstream SYN to `192.0.2.10`
gets a reply from `192.0.2.10` with TTL 64.

```json
{
  "name": "syn-reply",
  "type": "SynReply",
  "next": "packet-out"
}
```

With the settings below, that same SYN gets a reply from `192.0.2.20` with TTL 48.
Use an address assigned to your server in a deployed configuration.

```json
{
  "name": "syn-reply",
  "type": "SynReply",
  "next": "packet-out",
  "settings": {
    "reply-source-ip": "192.0.2.20",
    "ttl": 48
  }
}
```

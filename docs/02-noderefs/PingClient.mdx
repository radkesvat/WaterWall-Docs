# PingClient

`PingClient` is the client-side endpoint of Ping wire v2. It carries a complete
inner IPv4 packet in a real ICMP Echo Request, and consumes the exact Echo Reply
as a wire acknowledgement. It is a pure packet tunnel with no connection line
state.

Use the paired edges in this order:

```text
TunDevice -> PingClient -> RawSocket
RawSocket -> PingServer -> TunDevice
```

## Two Independent Echo Sessions

Ping v2 never puts new application data into an Echo Reply.

```text
client data: PingClient -- Echo Request(data) --> PingServer
             PingClient <-- Echo Reply(same bytes) -- PingServer

server data: PingClient <-- Echo Request(data) -- PingServer
             PingClient -- Echo Reply(same bytes) --> PingServer
```

The peer sends a type-0 Echo Reply first, then delivers the received request's
inner IPv4 packet once. The request originator matches and consumes the reply,
so echoed bytes are not delivered twice.

| PingClient callback | Behavior |
| --- | --- |
| upstream plain packet | Build a type-8 Echo Request; forward upstream. |
| downstream peer request | Build/send a type-0 reply upstream; strip and forward the original request downstream. |
| downstream matching reply | Consume as acknowledgement. |

## Settings

```json
{
  "name": "ping-client",
  "type": "PingClient",
  "settings": {
    "local-ipv4": "198.51.100.10",
    "peer-ipv4": "203.0.113.20",
    "identifier": "random",
    "sequence-start": 1,
    "ttl": 64,
    "tos": 0
  },
  "next": "raw-out"
}
```

| Setting | Required | Default | Description |
| --- | --- | --- | --- |
| `local-ipv4` | yes | — | Local source of requests/replies. |
| `peer-ipv4` | yes | — | Request destination and expected source of peer carrier traffic. |
| `identifier` | no | `"random"` | Stable local request-session ID. Integer `0..65535` is a deterministic override; random defaults are nonzero. |
| `sequence-start` | no | `1` | First local request sequence, `0..65535`; wrap is valid. |
| `ttl` | no | `64` | Locally generated packet TTL. |
| `tos` | no | `0` | Local request TOS. Generated replies copy the peer request TOS. |

Client and server identifiers are intentionally independent. A reply mirrors
the request's identifier and sequence rather than the responder configuration.

## Wire and Safety Rules

The wire format is exactly:

```text
20-byte IPv4 header -> 8-byte ICMP Echo header -> complete inner IPv4 packet
```

- Local requests: type `8`, code `0`, configured source/destination/TOS/TTL,
  DF set, IPv4 ID `0`, local identifier, and ascending sequence.
- Peer replies: type `0`, code `0`, reversed addresses, copied request
  identifier/sequence/payload length/payload bytes, copied request TOS, local
  TTL, and cleared fragmentation bits.
- Reply IPv4 IDs come from a securely seeded tuple-scoped Linux-like
  approximation. This is not host-global Linux kernel state.

Input must be an exact IPv4 packet no larger than `1472` bytes. Valid inner IPv4
fragments are supported; outer carrier fragmentation, invalid checksums,
malformed lengths, IPv6/non-IPv4 input, and oversized packets are dropped.
Structurally valid traffic unrelated to the configured carrier tuple passes
through unchanged in the same direction.

One synchronized node-wide tracker has a 1024-entry outstanding ring and a
1024-entry replay ring. Device worker affinity is not correlation identity: a
reply or duplicate request can arrive on another packet-line WID and still
match. Duplicate peer requests get another reply but deliver their inner data
once. The 28-byte carrier overhead gives a 1500-byte maximum packet; Ping does
not fragment, perform PMTU discovery, or adjust MSS.

## Breaking Migration From v1

Only the six settings above are accepted. `strategy`, all `wrap-*`/`warp-*`
modes, `source`, `dest`, protocol-swap settings, `check-identifier`,
`ipv4-id-start`, `xor-byte`, `roundup-size`, and `roundup` are removed and
produce a migration error.

Replace `source`/`dest` with `local-ipv4`/`peer-ipv4`; reverse them on the
server. Upgrade both peers together: v2 is not compatible with the removed
wire formats.

Correct Echo semantics reduce protocol fingerprints but do not make arbitrary,
high-rate tunnel traffic indistinguishable from interactive `ping` traffic.

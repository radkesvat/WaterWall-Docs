# HintPacketIN

`HintPacketIN` tells a client that the rest of the chain consumes IP packets.
The edge to `next` is Layer 3 (`kNodeLayer3`). Use
[HintConnectionIN](./HintConnectionIN.mdx) for a chain that consumes WaterWall
connections.

## Profile format

Use the exact `type` value `HintPacketIN` and choose a unique `name` for the node.
The hint must be the chain head, so no other node may point to it. Its `next`
must name an existing node that accepts the required layer. Its position in the
`nodes` array is immaterial. Omit `settings` or supply an empty object.

This inspection example uses [BlackHole](./BlackHole.mdx), which accepts either
input layer. To run a resolved copy, also set the sink's required
`settings.mode` to `"passive"`.

```json
{
  "name": "Input hint example",
  "nodes": [
    { "name": "sink", "type": "BlackHole" },
    { "name": "entry", "type": "HintPacketIN", "next": "sink", "settings": {} }
  ]
}
```

## Standalone startup

WaterWall rejects an unresolved hint before constructing any tunnel in that
configuration. Follow the [client handoff](./HintConnectionIN.mdx#client-handoff)
to supply concrete packet input.

> HintPacketIN requires a packet input. Replace this hint with a concrete input before starting WaterWall.

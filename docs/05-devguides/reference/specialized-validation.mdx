# Specialized validation

Choose proportional validation using [Part 6](../part6-build-test-review.mdx), then consult the relevant subsystem below. These cases supplement the common validation policy; they do not make every specialized lane mandatory for unrelated work.

## Specialized validation reference {#specialized-validation-reference}

### Trojan UDP size coverage {#trojan-udp-size-coverage}

`waterwall.trojan_udp_size_probe` carries IPv4 UDP through a WaterWall
TrojanClient/TrojanServer pair over TLS/TCP. Its payloads include empty, 8191-,
8192-, 8193-, 32768-, 65400- and 65507-byte datagrams; asymmetric request/reply
sizes include a small request followed by a maximum-sized socket reply. Exact
bytes and one-datagram delivery matter in both directions. Native client/server
fixtures separately exercise the 65535-byte framing boundary and reject local
65536-byte bodies; these codec checks do not attempt an impossible 65535-byte
ordinary IPv4 UDP send. Carrier fragmentation must preserve the complete datagram.

### Trojan and VLESS independent-peer coverage {#trojan-and-vless-independent-peer-coverage}

`waterwall.trojan_sing_box_{client,server}_{tcp,udp}` and
`waterwall.vless_sing_box_{client,server}_{tcp,udp}` exercise both WaterWall roles
against pinned sing-box 1.12.0. Each short case has a 25-second timeout and uses
the namespace harness. Provision the shared peer with
`cmake --build --preset linux --target waterwall_vmess_SING_BOX_reference`;
this target also exists for enabled Trojan/VLESS cases when VMess is disabled.
Run the eight cases with
`ctest --preset linux --output-on-failure -j8 -R '^waterwall\.(trojan|vless)_sing_box_'`.

Trojan uses TLS and VLESS uses native framing with empty flow and explicit empty
packet encoding; multiplexing is disabled. The sing-box TLS client verifies the
local fixture certificate. The WaterWall TLS client uses explicit `verify: false`
because it has no custom local CA setting. TCP exchanges include 65536-byte
payloads. UDP requires exact 8192-, 8193- and 15000-byte payloads and asymmetric
request/reply sizes. Empty replies work in both roles; empty requests are checked
only with WaterWall as client because the pinned direct sing-box ingress drops
them. Readiness retries use a distinct token; measured packets are never retried.

These are positive interoperability checks. sing-box's 16 KiB packet buffers
reserve protocol headroom, so their usable payload is smaller and varies by
path. The 15000-byte workload does not reduce WaterWall's limits or replace its
near-65 KB pair/native coverage. The fixture and full topology are documented in
`tests/cases/singbox_proxy_interop/README.md`.

### VMess independent-client coverage {#vmess-independent-client-coverage}

When either VMess endpoint is included, provision the checksum-pinned official
V2Ray 5.53.0, Xray 25.6.8 and sing-box 1.12.0 archives before entering test
namespaces. The aggregate target provisions all three; tests never select a
latest release or download inside a namespace:

```bash
cmake --build --preset linux --config Release --target waterwall_vmess_reference
ctest --preset linux --output-on-failure -R vmess
```

`WATERWALL_VMESS_REFERENCE`, `WATERWALL_VMESS_XRAY_REFERENCE` and
`WATERWALL_VMESS_SING_BOX_REFERENCE` can identify already provisioned executables.
The fixture checks each executable's exact release version. Official archive
names and SHA-256 digests live in `tests/provision_vmess_reference.py`; the small
`tests/vmess_reference.py` adapter uses each peer's native configuration schema.
Cases use only loopback destinations and local certificates. Missing peers or
namespace privileges are unavailable validation, never passed interoperability.

The exact-8-KiB cases measure **8192 application bytes**, excluding protocol
headers. Positive WaterWall-pair and sing-box cases require complete matching
request/reply datagrams. Negative Xray/V2Ray size-limit cases require a successful
small control exchange before verifying that an intact oversized echo cannot
complete; those passes record a known peer limit, not successful 8-KiB interop.
The bounds come from the pinned [Xray authenticated writer](https://github.com/XTLS/Xray-core/blob/v25.6.8/common/crypto/auth.go#L249)
and [V2Ray authenticated writer](https://github.com/v2fly/v2ray-core/blob/v5.53.0/common/crypto/auth.go#L251),
whose full-frame buffer sizes are respectively [8192](https://github.com/XTLS/Xray-core/blob/v25.6.8/common/buf/buffer.go#L12)
and [2048 bytes](https://github.com/v2fly/v2ray-core/blob/v5.53.0/common/buf/buffer.go#L10).
These peer limits do not reduce WaterWall's codec capacity or describe TCP transfer
limits. Never truncate or divide an application UDP datagram to hide a peer limit.

`tests/cmake/integration/vmess.cmake` registers a direction only when its required
targets exist. Existing local/managed WaterWall pairs retain admission, rotation,
quota, replay, fallback, destination, local-DNS and transport regressions. Added
cases cover auto selection, server security refusal before target/fallback Init,
short-ID/canonical-UUID boundaries, termination choices and real registered stats
through APIServer. Server packetaddr cases interleave two destination backends and
reverse replies to verify address association. Native fixtures exercise exact
codec maxima and bounded-map/reentry ownership independently of peer limitations. WaterWall-pair packetaddr coverage retains the 65400-byte workload.

Long encrypted cases perform 65540 stop-and-wait nonempty request/echo exchanges
on one persistent socket. Waiting for each echo before creating the next request
forces more than 65536 records in both directions; a relay accepts one transport,
so reconnection cannot make the case pass. AES and ChaCha cases include padded
peer framing and authenticated-length profile 29. Strict cases verify 65535
successful exchanges followed by closure before outgoing nonce reuse. The
separate zero/TLS long transfer and NONE/TLS UDP cases configure the peer to verify
the local certificate. Existing outbound TLS regressions keep their explicit
verification setting; TlsClient has no local custom-trust setting for an additional
locally verified outbound fixture.

Long and strict interoperability cases use CTest `RUN_SERIAL` so their 65-second
stop-and-wait workload does not compete with other tests in the same invocation.
The record counts, one-transport requirement and 75-second outer timeout remain
unchanged. Workload deadline diagnostics include completed exchanges and elapsed
time. V2Ray UDP cases wait for the returned relay's UDP-listening log before
sending: its SOCKS TCP listener starts before its UDP listener, so a successful
UDP ASSOCIATE alone does not establish UDP readiness. Datagram timeouts identify
the payload, receive stage, endpoints, sent requests and child exit statuses;
the fixture does not retry lost datagrams.

QUIC constructor validation runs client and server roles separately, with a
360-second aggregate budget per role for their repeated packed application
launches. Individual configuration startup and orderly-shutdown deadlines remain
8 and 10 seconds respectively.

### Registered API coverage {#registered-api-coverage}

`tests/cmake/native/api.cmake` registers APIServer envelope, session and reliable
stream fixtures; `api_core.cmake` covers the registry/resolver and detached
worker dispatcher. Private echo/binary/large-result operations belong only to
these fixtures. Large reliable-stream coverage uses the actual KCP nodes
with deterministic datagram loss and reordering, and requires one complete
response above 65 KiB with one dispatch. It must not introduce a public diagnostic
echo operation or randomized pass/fail impairment.

`tests/cmake/integration/api.cmake` registers real AuthenticationClient status
queries over TCP, HTTP/1.1 bodies and reconstructed KCP streams, plus
qualified/ambiguous selectors across loaded configurations. HTTP probes dechunk
before reading the API length and recognize replies without waiting for EOF.
`waterwall.api_authentication_server_views` separately exercises the server's
registered status, detail and paginated summaries through `TcpListener ->
APIServer`, without requiring AuthenticationClient. Its private existing-protocol
connection performs real authorized `UpdateUser` and `PushUserStats` setup: a
configuration edit invalidates the cursor, while a usage batch and exact replay
permit continuation with the current totals. The probe also checks exact large
IDs, field allowlists, credential omission and status-only operation permissions.
It additionally checks matching read edit tokens, explicitly permitted conditional
edits, protocol/unrelated-account conflicts, sparse/accounting preservation and
same-value revision increments. Its 1024-byte gateway accepts an acknowledgement
with a maximally escaped allowed correlation ID. A discarded reply body requires
a fresh read to establish committed state; reuse of the old token cannot commit
the edit again. Provider/dispatcher fixtures separately prove precommit refusal,
two-writer contention, late completion and shutdown abandonment. Do not claim an
unavoidable postcommit envelope-size failure for this bounded acknowledgement.
The generic codec fixture checks the absolute maximum acknowledgement envelope
with UINT64_MAX account ID/revision, a canonical 48-character edit token and the
maximally escaped allowed 64-byte correlation ID against that minimum cap.
The same real gateway fixture checks independently permitted creator tokens,
monitor/auditor/editor rejection of creation and producer-credential isolation.
It creates default, empty-config and fully configured accounts, checks zero
first-use/usage, normalization and public redaction, and refuses duplicate IDs,
credentials, names and ranges without changing revisions or existing accounts.
A creation ACK also traverses the 1024-byte endpoint with maximum correlation-ID
escaping. Discarding a creation reply preserves its account, while repeating the
same ID yields `id_exists`. Real protocol password lookup/add collision and
native AuthenticationClient refresh/offline catch-up fixtures cover credential
availability, revision ordering and preservation of existing pending usage.
The existing maximum mutation-ACK codec proof covers the identical creation
response schema; no second token format or duplicate envelope proof is needed.
Run creation parser/ownership/growth coverage under Debug ASan/UBSan and
creation/reader/duplicate races under Debug TSan with actual compile/link flags.

Password coverage uses the real registered `change-user-password` handler and
collection helpers. Provider/native cases exercise strict bounded input, typed
backend/collision refusals, all credential lookups and UUID transitions, unchanged
identity/accounting, contention, capacity/old-password bounds, deadline/budget
refusals and revision exhaustion. The real namespace case grants a separate
password administrator, denies monitors/editors/creators/producer credentials,
looks up exact Unicode/whitespace passwords through the existing protocol, checks
same-value revision and cursor invalidation, and replays a real usage ACK unchanged.
Its discarded reply is followed by a redacted read and explicit fresh-token
resubmission; the read alone does not establish the installed password. The same
1024-byte endpoint and maximum-ACK codec check cover this identical response schema.
The production support case `waterwall.api_example_client` runs the real example
CLI with a deterministic transport seam: successful/node-failed/conflicting and
unknown replies take one attempt, explain explicit recovery, and never print the
password or operator token. It does not replace the real namespace transport case.

The Python administration client adds `waterwall.api_admin_client` and the shared
transport's `waterwall.api_transport_client` to the same support lane. They cover
command validation, bounded pagination, explicit edit tokens, exact secret input,
framing and response validation, and conservative write-outcome classification.
The namespace case `waterwall.api_admin_cli` runs the actual CLI against a real
AuthenticationServer/APIServer chain for account workflows. Its fixture and
Python test files document the direct commands; no native C build is required for
the isolated Python tests.

Administrative audit coverage adds `waterwall.authenticationserver_audit_unit`
for real registered mutation outcomes, secret omission, bounded queue overflow,
writer failure isolation, producer save-failure rollback and shutdown drain. It gates the actual append boundary
with a linker wrapper to fill the queue deterministically; no production test
hook is required. Checked-writer units separately exercise file startup, append,
rotation and native I/O failures. `waterwall.api_authentication_audit` uses two
workers and private loopback to check API/producer outcomes, gateway identity,
malformed-input redaction and a committed operation whose reply is discarded.
Read-only status polling waits for output; no mutation is retried. The Python
administration tests validate both healthy and degraded audit status without
printing arbitrary native errors. Run the new native tests in Debug/Release and
with concurrency/memory instrumentation; these checks do not establish
transactional or crash-durable audit delivery.

`waterwall.authentication_sync_unit` rotates through the real API with two clients
on different reconnect schedules, a lost usage ACK and exact pending-batch replay,
and separately a held pull with traffic produced in flight. Verify each client's
old/new credential availability before/after its refresh, exact aggregate traffic,
first-use evidence/ACK and expiry projection, reservations and release/accounting
through an existing handle. Run the focused native selection in Debug and Release,
plus parser/preparation/index/runtime ownership under real Debug ASan/UBSan and
reader/password/duplicate races under real Debug TSan. Confirm actual compile/link
instrumentation; an unsanitized optimized target is not sanitizer evidence. Build
the normal production unity target as well: private helpers included in one unity
translation unit must have unique identifiers. Do not disable unity to hide a
collision or require byte-identical JSON object iteration order across builds.

The probe runner accepts an optional `configs.txt` listing unique local JSON
basenames in loading order; absent that manifest, it loads `config.json`.

Run focused API and authentication selections in Debug and Release, and explicitly
select added tests when sanitizer preset filters omit them. Envelope tests do
not prove transport framing or worker lifetime; use the session/dispatcher and

[Part 6](../part6-build-test-review.mdx#choosing-validation-and-regression-coverage). Feature

The user-index regression includes forced probe chains beyond the compact STC

both configurations; hashing changes alone do not establish collision correctness.
Authentication coverage exercises bounded producer JSON, immutable snapshot
continuation across edits, lease/resource refusal and cleanup, retained orphan

Malformed or unproved responses must preserve uncertain batches. Gateway session
coverage also exhausts the anonymous-memory domain while an authenticated line
continues dispatching and verifies immediate decoded-token clearing.

### Synthetic integrity testers {#synthetic-integrity-testers}

`TesterClient` owns its normal stream lines; `TesterServer` borrows incoming normal
lines. In packet mode both use chain-owned worker packet lines. Preserve their external
size, pattern, ordering and checksum checks when simplifying internal checks.
The exact stream byte budget makes a second trailing-byte failure after complete,
callback-free chunk consumption redundant; the entry budget check remains required.

The first request payload byte selects the flow id; it does not exempt the rest
of that chunk from pattern verification. UDP and ICMP chunks can contain more
than one payload byte even at index zero. Checksum verification must preserve
the received bytes, including on failure: stateless matching may retry the same
packet with another candidate flow id, and must never accept a checksum repaired
by an earlier attempt.

For immediate packet startup, publish the client's one-time send admission before
calling the next `Init`. A synchronous `Est` or `Resume` must not bypass the
configured startup delay or schedule another sender. Retain normal `Est` marking, task-admission
failure handling and callback-lifetime checks.

### Shared checksum regression coverage {#shared-checksum-regression-coverage}

`bufio_contract_unit` and its no-splice variant cover packet request reset/reuse,
whole-copy independence and refusal, growth and byte-range limits. Packet-tunnel,
affinity, bridge, Ping and IpManipulator fixtures cover buffer-local intent through
reentry, worker delivery, drop, duplication and raw-byte handoffs, including
ProtoSwap repair before encoding and intentional bad checksums left unrequested.
Run the relevant fixtures and complete native suite in Debug and Release for
shared buffer/packet contract changes. The external-node fixture rejects the
immediately preceding ABI before its getter and accepts current-header nodes.


`lwip_checksum_backend_test` exercises real lwIP checksum and copy entry points
through a linker-wrapped adapter, checking results against an independent byte
oracle. It covers unaligned and large spans, read-only guard pages, odd/empty
pbuf fragments, IPv4/IPv6 pseudoheaders and partial coverage, TCP odd writes and
retransmission, cascading payload/seed carries, corruption rejection, and
protocol checksum-zero behavior. The carry-overflow vector is also checked
through TCP output and standalone pre-initialization dispatch.
`lwip_checksum_variants_test` runs the same cases through a private test-build
dispatch instance for portable C and CPU-supported SSE3/AVX2 backends. Production
exposes no mutable backend test switch. Both tests exercise pre-initialization
portable behavior before selecting a backend.

Run both in Debug and Release alongside `wchecksum_test`,
`device_checksum_validity_test`, and `tun_linux_offload_test`. Comparisons between
`calcGenericChecksum()` and lwIP alone are not independent correctness evidence:
both now share the backend. `lwip_checksum_link_test` is a portable standalone
archive link/startup check and participates in platform unit builds. A
cross-compiled executable proves linking only; little-endian execution does not
establish big-endian runtime coverage.

### TUN TCP Chain Correctness And Throughput {#tun-tcp-chain-correctness-and-throughput}

On native Linux, `waterwall.tundevice_tcp_chain` exercises the exact chain
`TunDevice → PacketsToConnection → TcpConnector` with `gso` explicitly disabled
and enabled, default multiqueue and explicit single-queue receive, and omitted
(prefix), peer, spread and auto opaque settings. Native TCP stays on the shared
worker policy in every opaque mode. Auto falls back to prefix at the direct PTC
neighbour. The fixture checks requested/effective/reason and effective-mode/queue
startup diagnostics. It verifies payload bytes in both directions,
concurrent TCP connections, checksum-only framing with segmentation disabled,
actual GSO activity when enabled and supported, and clean shutdown. The fixture
checks virtio framing and actual checksum/TSO4 features separately.
The test uses Python sockets and does not require iperf3. It belongs to the
privileged lane. The runner creates fresh runtime and peer namespaces through the
existing network namespace wrapper, after checking that isolation is available.
Run it directly after building Release:

```bash
cmake --preset linux -DWATERWALL_ENABLE_PRIVILEGED_INTEGRATION_TESTS=ON
cmake --build --preset linux -j8
sudo -E ctest --test-dir build/linux -C Release --output-on-failure \
  -R '^waterwall\.tundevice_tcp_chain$'
```

`waterwall.tundevice_gso_live` verifies both offload modes, including deferred
ordinary TCP/UDP and kernel-normalized versus userspace GSO wire bytes.
`waterwall.tundevice_trusted_checksum` covers direct and interposed checksum-only
and GSO TCP/UDP chains, lazy trust activation, MTU boundaries and independent
peer-byte checksums with controlled software egress. Kernels need not mark every
live packet `NEEDS_CSUM`: `tun_linux_message_lifetime_unit` deterministically
proves destination-worker completion for odd IPv4/plain IPv6 TCP/UDP, compact
storage, FIFO order, capacity wakeup, stale discard and foreign cancellation in
both modes. Its syscall seams also cover CSUM-first negotiation, upgrade rejection,
raw fallback, common-resource rollback, safe GSO resource downgrade and named
attachment policy. Run it in Debug and Release alongside offload, configuration,
reader-session, affinity, checksum-validity, lifecycle and lwIP checksum/trust units.
Raw lifecycle fixtures explicitly inject unavailable offload.

The checksum fixture explicitly sets its private TUN queue to 16,384 entries so
four concurrent 1 MiB uploads at MTU 576 do not spend the transfer deadline
recovering from fixture-induced loss. This avoids dependence on the kernel's
500-entry default or the selected profile's automatic startup queue target.

The same runner, `tests/tun_tcp_chain.py`, provides the optional
`waterwall.speedtest_tundevice_tcp_chain` iperf3 comparison. Enable it separately;
`WATERWALL_ENABLE_TUN_TCP_SPEEDTEST` defaults to `OFF`, so ordinary test runs do
not perform this longer benchmark:

```bash
cmake --preset linux -DWATERWALL_ENABLE_PRIVILEGED_INTEGRATION_TESTS=ON \
  -DWATERWALL_ENABLE_TUN_TCP_SPEEDTEST=ON
sudo -E ctest --test-dir build/linux -C Release --output-on-failure \
  -R '^waterwall\.speedtest_tundevice_tcp_chain$'
```

The benchmark runs serially with four workers, the server RAM profile, and MTU 1500. For both one and four
TCP streams it collects three GSO-off/on pairs, alternating order, with two seconds
of warm-up followed by ten measured seconds per sample. Paired runs reuse the
same flow tuples so worker assignment is repeatable. Results include each sample,
throughput medians and ranges, CPU usage, and retransmits in JSON. CPU seconds
cover the full client run, including warm-up. Successful
execution and valid measurements determine pass/fail; there is no minimum
throughput or requirement that GSO be faster. Host contention and run-to-run
variation must be considered before drawing performance conclusions.

Both modes require Linux TUN support and the privileges to configure their private
network namespaces; the speed mode also requires iperf3. Missing runtime
capabilities or dependencies are reported as skipped (exit 77), not passed. Speed
runs always retain their run directory, including raw samples, generated settings,
logs, `results.json`, and `summary.json`. Integration runs retain any created run
directory on failure or skip; set `WATERWALL_TEST_KEEP_RUN_DIR=1` to retain it on
success too. When enabled, the optional benchmark is selected by both the speed
and privileged lane labels.

CI's manual `extended_tests` input enables the speed and stress lanes in the
`linux-gcc-x64` job. That selection also installs iperf3 and enables this benchmark.
The unprivileged speed lane excludes privileged cases; the subsequent privileged
lane runs it with `sudo`. Routine push/pull-request runs and other matrix entries
leave the benchmark disabled.

:::tip Write a test that would fail if direction were reversed
The highest-value test for a flow or packet change is one that breaks if you swap
upstream/downstream handling. For paired tunnels (client/server, encode/decode),
that single assertion catches the most common regression in this codebase. See the
direction rules in [Part 2](../part2-lines-and-callbacks.mdx) and
[Part 4](../part4-packet-tunnels.mdx).
:::

### Kernel queue tuning coverage {#kernel-queue-tuning-coverage}

Run `device_kernel_queue_tuning_unit` and the focused TUN/Capture native and node
configuration units in both Debug and Release for startup sizing changes. Check
profile targets, automatic caps, final queue counts after fallback, explicit
overrides, preserved larger values and strict input rejection even when disabled
or on an inactive capture path. Native fixtures must exercise disabled tuning,
request/readback failure, refused NFQUEUE ACKs, same-namespace socket probe
failure and host-capped `SO_RCVBUF`. A failed probe or one that cannot confirm an
increase must preserve the existing queue buffer and close its temporary socket,
without turning a usable queue into a startup failure. Unknown kernel values must remain
unknown in diagnostics; requested values are not evidence of accepted capacity.

Use the private-namespace TUN and Capture integrations to check startup,
single/multiqueue operation, exact packet delivery and cleanup. These correctness
checks do not establish a throughput gain or loss-free operation at saturation.
Any performance comparison must fix the workload, queue policy, MTU/offload,
worker count, metrics and sample order before measuring, following the optional
[optimization policy](../part6-build-test-review.mdx#optional-optimization-and-evidence-review).

## Worker-engine lwIP validation {#worker-engine-lwip-validation}

Production uses `NO_SYS=1`, raw APIs, no tcpip thread/core mutex, and explicit
shared allocator protection. The pinned-source engine, pool, port, timer,
lifecycle, checksum, ACK-batch, receive-budget and TCP timestamp patch recipes participate in the same
regeneration stamp as the pretend patch. Canonical recipes live under `ww/lwip/`;
`radkesvat_changes.txt` retains historical notes and points to those recipes.
Generated `patched-deps` trees are never
edit sources. Literal single-site edits require exactly one occurrence; intentional
repeated edits declare their expected count and reject drift before writing.
Engine token relocation retains both regex passes because consumed boundaries
can hide adjacent matches on the first pass.

`lwip_engine_isolation`, `lwip_engine_pools`, `lwip_engine_ports` and
`lwip_engine_ids` use a private small-capacity raw build to reach shared limits
and overlap real stack operations on two owners. `lwip_engine_runtime`,
`lwip_ptc_engine`, `lwip_ctp_roundtrip` and `lwip_shutdown` cover actual event
workers, timers, bridge routing and lifecycle. Existing checksum, netif, fragment,
refusal and affinity fixtures retain their behavioral assertions. Logical-owner
fixtures alone do not prove event-loop or shutdown behavior. `lwip_udp_reuse_unit`
uses a private stack with both reuse options enabled to check fan-out eligibility,
clone refusal/settlement and the ordinary UDP length contract; production reuse
options remain disabled.

`lwip_timestamp_boundaries_unit` uses a private timestamp-enabled stack while
production timestamps remain disabled. Real TCP handshakes and captured output
check unsigned timestamp decoding and echoing, small peer MSS and receive-window

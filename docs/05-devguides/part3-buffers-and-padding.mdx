# Part 3: Buffers, Padding & Shift Buffers

If your change frames payloads, prepends a header, rewrites bytes in place, or
allocates working memory, you must understand `sbuf_t`, the buffer pools, and the
chain-wide left-padding contract. Getting this wrong produces tunnels that work in
one chain layout and corrupt memory in another.

Source of truth: `ww/bufio/shiftbuffer.h`, `ww/bufio/buffer_pool.h`, and the
`required_padding_left` field in `ww/objects/node.h`.

## The `sbuf_t` Anatomy

WaterWall payloads are carried in `sbuf_t` ("shift buffer"), a padded, shiftable
byte buffer. Its header is exactly 32 bytes and the allocation's data area is
32-byte aligned:

```c
struct sbuf_s
{
    uint8_t *data;             // current payload start within head[]
    size_t   len;              // current payload length, in bytes
    size_t   capacity;         // ordinary: storage capacity; splice: logical geometry
    uint16_t initial_headroom; // original aligned reservation, constant for this allocation
    uint16_t flags;
    MSVC_ATTR_ALIGNED_32 uint8_t head[] GNU_ATTR_ALIGNED_32;
};
```

`head[]` is the fixed storage base, while `data` moves inside that allocation.
Lengths, capacities and byte-count APIs use `size_t`; allocation and logical
capacity remain bounded by `UINT32_MAX` and the target's allocation-size limit.
For ordinary buffers, the cursor moves inside a fixed allocation. The flag
`kSbufFlagSplice` gives the payload a different representation, described below.

Fresh and reset ordinary buffers start at `head + initial_headroom`, with the
initial reservation rounded to 32 bytes. Moving `data` can change the current
payload's alignment; allocation alignment alone does not justify aligned loads
or stores through `sbufGetRawPtr()` or
`sbufGetMutablePtr()`. Check the actual address, including any copy offset.

The storage diagram and accessor descriptions here apply to ordinary buffers:

```text
   |<-- current headroom -->|<----- payload (len) ----->|<-- writeable tail -->|
   +------------------------+--------------------------+----------------------+
head                      data                     data+len       head+capacity
```

- **`data`** moves left when you prepend (shift left) and right when you consume
  from the front.
- **`len`** is how many payload bytes are valid starting at `data`.
- **Initial headroom** (`sbufGetInitialHeadroom`) is the original aligned
  reservation stored in `initial_headroom`. It remains constant for the
  allocation's lifetime, even after cursor movement.
- **Current headroom** (`sbufGetHeadroom` = the byte offset from `head` to `data`)
  is how many bytes you can still prepend by shifting left.
- **Writable capacity** (`sbufGetWritableCapacity` = `capacity - headroom`)
  is how much you can address forward from the cursor, including current payload.
- **Tailroom** (`sbufGetTailroom` = `capacity - headroom - len`) is the
  spare room available to append bytes without growing an ordinary buffer.
  It requires valid ordinary geometry; it is not available for splice buffers.

Current headroom can exceed the initial reservation after consumption. For
example, with sufficient payload and initial headroom 64, prepending 12 bytes
leaves current headroom 52; consuming 20 front bytes then makes it 72. Initial
headroom remains 64 throughout.

### Key Accessors

| Call | Returns |
| --- | --- |
| `sbufGetLength(b)` | logical payload length (`len`), including a splice body |
| `sbufGetResidentView(b)` | borrowed `sbuf_read_view_t` containing the current `data` pointer and immediately readable `length` |
| `sbufGetResidentPrefixLength(b)` | immediately readable byte count, without obtaining a pointer |
| `sbufGetRawPtr(b)` | borrowed `const uint8_t *` to the payload start (`data`) |
| `sbufGetMutablePtr(b)` | borrowed `uint8_t *` to the payload start; requires mutable `sbuf_t *` |
| `sbufGetHeadroom(b)` | `size_t` byte offset from `head` to `data`, available to prepend |
| `sbufGetWritableCapacity(b)` | bytes addressable from the cursor (`capacity - sbufGetHeadroom(b)`) |
| `sbufGetTailroom(b)` | spare append space in an ordinary buffer (`capacity - sbufGetHeadroom(b) - len`) |
| `sbufGetTotalCapacity(b)` | ordinary storage capacity including headroom, excluding the sbuf header and allocator overhead; constant for that allocation |
| `sbufGetInitialHeadroom(b)` | `uint16_t` original aligned `initial_headroom` value |

Read-only accessors and copy/duplicate source parameters accept const buffers.
The raw pointer supports byte indexing without discarding const; use the mutable
accessor only when the buffer is owned for mutation. Neither accessor proves
that a splice body's logical bytes are resident. Const access does not extend
ownership or lifetime, and queued buffers must still be popped before mutation.

`sbufGetResidentView()` pairs the current pointer with its resident bound:

```c
sbuf_read_view_t view = sbufGetResidentView(buf);
for (size_t i = 0; i < view.length; ++i)
{
    inspectByte(view.data[i]); // inspection does not mutate or transfer buf
}
```

| Buffer state | `view.data` | `view.length` |
| --- | --- | --- |
| Ordinary payload | Current `data` | Complete active payload length |
| Splice prefix followed by pipe body | Current `data` | Only the resident prefix before metadata |
| Splice body with no prefix | Metadata boundary | Zero, even with positive logical length |
| Empty buffer | Current `data`, possibly an ordinary one-past position | Zero |

The view is a borrowed snapshot. Reacquire it after mutation and discard it before
storage replacement, destruction, recycling, or ownership transfer. It does not
extend lifetime, synchronize threads, or certify alignment. Never dereference an
empty view. The accessor performs no allocation, copying, materialization,
consumption, syscalls, callbacks, or ownership transfer; it does not expose private
pipe metadata as payload. Both resident accessors live in `shiftbuffer.h` and work
without platform splice support. They require valid geometry; corrupt state is a
programmer error, not an empty-view result.

A zero-length view is not EOF and does not prove that more network input is
needed: logical bytes may already reside in a private pipe. Use staged gathering,
range helpers, or explicit materialization when parsing requires those bytes.
Raw accessors remain valid for exposed splice prefixes, but supply no readable
length by themselves.

Create and reset set `data` to `head + initial_headroom` and length to zero.
Reset preserves an ordinary buffer's capacity and initial headroom.
`sbufDuplicate()` and `sbufDuplicateTo()` preserve the source's current headroom
by rebasing `data` into the destination's own `head[]`; copying the absolute
pointer would keep referring to the source. `sbufDuplicate()` also preserves the
source's initial headroom, while `sbufDuplicateTo()` leaves the destination's
initial headroom unchanged.

On its successful pooled-copy path, `sbufDuplicateByPool()` places the copied
payload at the destination's initial headroom. If no configured tier matches or
the selected pooled destination cannot fit the complete payload, it falls back
to `sbufDuplicate()`, preserving the source's current and initial headroom.
Growth may replace and free the allocation, restoring its initial headroom.
Use only the returned buffer and reacquire payload pointers after any operation
that may replace it. Prepending and consuming move `data` without moving bytes.

Use `sbufGetHeadroom()` for the cursor offset. On supported flat-address
targets, it subtracts `uintptr_t` addresses so an offset above `PTRDIFF_MAX`
remains representable on a 32-bit target. Direct `data - head` pointer subtraction
does not provide that guarantee.

### Cursor Shifts

Both cursor helpers return `uint8_t *` pointing to the updated `data`:

| Call | Effect and precondition |
| --- | --- |
| `sbufShiftLeft(b, bytes)` | Prepend `bytes`: subtract from `data`, add to `len`; requires `bytes <= sbufGetHeadroom(b)`. |
| `sbufShiftRight(b, bytes)` | Consume resident front bytes: add to `data`, subtract from `len`; requires `bytes <= len` and, on splice input, `bytes` within the resident prefix. |

A zero-byte shift returns the existing `data`. Complete ordinary consumption
can return a valid one-past position; an empty buffer's result must not be
dereferenced. The returned pointers are borrowed: they do not extend buffer
lifetime and must not be used after replacement, destruction, recycling or
ownership transfer. Another shift can change the current payload start without
freeing the allocation.

Neither helper allocates, replaces storage, transfers ownership, invokes
callbacks or returns an error sentinel. The result may be ignored when no raw
pointer is needed. Returning a pointer establishes neither alignment nor that
`len` bytes are resident; splice bodies still require their dedicated helpers.

Prepending extends length before filling the exposed region. Keep that interval
private: initialize every new byte synchronously before inspection, queue
publication, callbacks, or ownership handoff. This requires a guaranteed complete
fill; a producer that can fail or return a short result must commit only its actual
successful output instead.

Ordinary Ping and direct Ping6 reserve nine left bytes for Echo plus the final
protocol trailer. Ping6 `ipv6-in-ipv4` reserves 49, including a 40-byte IPv6 base
header. Set the mode-specific per-instance `required_padding_left` in construction,
before chain insertion accumulates it. Left padding grants no tail space: for
framing size F = 9 or 49, encoding first moves the actual IPv4 header left F,
then body left one; decoding first moves body right one, then header right F,
before advancing F. The allocation's used end stays fixed. Use overlap-safe moves and unaligned-safe field/checksum access.
The trailer lies inside the declared IP packet and visible checksum coverage.
Native TCP/UDP address normalization and carrier-only repair follow the
[paired-Ping contract](./part4-packet-tunnels.mdx#paired-tunnel-direction-the-pingclient--pingserver-rule).

### Reading and Writing

These helpers read or overwrite bytes at the **current front**. They do not
append, consume bytes, move the cursor, or publish a new payload length:

| Helper | Caller establishes | Effect on cursor and length |
| --- | --- | --- |
| `sbufRead(b, dest, n)` | `n` resident payload bytes and a writable, nonoverlapping destination | Neither changes; copies from the current front |
| `sbufWrite(b, src, n)`, `sbufWriteLarge(b, src, n)` | `n` writable resident bytes and a readable, nonoverlapping source | Neither changes; overwrites at the current front |
| `sbufWriteZeros(b, n)` | `n` writable resident bytes | Neither changes; fills bytes with zero |
| `sbufWriteBuf(to, from, n)` | Distinct ordinary buffers, enough source payload and destination writable capacity | Neither buffer's cursor or length changes |
| Integer reads/writes | Enough resident bytes; aligned variants also require actual cursor alignment | Neither changes; values use native byte order |

The raw read/write helpers do not check these bounds. The destination-capacity
assertion in `sbufWriteBuf()` is not source validation or a Release runtime check.
Validate external lengths before access. Generic pointer access does not make a
splice body resident; only an exposed real prefix can be accessed that way.

Unaligned integer helpers remove the alignment requirement, not the byte-order
requirement. Encode network fields explicitly or use `htons()`/`ntohs()` and the
appropriate unaligned helper. Consecutive writes without cursor movement overwrite
the same front bytes. For ordinary tail growth, use the [append helpers](#appending-ordinary-payloads).

```c
// Independent operations, each after establishing its bounds:
sbufWriteUnAlignedUI16(b, htons(port)); // network-order field at the front
uint16_t wire_port;
sbufReadUnAlignedUI16(b, &wire_port);   // reads without consuming
uint16_t port_value = ntohs(wire_port);
sbufShiftRight(b, sizeof(wire_port));   // explicitly consume that resident field
```

Writing into spare ordinary storage does not make it payload: publish the
successfully initialized length with `sbufSetLength()`. Conversely,
`sbufSetLength()` initializes no bytes. Use the reserve/produce/commit example
below for producers that can fail or return short results.

`sbufReduceLength()` changes only length; it does not consume front bytes or
perform pipe I/O. Splice body accounting uses `sbufSpliceConsumeBody()` after
successful pipe I/O so logical capacity is reduced together with length.

`sbufSlice(source, bytes)` consumes leading ordinary bytes into a new ordinary
buffer with the source's full original aligned left padding. The caller owns
both the result and the remaining source, including when the source becomes empty.

### Appending Ordinary Payloads

The append helpers combine tailroom validation, destination calculation, and
length update without allocating or replacing storage:

```c
uint8_t *sbufAppendSpaceInPlace(sbuf_t *buf, size_t bytes);
uint8_t *sbufTryAppendSpaceInPlace(sbuf_t *buf, size_t bytes);
void sbufAppendBytesInPlace(sbuf_t *restrict buf,
                            const void *restrict source, size_t bytes);
bool sbufTryAppendBytesInPlace(sbuf_t *restrict buf,
                              const void *restrict source, size_t bytes);
```

Every form requires a non-null, exclusively mutable ordinary buffer with valid
geometry, including for zero bytes. Splice input and corrupt geometry are
programmer errors; `Try` does not turn them into ordinary refusal. Non-`Try`
forms require sufficient tailroom and assert it in Debug. The checked forms
validate tailroom in every build and refuse before any write or mutation. Room
is checked before adding to length or forming the requested end pointer, so an
oversized request cannot wrap into apparent success.

All four preserve the allocation address, cursor, capacity, current and initial
headroom, previous payload, and flags, including checksum intent. They perform
no allocation, recentering, compaction, callbacks, pipe I/O, recycling, or ownership
transfer. Append starts have no extra alignment guarantee.

`Space` returns the old payload end and immediately extends length by `bytes`.
The exposed bytes remain uninitialized. Use it only for a guaranteed complete,
synchronous fill before any inspection, queue publication, callback, or ownership
handoff. For example, encoding a `uint32_t value` after establishing room for a
four-byte footer:

```c
assert(sbufGetTailroom(buf) >= 4);
uint8_t *footer = sbufAppendSpaceInPlace(buf, 4);
footer[0] = (uint8_t) (value >> 24);
footer[1] = (uint8_t) (value >> 16);
footer[2] = (uint8_t) (value >> 8);
footer[3] = (uint8_t) value;
// The complete appended region is now initialized and may be observed.
```

A zero-byte space append changes nothing and returns the current tail, which
may be a valid one-past pointer; do not dereference it. The checked form returns
`NULL` only for insufficient tailroom. Positive results must be fully initialized;
obtaining space alone does not certify readable payload. Returned pointers are
borrowed and must be discarded before replacement, recycling, destruction, or
ownership transfer.

`Bytes` validates room, copies exactly `bytes` with `memoryCopy`, then extends
length. A positive copy requires a non-null readable source range that does not
alias the destination allocation; self-appending is outside the contract. A
zero-byte copy succeeds, accepts a null source, and skips the copy primitive.
The source stays unchanged and caller-owned; its flags are not copied. Use the
checked copy when tailroom shortage is an expected outcome:

```c
if (sbufTryAppendBytesInPlace(buf, encoded, encoded_length))
{
    // The copied bytes are initialized and included in buf's length.
}
else
{
    // Insufficient tailroom: buf's fields and storage are unchanged.
    // Choose the caller's existing growth, queueing, or refusal path.
}
```

Keep short or failing producers on a reserve/produce/commit sequence. Native
receives, TLS/BIO reservations, compression, and deferred I/O must publish only
actual successful output; they cannot use space append to precommit a maximum.
`sbufReserveSpace()` takes the required **total payload capacity from the cursor**,
not an increment or spare-tail count. Establish representable geometry, retain
its returned buffer, and reacquire pointers after growth. For an already validated
positive receive request within the OS interface's limit:

```c
const size_t old_length = sbufGetLength(buf);
size_t allocation_capacity;
if ((uint64_t) request > (uint64_t) UINT32_MAX - old_length ||
    !sbufTryComputeCapacity((uint64_t) old_length + request,
                           sbufGetInitialHeadroom(buf), &allocation_capacity))
{
    // Reject the requested geometry; buf remains owned and unchanged.
}
else
{
    buf = sbufReserveSpace(buf, old_length + request);
    uint8_t *tail = sbufGetMutablePtr(buf) + old_length; // reacquire after growth
    ssize_t produced = recv(fd, tail, request, 0);
    if (produced > 0)
    {
        sbufSetLength(buf, old_length + (size_t) produced);
    }
    // Zero is EOF; negative is an error. Handle either with length unchanged.
    // buf remains owned here, including when the allocation was replaced.
}
```

Neither append family implicitly grows storage. A `Try` prefix describes a
helper's refusal behavior, not a universal allocation guarantee:
`bufferpoolTryGetBestFit()` and `sbufTryEnsureOrdinary()` can allocate after
accepting geometry. Actual heap allocation failure remains fatal.

### Operation Contracts

The table separates expected refusal from programmer preconditions, storage
replacement, and ownership. Valid representation and locally checkable
preconditions use Debug assertions; they are not extra runtime failure modes.

| Operation | Expected refusal | Allocation or replacement | Length and ownership effect |
| --- | --- | --- | --- |
| `sbufRead`, `sbufWrite`, `sbufWriteBuf` | Caller establishes readable/writable ranges | Neither | Copies at the front; no cursor/length change or ownership transfer |
| `sbufAppendSpaceInPlace` | None when tailroom precondition holds | Neither | Extends length; caller immediately initializes; ownership retained |
| `sbufTryAppendSpaceInPlace` | `NULL` for insufficient tailroom | Neither | Same on success; fields and storage unchanged on refusal |
| `sbufAppendBytesInPlace` | None when tailroom precondition holds | Neither | Copies, then extends length; source and destination remain owned |
| `sbufTryAppendBytesInPlace` | `false` for insufficient tailroom | Neither | Same on success; fields and storage unchanged on refusal |
| `sbufGetResidentView` | None for a valid buffer | Neither | Observes resident bytes; borrowed lifetime |
| `sbufShiftLeft` | Caller establishes headroom | Neither | Extends front; caller immediately initializes exposed bytes |
| `sbufShiftRight` | Caller establishes enough resident front bytes | Neither | Consumes front bytes; allocation remains owned |
| `sbufReduceLength` | Caller establishes enough payload; splice body needs its dedicated helper | Neither | Removes logical tail bytes without moving the cursor; ownership retained |
| `sbufMoveTo` | Distinct ordinary buffers, enough source bytes and destination tailroom | Neither | Consumes source front and appends to destination; both allocations remain owned, even if source becomes empty |
| `sbufSlice` | Ordinary source with enough bytes; representable output geometry | Allocates a new result | Consumes source front; caller owns both source and result |
| `sbufDuplicate`, `sbufDuplicateByPool` | Ordinary source and representable copy geometry | Allocates or checks out a destination | Source unchanged; caller owns the independent copy |
| `sbufDuplicateTo` | `false` if destination cannot represent the complete copy | Neither | Destination changes only on success; source retained |
| `sbufReserveSpace` | Representable geometry is a caller obligation | May replace and free old buffer | Existing payload and length preserved; only returned buffer remains owned |
| `sbufConcat` | Caller supplies distinct ordinary inputs and bounded total geometry | May replace destination | Appends source; source retained |
| `sbufAppendMerge` | Valid distinct ordinary inputs and geometry required | May replace first input | Consumes both inputs; only returned buffer remains owned |

`sbufConcatNoCheck()` retains its ordinary, distinct-buffer, sufficient-tailroom
preconditions and copies through `sbufAppendBytesInPlace()` without growth.
`sbufConcat()` keeps explicit growth and its `memoryCopyLarge` policy. Neither
operation transfers the source's checksum intent. Always execute mutating helpers
outside `assert()` so Release builds perform the operation.

### Choosing the Right Buffer Quantity

Use the quantity that matches the decision being made. All sizes below are bytes;
entry counts and kernel-resource limits are separate dimensions.

| Quantity | Ordinary buffer | Splice buffer | Use |
| --- | --- | --- | --- |
| Logical length: `sbufGetLength()` | Active payload | Real prefix plus private-pipe body | Protocol length and logical-byte accounting |
| Resident length: `sbufGetResidentPrefixLength()` | Complete active payload | Real prefix only; may be zero with a nonempty body | Bound inspection through the borrowed view |
| Current headroom: `sbufGetHeadroom()` | Space before the cursor | Remaining real prepend storage before the prefix | Check actual prepend room, separately from the node's allowance |
| Tailroom: `sbufGetTailroom()` | Spare storage after payload | Not supported | Check in-place ordinary append room |
| Total capacity: `sbufGetTotalCapacity()` | Storage including headroom, excluding header/allocator overhead | Logical geometry; not a resident bound | Geometry calculations within the representation contract |
| Allocation charge: `sbufGetAllocationCharge()` | Header + storage capacity + alignment overhead | Header + original headroom + fixed control storage + alignment overhead | Account for the sbuf's own userspace allocation |
| Queue charge: `sbufGetQueueCharge()` | Header + capacity + alignment overhead | Same formula using logical capacity | Canonical queue-budget policy; not physical pipe memory |
| Kernel pipe capacity | Not applicable | Capacity of the private pipe, independent of bytes currently stored | Splice inventory/resource limits |

An ordinary one-byte payload can retain a whole large pool allocation. A splice
buffer can have positive logical length and zero resident length. Neither queue
charge nor allocation charge measures total process RSS. See [retained
accounting](#payload-length-versus-retained-allocation-charge) and the
[splice inventory contract](./reference/splice-buffers.mdx#splice-payloads-ksbufflagsplice)
for the respective limits.

### Packet checksum repair requests

`kSbufFlagRecalculateChecksum` uses the existing `sbuf_t.flags` storage without
changing the 32-byte header. `sbufSetRecalculateChecksum(buf, requested)` changes
only this bit; `sbufGetRecalculateChecksum(buf)` reads it. Requesting repair
requires an ordinary resident buffer and asserts against a splice wrapper.

True means this packet has an outstanding request for the existing checksum
repair operation. False means no repair requested; it does not certify checksum
validity. Deliberately invalid checksums remain possible. The bit is independent
of TUN-private checksum assurance, hardware offload and GSO metadata.

Fresh allocations, reset and ordinary pool reuse clear the request. Whole-payload
`sbufDuplicateTo()`, `sbufDuplicate()` and `sbufDuplicateByPool()` copy it exactly,
including clearing a previously marked destination when the source is unmarked.
A failed duplicate leaves destination bytes, geometry and flags unchanged.
Each clone owns its own request; consuming one does not change another.
`sbufReserveSpace()` preserves the request across replacement or no growth; use
only its returned pointer after it may replace the allocation.

Byte-copy helpers, including `sbufWriteBuf()` and the append-byte helpers, do not
transfer intent. All in-place append helpers preserve the destination flags. New
partial moves, slices and range extractions start unmarked and do not consume the source's
request. Concatenation preserves the destination bit through growth without ORing
source bits. Cursor/length changes preserve the bit mechanically; mutable access
and byte writers do not infer checksum consequences. Packet-aware callers must
complete repair before losing a packet boundary, or explicitly assign intent to
complete constructed packets. Segmentation, fragmentation and synthetic output
choose intent for each result according to their checksum generation semantics.
Splice wrappers stay unmarked; materialization never creates packet intent.

Forwarding transfers bytes and intent together. After forwarding or recycling,
the sender must not inspect or change either. A successful complete repair clears
the bit; an incremental correction covering only a transform's own edit preserves
an earlier request. A terminal consumer may take it before repair because refusal
discards the packet. A transform that declines and forwards unchanged preserves
both bytes and request. See [packet boundaries in Part 4](./part4-packet-tunnels.mdx#packet-checksum-repair-boundaries).

## The Padding Contract: `required_padding_left`

A tunnel may only rely on left padding it **advertised** through its instance's
`node->required_padding_left`. The `node.c` declaration supplies the default:

```c
.required_padding_left = kMyProtocolHeaderSize,
```

A constructor with mode-dependent framing resolves that instance's value before
`tunnelchainInsertAt()` accumulates chain padding. Never defer this choice to
`onPrepare` or borrow another node's reservation.

Keep three quantities separate:

1. **Initial reservation.** Chain insertion sums every node's
   `required_padding_left`; finalization passes that sum to
   `globalstateUpdateAllocationPadding()`. Worker pools round it to 32 bytes and
   retain the maximum required by the chains finalized into those pools. A fresh
   runtime buffer can therefore have more headroom than this chain alone needs.
2. **Current headroom.** Each prepend subtracts from it; resident front consumption
   adds to it. Read `sbufGetHeadroom(buf)` at the point of use. Remaining space is
   not a sum based only on which nodes are nearer the producing adapter.
3. **This node's allowance.** `required_padding_left` declares what this node may
   spend. Alignment slack, another chain's larger reservation, or previously
   consumed bytes do not increase that advertised allowance.

For example, three nodes advertising 8, 16 and 32 bytes require 56 bytes, rounded
to at least 64 at allocation. Starting from 64, after the first node prepends 8,
the second sees 56 bytes of current headroom but may spend only its advertised
16. Its prepend leaves 40 for subsequent work. An additional chain can raise the
initial reservation without changing any of these nodes' allowances.

This is why a framing tunnel that "works on my machine" can corrupt memory once a
user puts a different node in front of it. Advertise what you prepend.

Rules:

- Use `sbufShiftLeft()` only when `sbufGetHeadroom()` is at least the header
  size you need.
- Keep every prepend within this tunnel's advertised `required_padding_left`.
- If you must prepend more than your budget, either raise
  `required_padding_left` to match, or build a fresh buffer (see below) instead of
  shifting.

## Buffer Pools

Generic object-pool item sizes and their getter/constructor arguments use
`size_t`, including the mutex-protected wrapper. Item size remains bounded by
`UINT32_MAX`; constructors reject larger requests before allocating metadata or
installing master callbacks. Cache widths and counts retain their bounded
`uint32_t` representation. This is separate from buffer-tier sizes and the
16-bit headroom reservation.

For ordinary runtime buffers, do not `malloc`. Use the worker-local buffer pool so
allocations are recycled and correctly padded. The pool is reachable from any
line:

```c
buffer_pool_t *pool = lineGetBufferPool(line);     // this line's worker pool

sbuf_t *big   = bufferpoolGetLargeBuffer(pool);    // ordinary read/working buffer
sbuf_t *medium = bufferpoolGetMediumBuffer(pool); // 32 KiB in S1/S2, 64 KiB in higher profiles
sbuf_t *small = bufferpoolGetSmallBuffer(pool);    // small working buffer
sbuf_t *splice_buf = bufferpoolGetSpliceBuffer(pool); // leased private pipe, or NULL when exhausted

// ... use the buffer ...

bufferpoolReuseBuffer(pool, buf);                  // return it to the pool
lineReuseBuffer(line, buf);                        // convenience: pool of line's worker
```

Pools are **per worker**. A line belongs to exactly one worker (`lineGetWID`), so
always use that line's pool — never a different worker's. Buffers from a pool
already carry the chain's reserved left padding, so a pooled buffer is the correct
place to build a payload you intend to prepend onto.

Pool metadata and ordinary buffer allocation follow the
[fatal heap-allocation policy](./part5-tunnel-anatomy.mdx#heap-allocation-failure).
`bufferpoolCreate()` remains nullable for invalid construction inputs or
unrepresentable geometry. Bounded splice-inventory exhaustion is separate from heap
exhaustion and keeps its documented ordinary-buffer fallback.

Each buffer pool has large, medium and small ordinary caches backed by three
shared ordinary masters. `bufferpoolCreate()` takes those masters in that order,
then the ordinary cache width, large/medium/small payload capacities, the splice
payload limit and the waiting-budget basis. The latter two values must be in
`[1, INT_MAX]` and stay fixed after construction. Device pools inherit the sizes
and limits from their worker pool. Splice caches use the shared bounded inventory
without a separate wrapper master or a constructor argument for one.

Device backends use `devicePoolCreate()` with an explicit, exclusively accessible
worker pool and a backend-specific minimum small tier. Construction preserves
zero initial padding; `devicePoolUpdatePadding()` copies all four finalized
padding values during BringUp, before publishing I/O producers. Neither helper
obtains a worker pool from thread-local identity. Private TUN reader pools use the packet
MTU as their minimum; Linux worker readers use their owner worker pools and a
shared fragment table with detached allocations. Darwin receives its family
prefix into separate storage.
The worker GSO output allowance and its exact-sized fallback remain a separate
calculation.

Worker and device pools select ordinary cache width with
`PROPER_BUFFER_POOL_WIDTH()`. Ordinary masters use twice that width as their
constructor argument. Splice caches have a fixed eight-entry limit; their global
master is sized for the maximum permitted inventory; the configured profile and
detected RAM ceiling affect its global budget, not local cache width.

The master's mutex transfers ownership and visibility of cached item slots.
Its atomic `len` uses relaxed loads/stores: reads outside the mutex are advisory
empty/full probes, and slot access always holds the mutex. `checked_out` has a
different role: terminal returns can finish outside that mutex, so their release
decrements pair with acquire reads before teardown frees pool-family resources.
Observing zero does not close checkout admission; the owner must prevent new
checkouts and satisfy the existing lifecycle requirements before destruction.

Master constructors double their argument, giving
these actual entry capacities:

| Profile | Ordinary local width | Each ordinary master |
| --- | --- | --- |
| S1 / `minimal` | 1 | 4 |
| S2 | 4 | 16 |
| M1 / `client` | 8 | 32 |
| M2 / `client-larger` | 32 | 128 |
| L1 | 64 | 256 |
| L2 / `server` | 128 | 512 |

Ordinary local pointer arrays hold twice their selected width. Recycling shrinks
an ordinary tier once its cached count exceeds `floor(4 * width / 3)`, transferring
up to one width of entries to its master; a full ordinary master destroys overflow.
These are idle cache bounds, not limits on active allocations.

Payload capacities, excluding reserved left padding, are:

| Tier | Capacity | Use |
| --- | --- | --- |
| Small | 4 KiB | Small ordinary payloads and control messages |
| Medium | 32 KiB in S1/S2; 64 KiB in M1/M2/L1/L2 | Framing, retained queues including paused Mux children, and best-fit UDP reads |
| Large | 64 KiB in S1/S2; 128 KiB in M1/M2/L1/L2 | Ordinary event-loop read buffers and larger working payloads |
| Splice storage | 32 bytes of control storage | Explicit splice wrappers; logical body size is independent of allocation size |
| Splice payload limit | 1 MiB in every profile | Socket read limit and required new-pipe capacity |

S1 and S2 share buffer sizes but retain different profile-based local and master
cache capacities; S1 caches fewer allocations. Higher profiles retain 64 KiB
medium and 128 KiB large buffers. Their independent splice target remains 1 MiB.
NIO ordinary TCP reads use the large tier directly. Linux NIO UDP reads select an
ordinary tier through best-fit allocation when a positive size hint is available.
Medium buffers also serve nodes and retained queues. Mux selects the smallest
fitting ordinary tier; a full 1 MiB frame requires dedicated ordinary storage in
every profile. The wire payload maximum remains 1 MiB.

`bufferpoolGetBestFit()` selects the smallest ordinary tier that satisfies both
payload and padding requirements, comparing actual sizes across small, medium,
and large. If no tier fits, it creates a dedicated padded buffer that is destroyed
on return. `bufferpoolTryGetBestFit()` accepts a 64-bit computed length and returns
`NULL` for unrepresentable geometry before using the same allocation path. Neither
helper shrinks an existing buffer. Splice allocation stays explicit.

A successful best-fit allocation already satisfies the requested payload capacity
and left padding; callers need no undersized-success recovery branch. Use
`bufferpoolGetBestFit()` when caller-established bounds guarantee representable
geometry, including padding and alignment; otherwise preserve
`bufferpoolTryGetBestFit()`'s geometry refusal. These guarantees describe the
returned buffer at allocation time. Incoming or subsequently shifted buffers
still need the applicable capacity and prepend checks.

`sbufCreateWithPadding()` makes a separate ordinary `sbuf_t` and follows the same
fatal heap-allocation policy as pool refill. Validate computed geometry with
`sbufTryComputeCapacity()` before creating storage when an unrepresentable request
must be refused locally. Destroy this direct buffer with
`sbufDestroy()` after its last user has stopped.

The 128 KiB tier is not a maximum payload or total-memory limit. Smaller pooled
allocations do not cap process memory, kernel pipe memory, frame sizes, or
dedicated ordinary allocations. Frequent large materializations can incur
allocation/free work; these sizes make no throughput guarantee.

Materialization callers must request the complete logical payload plus required
headroom, including real prefixes, residual padding and any destination bytes
already present. Low-level conversion helpers do not grow caller storage. For
example, 600 KiB requires dedicated ordinary storage with a 128 KiB large tier;
a pipe with 1 MiB capacity holding only 20 KiB needs storage for its logical bytes,
not its kernel capacity. Dedicated buffers above all tiers are destroyed on
recycling, while consumed splice wrappers return to their separate splice cache.

Each tier refills at most four buffers at a time, further bounded by half the
local cache capacity and its available slots. Pools whose previous refill batch
was smaller than four retain that smaller batch. Cache capacities and shrink
thresholds are independent of this refill limit.

Fresh `sbuf_t` allocations with more than 2 KiB of physical buffer storage,
including reserved left padding and alignment rounding but excluding the header,
are prefaulted in `shiftbuffer.c`. Release builds write volatile zero bytes at
4096-byte strides and at the final byte, covering trailing unaligned pages.
Debug builds retain their existing full-storage diagnostic fill, which already
touches every page. The supported minimum page size is assumed to be 4096 bytes;
no OS page-size query is performed.

This applies to newly allocated pool buffers, dedicated buffers and replacement
allocations during growth. Pool checkout and recycling do not repeat the writes.
Splice wrappers use only their physical padding and control-storage size, never
their logical pipe payload size. Length, padding and ownership rules are unchanged;
callers must still initialize payload bytes before use. Prefaulting pays possible
first-write page faults during allocation, may populate unused capacity, and does
not pin memory or guarantee a throughput improvement.

`bufferpoolGetSpliceBufferStorageSize()` and `bufferpoolGetSpliceBufferPadding()` expose
the splice geometry. `bufferpoolUpdateAllocationPaddings()` accepts separate
large, medium, small, and splice padding arguments. Global chain-padding updates cover
all four tiers, and device pools inherit each tier's padding value from their
worker pool. Finalize padding before creating the splice inventory or populating
local caches; splice padding cannot change after inventory initialization.

The existing `lineGetBufferPool()`, `getWorkerBufferPool()`, and
`getCurrentWorkerBufferPool()` accessors expose every tier through the same pool, including
`bufferpoolGetMediumBuffer()` and `bufferpoolGetSpliceBuffer()`. `lineReuseBuffer()` and `reuseBuffer()` use the same
recycling path as `bufferpoolReuseBuffer()`, subject to their existing worker
ownership requirements. Ordinary recycling clears flags and length. Splice
recycling preserves its representation/ownership flags and pipe, clears payload,
and restores `capacity = initial_headroom + SPLICE_BUFFER_STORAGE_SIZE` and
`data = head + initial_headroom`. Discard the pipe body before resetting these
fields; resetting geometry does not drain the pipe.

`bufferpoolGetSpliceBuffer(pool)` returns a complete buffer from the local cache,
shared master or bounded lazy growth. A refusal returns `NULL` with `ENOBUFS`; unsupported
builds use `ENOSYS`. Handle this before accessing the buffer, normally by choosing
ordinary storage. Bypass uses the same bounded global inventory without local caching.
Only checkout/refill may grow the inventory; returning a healthy buffer never
creates, resizes or closes its pipe.

If you need a buffer bigger than the current one for an append, use
`sbufReserveSpace()` (it reallocates and copies only when necessary) rather than
hand-rolling growth.

`sbufCreateSplice(pad_left)` directly allocates an empty buffer with exactly
32 bytes of payload capacity, plus left padding rounded up to a 32-byte
boundary. Its payload capacity stays at 32 bytes regardless of the CPU cache
line size. The buffer starts with zero length and only `kSbufFlagSplice` set;
`sbufDestroy()` physically frees this unmanaged allocation. Inventory entries
are acquired through the pool APIs and preserve their flags while cached.

### Ordinary TCP and UDP receive sizing

NIO ordinary TCP reads take the pool's large buffer directly and call `recv()`
with its full writable payload capacity, without first querying `FIONREAD`.
This also applies to an ordinary receive after a failed pipe allocation or a
splice attempt that makes no progress. A receive may return fewer bytes than
the capacity; remaining stream bytes stay queued for later reads. Its actual
return value determines the published length, and zero confirms TCP EOF.
Buffer capacity does not define TCP application message boundaries.

On Linux, UDP uses `FIONREAD` as an allocation hint for the full size of the next
datagram, not the sum of queued packets. `bufferpoolGetBestFit()` requests that
complete size. It can select a larger tier or dedicated storage if the datagram
exceeds a custom pool's large tier. Each receive still delivers one datagram.
The socket has one serialized reader between the query and receive.

UDP best-fit reads request at least the large tier's reserved left padding, so
a smaller tier with insufficient padding is ineligible. A failed or zero size
query falls back to a large-buffer receive. Zero never skips the receive: it
may represent an empty UDP datagram or transient readiness. The actual receive
result determines the published length, and Linux UDP truncation detection
still drops incomplete datagrams.

TunDevice uses its separate raw-IP/GSO reader and buffer sizing. Other NIO socket
types and non-Linux/IOCP receive paths retain their own allocation policy.

### Sizing Destination Buffers for Untrusted or Variable Payloads

When sizing a destination buffer from an untrusted or variable payload length:

- Use `bufferpoolGetBestFit()` (or another checked growth operation) rather than
  assuming a fixed buffer tier fits the input. Supply the left padding required
  by the onward buffer contract as well as the payload capacity: when no
  pool tier fits, best-fit creates a dedicated buffer with exactly the requested
  padding. Request zero only for a locally consumed buffer or a proven
  zero-padding destination.
- Compare the requested length with actual writable capacity
  (`sbufGetWritableCapacity()`) in ordinary Release control flow before any
  assert-only length mutator (such as `sbufSetLength()`) or write.
- Publish actual produced length only after a partial or failing producer has
  successfully written or validated that many bytes. Space append and prepend
  may privately extend length for a guaranteed complete synchronous fill, but no
  inspection, queue publication, callback, or ownership handoff may observe the
  region before it is fully initialized.

`sbufEnsureHeadroom(pool, buf, need)` consumes an exclusively owned buffer
and returns the sole owned result. Sufficient headroom returns the original
unchanged; otherwise replacement preserves the complete logical payload and
reserves at least `max(need, large_pool_padding)`. Ordinary input remains ordinary.
Splice input attempts a sufficiently padded splice destination, with ordinary
fallback on checkout or transfer refusal, including partial transfer progress.
It promises byte preservation, not a particular resident/pipe split or copying
arbitrary metadata flags. The caller supplies representable replacement geometry
and the owner-worker pool; there are no callbacks. Node padding declarations and
actual prepend bounds remain the caller's obligations. Trojan UDP checks its
actual header length before requesting maximum-header replacement padding;
VLESS UDP requests its fixed two-byte prefix.

## Buffer Ownership

Buffer helpers returning the sole owned replacement are marked `WW_MUST_USE`,
including `sbufReserveSpace()`, `sbufEnsureOrdinary()`,
`sbufTryEnsureOrdinary()`, `sbufEnsureHeadroom()`, `sbufConcat()`,
`sbufAppendMerge()`, `sbufMoveRangeTo()` and splice frame movement. Consume their
returned result according to each ownership contract; the previous allocation
may have been freed or recycled. Checked conversion still leaves the source
owned by the caller on refusal. Cursor shifts do not replace storage, so their
returned pointers remain optional.

Buffer lifetime bugs are as common as line lifetime bugs. The rules:

- **A callback takes ownership of the buffer you pass it.** After
  `tunnelNextUpStreamPayload(t, line, buf)` (or the downstream form), `buf` is no
  longer yours. Do not read it, reuse it, or free it.
- **If you keep a buffer, you own it.** You are responsible for eventually
  recycling it with `bufferpoolReuseBuffer` / `lineReuseBuffer`, or handing it to
  a callback.
- **On an error path that still owns a buffer**, return it to the pool (or the
  line) before you close. Do not leak it, and do not touch it after the line dies.
- **If a re-entrant callback killed the line** (a `false` from
  `lineCallWithRef()` / `lineCallWithRefWithBuf()`), only recycle buffers you still hold; do not touch the dead
  line's state to do it.

ContextQueue owns enqueued contexts until pop or destruction. `contextqueuePop()`
returns `NULL` when empty; otherwise ownership transfers to the caller.
`contextqueuePush()` terminates on deque insertion failure.

After transferring or recycling a context's payload, `contextDropPayload()`
clears its payload pointer in every build configuration. It does not free the
buffer. `contextReusePayload()` and `bufferStreamPushContextPayload()` perform
this bookkeeping so later context destruction cannot recycle the payload again.

### Payload length versus retained allocation charge

`sbufGetLength()` measures buffer contents. That is the correct unit for ordinary
queue byte counts, protocol thresholds, FIFO delivery statistics, and
backpressure decisions, and `buffer_queue_t.total_len` intentionally keeps those
logical payload semantics.

Do not treat that content length as a memory charge when a security or resource
limit specifically promises to bound allocations retained by a live queue. An
empty or one-byte `sbuf_t` can still retain its full capacity, left padding,
header, and allocator alignment overhead. Memory-sensitive code that needs such
a hard bound must keep a separate storage/resource charge. Mux's child, parent,
detached and outgoing queues use their
[queue-capacity policy](./reference/protocol-buffers.mdx#queue-capacity-budgets); it deliberately
does not bound physical kernel resources. It must not replace logical length in
BufferQueue or in the incoming-child FlowResume threshold.

Use `bufferqueueGetCharge()` for an individual BufferQueue instead of maintaining
a duplicate counter beside it. A whole-queue ownership transfer carries the budget binding and both cached
totals; initialize the relinquished source as empty and unbound. Reserved pop
keeps continued active retention charged. TCP adapters share one budget between
the queue and active WIO reservation, retaining original capacity charge until
completion or terminal callback detachment. Partial writes release logical bytes.
Mux's children, parser and detached associations retain their existing policies.

`sbufGetAllocationCharge(const sbuf_t *buf)` is the canonical O(1) charge for an
allocated buffer's own userspace storage. For ordinary buffers it returns
`sizeof(sbuf_t) + sbufGetTotalCapacity(buf) + kSbufAllocationAlignment`; capacity
already includes left padding. For splice wrappers it returns the header plus
original left padding, `SPLICE_BUFFER_STORAGE_SIZE`, and alignment overhead.
Splice capacity and length are logical, so they cannot measure wrapper storage.
The helper works before pipe initialization, makes no allocation or syscall, and
reads no payload bytes. Cursor movement, consumption, and prepending leave the
charge unchanged unless storage is replaced. It excludes kernel pipe memory,
allocator bookkeeping beyond explicit
alignment overhead, and pool/queue storage. The separate queue-charge helpers use sbuf capacity for both representations. This does not change `sbufGetAllocationCharge()` or
BufferQueue's logical-byte accounting.

`bufferpoolQueryBestFit()` predicts ordinary storage without allocating, consuming
a cache entry, or making a reservation. It shares tier selection with
`bufferpoolGetBestFit()` and reports aligned payload capacity, left padding,
allocation charge, and whether a configured pool tier fits. Unrepresentable
geometry returns false without changing the output. Predictions remain valid
while pool geometry is unchanged. Mux uses this query for ordinary compaction
and batch fallback reservations; compaction still requires a smaller pooled tier.

Device receive dispatch has separate allocation, batch and offload allowances;
see [Device receive dispatch storage](./reference/device-buffer-storage.mdx#device-receive-dispatch-storage)
when changing reader admission or packet handoff.

### Buffers transferred to scheduled line tasks

Calling `lineScheduleTaskWithBuf()` or
`lineScheduleDelayedTaskWithBuf()` transfers the buffer on **every** result,
including synchronous `RejectedSettled`. The caller must never recycle, destroy,
or inspect it after the call. If the task executes, the task callback receives
ownership. Otherwise the scheduler settles the buffer after optional
cancellation notification: it returns the buffer to the line's pool only while
cleanup runs in that owner event-worker context, including owner-bound teardown,
and destroys it on a foreign or unbound cleanup thread.

The cancellation callback does not receive or own the buffer. It runs before
internal buffer release, while the scheduler's physical line reference remains
held, and must not attempt to infer buffer lifetime from the cancellation
reason. A null cancellation callback suppresses only notification; line death,
submission refusal, quiescence, and teardown still release the buffer exactly
once. This makes memory safety independent of task progress.

In debug builds, `BUFFER_WONT_BE_REUSED(x)` swaps a buffer for a fresh duplicate
and destroys the original, so any stale pointer to the old buffer is caught
quickly. If you see it in reference tunnels, it marks "this buffer must not be
touched again after this point."

## Prepending a Header: `sbufShiftLeft`

The initial headroom reservation lets a tunnel prepend a protocol header
**without reallocating or memmoving** the payload. You move the cursor left and
write into the exposed space. Given an encoded `wire_header` of `header_len`
bytes:

```c
// Reserve room and move the cursor back by header_len bytes.
assert(sbufGetHeadroom(buf) >= header_len);
uint8_t *header = sbufShiftLeft(buf, header_len); // data -= header_len; len += header_len

// Now write the header at the new front.
sbufByteCopy(header, wire_header, header_len);
```

The returned pointer replaces a subsequent `sbufGetMutablePtr(buf)` when the
caller needs the new front. Byte copying requires no aligned cursor; aligned
integer writers still require the alignment described above. Fill the entire
exposed header synchronously before any observer or ownership handoff; length has
already been extended during this private initialization interval.

`sbufShiftLeft` asserts that enough current headroom exists:

```c
static inline uint8_t *sbufShiftLeft(sbuf_t *const b, const size_t bytes)
{
    assert(sbufGetHeadroom(b) >= bytes);
    b->data -= bytes;
    b->len += bytes;
    return b->data;
}
```

If the assertion fires, actual headroom is insufficient. Check both the incoming
buffer's onward-padding contract and this node's advertised allowance; exceeding
the allowance can also be wrong when extra physical headroom hides the mistake.

## A Complete Prepend Example

This encoding helper adds a two-byte big-endian length for a protocol whose frames
contain 1 through 65,535 body bytes. Its node advertises
`.required_padding_left = 2` in `node.c`. The caller exclusively owns a valid
ordinary buffer or splice wrapper with at least two bytes of current headroom.
The body remains opaque, so a splice body need not be materialized.

```c
static bool prependLength16(sbuf_t *buf)
{
    const size_t payload_len = sbufGetLength(buf);
    if (payload_len == 0 || payload_len > UINT16_MAX)
    {
        return false; // No mutation or ownership transfer.
    }

    assert(sbufGetHeadroom(buf) >= 2);
    uint8_t *header = sbufShiftLeft(buf, 2);
    header[0] = (uint8_t) (payload_len >> 8);
    header[1] = (uint8_t) payload_len;
    return true;
}
```

A three-byte body receives `00 03`; 65,535 bytes receives `ff ff`. A 65,536-byte
body is refused before any narrowing or mutation. Bytewise encoding works at an
unaligned cursor and is independent of host byte order. The full exposed prefix
is initialized synchronously before it can be observed.

The caller still owns `buf` on both results. On false it applies its protocol's
refusal policy and releases the buffer if discarding it; splitting a datagram is
not an equivalent recovery. On true it can transfer the buffer with
`tunnelNextUpStreamPayload(t, l, buf)` and return immediately. If it continues
working after forwarding, it must protect and recheck the line as described in
[Part 2](./part2-lines-and-callbacks.mdx#protecting-a-line-across-re-entrant-callbacks).
Never place the call to this mutating helper inside `assert()`.

## Choosing a Container or Reader

Choose by representation, retained boundaries and parsing obligation. These
helpers do not choose the node's protocol limits or callback direction.

| Need | Helper and canonical contract | Representation and ownership |
| --- | --- | --- |
| Retain separate buffers in FIFO order | [BufferQueue](./reference/buffer-containers.mdx#bufferqueue-splice-ownership) | Ordinary or splice; successful push transfers ownership, failed try-push retains it; pop transfers it back |
| Inspect/search a byte stream across storage entries | [BufferStream](./reference/buffer-containers.mdx#bufferstream-representation-inspection-and-extraction-contracts) | Ordinary only; push owns input and may coalesce; storage boundaries are not records |
| Gather variable protocol metadata before extracting a body | [Staged buffer reader](./reference/buffer-containers.mdx#staged-buffer-reader) | Ordinary or splice; successful try-push owns input, refusal retains caller ownership |
| Control fixed-header extraction and custom pressure policy directly | [Splice stream](./reference/buffer-containers.mdx#fixed-header-splice-stream) | Ordinary or splice; caller coordinates draining and admission |
| Serialize fixed-header frames or incremental bodies, including nested input | [Frame reader](./reference/buffer-containers.mdx#fixed-header-frame-reader) | Ordinary or splice; admission owns input on every result |
| Share byte/queue-charge limits across queues and active work | [Buffer budget and reservations](./reference/buffer-containers.mdx#bufferqueue-splice-ownership) | Owns accounting, not buffers; budget address and owner worker remain stable |

Use complete-frame extraction where one output must remain one datagram. Use
incremental-body extraction only where the protocol permits delivery before the
whole frame arrives. The source map in [Part 1](./doc1.mdx#reuse-existing-containers-and-helpers)
lists the corresponding headers.

## Decoding Across Payload Deliveries

A stream callback is not a frame boundary. For the example wire format above,
suppose `abc` and `de` arrive in three deliveries (hexadecimal bytes):

| Delivery | Reader action | Output |
| --- | --- | --- |
| `00` | Retain the first header byte; the two-byte header is incomplete | None |
| `03 61 62` | Gather `00 03`, validate length 3, retain two body bytes | None |
| `63 00 02 64 65` | Complete the first body; then parse the next complete header and body in the same drain | `abc`, then `de` |

Use `splice_frame_reader_t` to own this accumulation. Initialize it at its final
location in line state during Init, with a two-byte header, explicit finite
nested-byte and retained-charge limits, and the finalized splice-output
capability. The borrowed owner-worker pool must outlive reader destruction.

1. Pass each input to `spliceframereaderAdmit()`. It consumes the buffer on
   **every** result. `Queued` or `Empty` returns without starting another drain;
   only `Drain` starts parsing. A byte, charge or push refusal requires the node's
   close path to destroy the reader and its older input. Do not recycle or retry
   the submitted buffer.
2. During a drain, `spliceframereaderPeekHeader()` returns `NULL` until the header
   is complete. Decode its two bytes into a local value and reject zero for this
   protocol. Header pointers are borrowed until reader mutation; do not retain
   one across extraction or callbacks.
3. If `spliceframereaderBodyReady(reader, length)` is false, end this drain and
   keep the incomplete frame for the next delivery. If true,
   `spliceframereaderTakeFrame()` consumes the header and body and returns the
   sole owned body buffer with onward padding. Forwarding that buffer transfers
   its ownership again. Repeat for every complete frame already admitted.
4. Hold a line reference across delivery when continuing the loop. Check logical
   line life before accessing line state, then check
   `spliceframereaderIsAttached()` on this line-embedded reader. If the line died
   or its reader was retired, release the reference and return without accessing
   destroyed state or calling `EndDrain()`. A reader stored elsewhere needs its
   own allocation-lifetime proof.
5. On a normal stop for incomplete input, call `spliceframereaderEndDrain()` while
   the reader is live. It settles retained charge and clears the drain guard;
   false requires closure and reader destruction. Finish also destroys retained
   input. Release the temporary line reference on each path.

This sequence preserves nested-input FIFO order and needs no extra payload to
flush a complete second frame. It also works when body bytes are in a private
pipe; resident length alone cannot decide body readiness. The concrete
`tunnels/UdpOverTcpClient/downstream/payload.c` loop demonstrates this ownership
and lifetime pattern. Its protocol-specific limits remain defined by that node.

## Common Buffer Mistakes

- Prepending without advertising padding, then relying on left capacity that only
  exists in one chain layout.
- Misusing `sbufShiftLeft` when left capacity is insufficient (the assert is your
  friend in debug; release builds corrupt memory).
- Reusing or reading a buffer after passing it to a forwarding callback.
- Leaking a buffer on an error/close path.
- Using a different worker's pool than the line's own.
- Treating `sbufGetWritableCapacity` as "spare room beyond the payload" — it
  is room from the cursor, so subtract the current length first.

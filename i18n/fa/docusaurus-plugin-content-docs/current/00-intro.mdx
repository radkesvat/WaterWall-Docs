# معرفی WaterWall

WaterWall یک framework ماژولار برای ساخت تونل است. در فایل‌های config با فرمت
JSON، node‌های کوچک را به هم وصل می‌کنید تا یک chain بسازید و ترافیک شبکه را
از مسیر دلخواهتان عبور دهید.

یک chain WaterWall می‌تواند به سادگی هدایت ترافیک یک پورت TCP باشد:

```text
TcpListener -> TcpConnector
```

یا چند لایه‌ی transport، پروتکل، رمزنگاری، multiplexing و پردازش packet را
با هم ترکیب کند:

```text
TcpListener -> MuxClient -> VlessClient -> TlsClient -> TcpConnector
```

همین طراحی برای کار با packet هم کاربرد دارد؛ از جمله interface‌های TUN، مسیرهای
شبیه WireGuard، پردازش raw packet و bridge‌هایی که اتصال را به packet یا packet
را به stream تبدیل می‌کنند.

## WaterWall چگونه کار می‌کند؟

هر node وظیفه‌ی مشخصی دارد: پذیرفتن ترافیک، انتخاب مقصد، تبدیل داده یا ارسال آن
از طریق socket یا interface. برای نمونه، `TcpListener` اتصال را می‌پذیرد و
`TcpConnector` اتصال خروجی آن را باز می‌کند؛ node‌های میان این دو، قابلیت‌های
موردنیاز مسیر را اضافه می‌کنند.

در فایل JSON، با فیلدهای `next` این node‌ها را به هم متصل می‌کنید. فیلد `type`
پیاده‌سازی node را انتخاب می‌کند و `name` نامی است که node‌های دیگر برای
پیداکردن آن به کار می‌برند. `next` به این نام اشاره می‌کند، نه به نوع node.
ترافیک در جهت upstream به‌سوی `next` می‌رود و پاسخ‌ها در جهت downstream از chain
بازمی‌گردند.

هر chain پردازش درون یک instance از WaterWall را توصیف می‌کند. اتصال socket بین
دو ماشین، chain‌های جداگانه را به هم وصل می‌کند: سمت client داده را بسته‌بندی
می‌کند و سمت server با node‌های متناظر آن را باز می‌کند. node‌های پروتکل مانند
`VlessClient`، `HttpClient` و `QuicClient` برای رسیدن به server راه‌دور به یک
adapter انتقال جداگانه نیاز دارند.

می‌توانید با یک config ساده شروع کنید، از کارکرد درست آن مطمئن شوید و بعد
با اضافه‌کردن node‌ها، قابلیت‌های موردنیازتان را به آن اضافه کنید.

## خانواده‌های node‌های موجود {#available-node-families}

جدول‌های زیر node‌های عمومی را بر اساس کاربرد دسته‌بندی می‌کنند. برای دیدن
تنظیمات، حالت‌های پشتیبانی‌شده و قواعد جای‌گذاری هر node، لینک آن را باز کنید؛
فهرست الفبایی هم در [همه‌ی node‌ها](./02-noderefs/all-nodes.mdx) آمده است.
در build سفارشی می‌توان نوع‌های خاصی از node را غیرفعال کرد.

## انتخاب لایه‌های سازگار

ابتدا مشخص کنید چه ترافیکی باید حمل شود: byte stream نوع TCP، datagram‌های UDP
یا raw packet‌های IP. این‌ها رابط‌های متفاوتی هستند. یک datagram نوع UDP حاوی
داده‌ی برنامه است؛ raw packet نوع IP، header‌های IP و transport را هم دارد.
برای عبور از این مرزها از node‌های bridge استفاده کنید و پروتکل‌های پشتیبانی‌شده‌ی
هر node را بررسی کنید. برای نمونه، bridge‌های packet/stream و lwIP بالا در حال
حاضر IPv4 را پشتیبانی می‌کنند.

برای transform‌های جفت WaterWall، decoder متناظر را در سمت دیگر با ترتیب
سازگار تنظیم کنید. client‌های استاندارد proxy می‌توانند در محدوده‌ی حالت‌های
مستند هر node به یک server سازگار بیرونی هم وصل شوند. رمزنگاری، احراز هویت،
multiplexing و framing انتخاب‌های جداگانه‌اند؛ افزودن یکی، بقیه را خودکار اضافه
نمی‌کند.

[بخش ۴: انتخاب node‌ها](./01-getting-started/tutorial-part4.mdx) این انتخاب‌ها
را با نمونه‌های chain، از جمله bridge‌های packet و WireGuard، توضیح می‌دهد.

## مدل config {#مدل-پیکربندی}

config WaterWall دو سطح دارد:

| فایل | کاربرد |
| --- | --- |
| `core.json` | راه‌اندازی WaterWall، تنظیم log‌ها، worker‌ها و DNS، و مشخص‌کردن فایل‌های config که باید load شوند. |
| فایل‌های config node‌ها | تعریف chain‌ها و تنظیمات هر node. |

نمونه‌ی `core.json` (مسیر داخل آن نسبت به پوشه‌ای است که WaterWall را از آن
اجرا می‌کنید):

```json
{
  "misc": {
    "workers": 4,
    "ram-profile": "server",
    "mtu": 1500,
    "try-enabling-bbr": true,
    "libs-path": "libs/"
  },
  "dns": {
    "domain-strategy": "prefer-ipv4"
  },
  "configs": [
    "configs/server.json"
  ]
}
```

chain متناظر را در `configs/server.json` ذخیره کنید:

```json
{
  "name": "simple-forward",
  "nodes": [
    {
      "name": "entry",
      "type": "TcpListener",
      "settings": {
        "address": "0.0.0.0",
        "port": 8080
      },
      "next": "exit"
    },
    {
      "name": "exit",
      "type": "TcpConnector",
      "settings": {
        "address": "example.com",
        "port": 80
      }
    }
  ]
}
```

در این نمونه، `entry` و `exit` نام node‌ها هستند و `"next": "exit"` listener
را به connector متصل می‌کند. پورت `8080` پورت محلی دریافت اتصال است و
`example.com:80` مقصد خروجی. این chain بایت‌های TCP را بدون بازنویسی header‌های
HTTP منتقل می‌کند. [راهنمای نصب](./01-getting-started/installation.mdx) مراحل
ساخت فایل‌ها و اجرای برنامه را توضیح می‌دهد.

## چرا WaterWall؟

### معماری ماژولار

در WaterWall مجبور نیستید همیشه از یک ساختار ثابت برای proxy استفاده کنید.
می‌توانید listener‌ها، connector‌ها و node‌های پروتکل، رمزنگاری، packet و
مسیریابی را متناسب با نیاز شبکه‌ی خود کنار هم بچینید.

### مبتنی بر config {#پیکربندیمحور}

بیشتر کارها از طریق فایل‌های JSON انجام می‌شود. بدون نوشتن کد C می‌توانید
chain‌ها را بسازید و تغییر دهید.

### پشتیبانی از stream و packet {#پشتیبانی-از-جریان-stream-و-بسته-packet}

WaterWall علاوه بر stream‌های معمول TCP، با مسیرهای packet هم کار می‌کند.
هرجا توپولوژی نیاز داشته باشد، می‌توانید packet‌ها را از طریق یک stream منتقل کنید.

### طراحی runtime {#پیادهسازی-مبتنی-بر-زمان-اجرا}

هسته با C نوشته شده و برای کار شبکه از I/O به‌صورت async، worker thread‌ها،
buffer pool‌ها و اجزای قابل‌استفاده‌ی مجدد تونل استفاده می‌کند.

## WaterWall چه چیزی نیست؟

WaterWall یک پروفایل VPN آماده یا preset یک‌کلیکی proxy نیست؛ ابزاری است که با آن
مسیر شبکه‌ی خود را می‌سازید. دستتان برای این کار باز است، اما باید بدانید
chain شما چگونه کار می‌کند.

برای نخستین راه‌اندازی، chain را کوچک نگه دارید، از کارکرد درست آن مطمئن شوید و
سپس node‌ها را یکی‌یکی اضافه کنید.

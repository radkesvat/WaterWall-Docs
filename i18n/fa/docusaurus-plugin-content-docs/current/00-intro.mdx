# معرفی WaterWall

WaterWall چارچوبی ماژولار و زنجیره‌محور برای تونل‌سازی است. با اتصال Nodeهای کوچک
(گره‌های اجرایی) به یکدیگر در فایل‌های پیکربندی JSON، می‌توانید مسیر دلخواه خود
را برای ترافیک شبکه بسازید.

یک زنجیره‌ی WaterWall می‌تواند به سادگی هدایت ترافیک یک پورت TCP باشد:

```text
TcpListener -> TcpConnector
```

یا چندین لایه‌ی انتقال، پروتکل، رمزنگاری، چندگانه‌سازی (`multiplexing`) و پردازش
بسته (`Packet`) را با هم ترکیب کند:

```text
TcpListener -> MuxClient -> VlessClient -> TlsClient -> TcpConnector
```

همین طراحی در فرایندهای بسته‌محور نیز کاربرد دارد؛ از جمله رابط‌های TUN، مسیرهای
شبیه WireGuard، پردازش بسته‌ی خام، پل‌های اتصال به بسته و پل‌های بسته به جریان
(`Stream`).

## WaterWall چگونه کار می‌کند؟

پیکربندی‌های WaterWall از Nodeها ساخته می‌شوند.

هر Node وظیفه‌ی مشخصی دارد:

| نقش Node | نمونه‌ها |
| --- | --- |
| دریافت ترافیک ورودی | `TcpListener`، `UdpListener`، `TunDevice` |
| اتصال به یک مقصد بیرونی | `TcpConnector`، `UdpConnector`، `UdpStatelessSocket` |
| تبدیل یا محافظت از ترافیک | `TlsClient`، `EncryptionClient`، `MuxClient`، `VlessClient` |
| مسیریابی یا بررسی ترافیک | `Router`، `SniffRouter`، `LoggerTunnel` |
| ایجاد پل میان مدل‌های اتصال، بسته و جریان | `ConnectionToPackets`، `PacketsToConnection`، `PacketsToStream`، `StreamToPackets` |

در فایل JSON، با فیلدهای `next` این Nodeها را به هم متصل می‌کنید. ترافیک در جهت
upstream، یعنی به‌سوی Node بعدی، از زنجیره عبور می‌کند و پاسخ‌ها در جهت downstream،
یعنی به‌سوی Node قبلی، از همان زنجیره بازمی‌گردند.

از آنجا که Nodeها قابل ترکیب‌اند، می‌توانید کار را با یک پیکربندی کوچک و عملیاتی
شروع کنید و قابلیت‌های موردنیاز را لایه‌به‌لایه به آن بیفزایید.

## مدل پیکربندی

پیکربندی WaterWall دو سطح دارد:

| فایل | کاربرد |
| --- | --- |
| `core.json` | راه‌اندازی WaterWall، پیکربندی ثبت گزارش، Workerها و DNS، و تعیین فایل‌های پیکربندی‌ای که باید بارگذاری شوند. |
| فایل‌های پیکربندی Nodeها | زنجیره‌های واقعی و تنظیمات Nodeها را تعریف می‌کنند. |

نمونه‌ی `core.json`:

```json
{
  "misc": {
    "workers": 4,
    "ram-profile": "server",
    "mtu": 1500,
    "try-enabling-bbr": true,
    "libs-path": "libs/"
  },
  "dns": {
    "domain-strategy": "prefer-ipv4"
  },
  "configs": [
    "configs/server.json"
  ]
}
```

نمونه‌ی پیکربندی یک زنجیره:

```json
{
  "name": "simple-forward",
  "nodes": [
    {
      "name": "entry",
      "type": "TcpListener",
      "settings": {
        "address": "0.0.0.0",
        "port": 8080
      },
      "next": "exit"
    },
    {
      "name": "exit",
      "type": "TcpConnector",
      "settings": {
        "address": "example.com",
        "port": 80
      }
    }
  ]
}
```

## چرا WaterWall؟

### معماری ماژولار

WaterWall برای همه‌ی استقرارها یک ساختار ثابت پراکسی تحمیل نمی‌کند. می‌توانید
Listenerها (ورودی‌ها)، ‏Connectorها (خروجی‌ها) و Nodeهای مربوط به پروتکل،
رمزنگاری، Packet و مسیریابی را طوری کنار هم بچینید که دقیقاً با نیاز شبکه‌ی شما
هماهنگ باشد.

### پیکربندی‌محور

بیشتر کارها از طریق فایل‌های JSON انجام می‌شود. بدون نوشتن کد C می‌توانید
زنجیره‌ها را بسازید و تغییر دهید.

### پشتیبانی از جریان (`Stream`) و بسته (`Packet`)

WaterWall فقط به جریان‌های معمول TCP محدود نیست. می‌تواند با مسیرهای بسته‌محور نیز
کار کند و هرجا توپولوژی ایجاب کند، بسته‌ها را از طریق بسترهای انتقال جریانی
جابه‌جا کند.

### پیاده‌سازی مبتنی بر زمان اجرا

هسته با زبان C نوشته شده و بر پایه‌ی شبکه‌سازی ناهمگام، رشته‌های کاری
(`worker threads`)، مخزن‌های بافر (`buffer pools`) و اجزای قابل‌استفاده‌ی مجدد تونل
طراحی شده است.

## WaterWall چه چیزی نیست؟

WaterWall یک پروفایل VPN ازپیش‌آماده یا یک پیش‌تنظیم پراکسی یک‌کلیکی نیست؛ بلکه
جعبه‌ابزاری برای ساخت مسیرهای شبکه است. این انعطاف قدرت زیادی به شما می‌دهد، اما
در عوض باید زنجیره‌ای را که می‌سازید به‌درستی بشناسید.

برای نخستین راه‌اندازی، زنجیره را کوچک نگه دارید، از کارکرد درست آن مطمئن شوید و
سپس Nodeها را یکی‌یکی اضافه کنید.

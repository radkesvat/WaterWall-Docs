# HttpProxyClient

این node درخواست HTTP/1.1 یا تونل CONNECT را از proxy بالادست عبور می‌دهد. node بعدی باید به endpoint خود proxy وصل شود؛ `target-address` و `port` مقصد داخل proxy را انتخاب می‌کنند.

## رفتار DNS

با `settings.dns-behaviour`، فعال‌بودن lookup محلی، انتخاب آدرس و انتقال DNS را مستقل تنظیم کنید. در صورت حذف object، resolve محلی غیرفعال می‌ماند.

```json
{"dns-behaviour": {"resolve": true, "mode": "direct", "strategy": "prefer-ipv4", "servers": ["203.0.113.53:53"]}}
```

این IP نمونهٔ مستندات است؛ آن را با سرور خود جایگزین کنید.

| فیلد | معنی |
| --- | --- |
| `resolve` | boolean اجباری در صورت نوشتن object. |
| `mode` | `native` (پیش‌فرض هنگام فعال بودن)، `direct` یا `chain`. |
| `strategy` | یکی از `core-settings`، `accept-dns-returned-order`، `prefer-ipv4`، `prefer-ipv6`، `only-ipv4` یا `only-ipv6`؛ حذف آن پیش‌فرض قبلی مصرف‌کننده را نگه می‌دارد. |
| `servers` | ۱ تا ۳۲ endpoint عددی IP، IP:port یا [IPv6]:port؛ در direct/chain اجباری و در native ممنوع. |
| `dns-next` | نام غیرخالی ورودی DNS، فقط در chain. |

در `native`، کانال مشترک worker و گزینه‌های DNS در core استفاده می‌شود. `direct` یک شاخهٔ خصوصی TCP/UDP به سرورهای صریح می‌سازد. `chain` lineهای DNS را از ورودی انتخابی می‌فرستد؛ رمزنگاری به همان مسیر بستگی دارد. UDP و fallback روی TCP هر دو لازم‌اند. خطای route یا lookup حالت را عوض نمی‌کند و مسیر fallback برنامه را انتخاب نمی‌کند.

در حالت `chain`، `dns-next` صریح باید یک شاخهٔ DNS جدا و بدون مالک قبلی را نام ببرد.
شاخهٔ صریح باید بدون مالک قبلی باشد. نام‌بردن از خود node یا شاخهٔ متعلق به مالک دیگر رد می‌شود.

شکل غیرفعال دقیقاً `"dns-behaviour": {"resolve": false}` است و فیلدهای `mode`، `strategy`، `servers` و `dns-next` را رد می‌کند. object تهی، null، نوع غیرobject، فیلد ناشناخته، strategy عددی و هم‌زمانی با `domain-strategy` یا `resolve-domains` همان scope رد می‌شود. با حذف object، فیلدهای قدیمی همچنان معتبرند. `core-settings` فقط اولویت آدرس را انتخاب می‌کند و انتقال DNS را تغییر نمی‌دهد.

با `resolve: false`، درخواست proxy در صورت پشتیبانی پروتکل نام دامنه را نگه می‌دارد. connector بعدی مقصد مستقل proxy یا VPN و سیاست DNS خودش را دارد؛ برای bootstrap از IP عددی یا مسیر مستقل استفاده کنید.

resolve محلی فقط با `mode: "connect"` مجاز است. حالت HTTP عادی معنای authority را نگه می‌دارد. `settings.mode` برای HTTP و `settings.dns-behaviour.mode` برای انتقال DNS است.

مثال‌های native، direct و chain محافظت‌شده و محدودیت گزینه‌های core را در [DomainResolver](./DomainResolver.mdx) ببینید. این سیاست فقط lookupهای متعلق به همین node را کنترل می‌کند؛ fake DNS در PTC، DNS سیستم در TunDevice و همهٔ منابع DNS برنامه را تغییر نمی‌دهد.

## تنظیمات HTTP

`mode` یکی از `connect` (پیش‌فرض) یا `http` است. `target-address` و `port` اجباری‌اند و می‌توانند از `dest_context->address` و `dest_context->port` خوانده شوند. حالت HTTP یک درخواست می‌سازد و بایت‌های node قبلی را body آن می‌گیرد. `method`، `path` و `body-mode` آن را مشخص می‌کنند. `username` و `password` احراز هویت Basic اختیاری را فعال می‌کنند. برای TLS به proxy، `TlsClient` را پیش از connector قرار دهید.

```text
TcpListener -> HttpProxyClient -> TcpConnector
```

برای HTTP کامل و تنظیمات timeout و header، [مرجع انگلیسی](https://radkesvat.github.io/WaterWall/docs/noderefs/HttpProxyClient) را ببینید.

# RealityServer

`RealityServer` tunnel سمت server برای Reality در واتروال است. این نود هر line ورودی را در ابتدا ترافیک عادی visitor در نظر می‌گیرد و آن را به شاخه `destination` می‌فرستد؛ هم‌زمان recordهای TLS در جهت client-to-server را زیر نظر دارد تا یک Reality record معتبر پیدا کند. پس از احراز اصالت موفق، شاخه visitor بسته می‌شود و همان line به chain محافظت‌شده `next` تغییر مسیر می‌دهد.

سرور TLS مربوط به visitorها را خاتمه نمی‌دهد؛ فقط به اندازه‌ای recordهای شبیه TLS را بررسی می‌کند که تشخیص دهد peer یک Reality client معتبر است یا ترافیک عادی visitor.

## جایگاه رایج

```text
TcpListener -> RealityServer -> protected-chain
                 |
                 +-> destination visitor branch
```

نود `next` ترافیک مجاز Reality را دریافت می‌کند. گزینه `destination` نام شاخه معمول visitor است که اغلب یک `TcpConnector` برای سایت واقعی visitor خواهد بود.

## نمونه تنظیمات

```json
{
  "name": "reality-server",
  "type": "RealityServer",
  "settings": {
    "destination": "visitor-site",
    "password": "replace-with-a-strong-secret",
    "algorithm": "chacha20-poly1305",
    "sniffing-attempts": 8
  },
  "next": "protected-chain"
}
```

مقصد visitor:

```json
{
  "name": "visitor-site",
  "type": "TcpConnector",
  "settings": {
    "address": "www.example.com",
    "port": 443
  }
}
```

## فیلدهای اجباری

| فیلد | نوع | توضیح |
|---|---|---|
| `type` | string | باید `RealityServer` باشد. |
| `next` | string | نودی که payload decrypt شده و تاییدشده Reality را می‌گیرد. |
| `settings` | object | باید object غیرخالی باشد. |
| `settings.destination` | string | نام نود مربوط به ترافیک visitor. نود باید وجود داشته باشد و نمی‌تواند خود `RealityServer` یا نود مجاز `next` باشد. |
| `settings.password` | string | secret مشترک و غیرخالی Reality؛ باید با client یکسان باشد. |

## تنظیمات

| گزینه | پیش‌فرض | توضیح |
|---|---|---|
| `destination` | اجباری | شاخه visitor. تا پیش از authorization، handshake، TLS معمول visitor، probeهای نامعتبر و candidateهای ناموفق Reality به این شاخه فرستاده می‌شوند. |
| `password` | اجباری | secret مشترک برای key derivation. |
| `algorithm` | `chacha20-poly1305` | یکی از `chacha20-poly1305`، `chacha20poly1305`، `aes-gcm`، `aes-256-gcm` یا `aes256gcm`. |
| `method` | مثل `algorithm` | alias برای `algorithm`، وقتی `algorithm` وجود نداشته باشد. |
| `salt` | `waterwall-reality` | salt برای key derivation. باید با client یکی باشد. |
| `kdf-iterations` | `12000` | تعداد roundهای key derivation. بازه معتبر `1` تا `1000000`. |
| `max-frame-size` | `16356` | حداکثر plaintext هر Reality record. بازه معتبر `1` تا `16356`. downstream payload بزرگ‌تر split می‌شود. |
| `sniffing-attempts` | `8` | تعداد candidateهای Reality ناموفق قبل از اینکه line به‌صورت دائم visitor فرض شود. بازه معتبر `1` تا `1024`. |
| `sniffing-counter` | مثل `sniffing-attempts` | alias قدیمی، فقط وقتی `sniffing-attempts` وجود نداشته باشد. |

اگر `aes-gcm` انتخاب شود اما crypto backend فعال از AES-GCM پشتیبانی نکند، ساخت tunnel شکست می‌خورد.

## شاخه Visitor و Protected

در upstream `Init`، `RealityServer` state مربوط به line را مقداردهی اولیه می‌کند و بی‌درنگ شاخه `destination` را آماده می‌سازد. chain محافظت‌شده `next` در این مرحله هنوز initialize نشده است.

تا قبل از authorization:

1. بایت‌های upstream به شکل TLS recordهای محتمل خوانده می‌شوند
2. recordهای handshake، alert و change-cipher-spec و سایر recordهای TLS که candidate نیستند به `destination` می‌روند
3. از application-data recordهایی که ممکن است Reality باشند یک کپی گرفته می‌شود و احراز اصالت روی همان کپی انجام می‌گیرد
4. اگر احراز اصالت شکست بخورد، record اصلی به `destination` فرستاده می‌شود
5. اگر احراز اصالت موفق باشد، شاخه visitor با `Finish` بسته و chain محافظت‌شده `next` مقداردهی اولیه می‌شود

بعد از authorization:

| جهت | رفتار |
|---|---|
| Upstream payload | باید Reality record معتبر باشد؛ پس از احراز اصالت و رمزگشایی، cleartext به `next` می‌رود. |
| Downstream payload | cleartext مربوط به `next` رمزنگاری می‌شود و در قالب TLS-like application-data record به نود قبلی برمی‌گردد. |

اگر بعد از authorization upstream نامعتبر باشد، TLS record غیر Reality برسد، یا authentication شکست بخورد، line از هر دو جهت بسته می‌شود.

## قوانین Visitor Fallback

line در یکی از این حالت‌ها به ترافیک visitor تبدیل می‌شود:

- bytes pending یک TLS record محتمل نباشند
- تعداد Reality candidateهای ناموفق به `sniffing-attempts` برسد

بعد از visitor شدن، upstream به `destination` می‌رود و downstream همان شاخه به نود قبلی برمی‌گردد. chain محافظت‌شده `next` برای آن line init نمی‌شود.

## قالب Record

```text
TLS record header (5 bytes)
nonce             (12 bytes)
ciphertext
AEAD tag          (16 bytes)
```

header شبیه TLS از این مقادیر استفاده می‌کند:

| فیلد | مقدار |
|---|---|
| Content type | `0x17` application data |
| Version | `0x0303` |
| Length | `12-byte nonce + ciphertext + 16-byte tag` |

TLS record header به‌عنوان associated data مربوط به AEAD احراز اصالت می‌شود. nonce هر record رمزنگاری‌شده downstream به‌طور مستقل تصادفی است.

## نکته‌های Buffer و Lifecycle

- `RealityServer` به‌ازای هر line state نگه می‌دارد که شامل record parser، mode فعلی، state initialization شاخه destination/protected و transition flagها است.
- این نود line معمولی را نه ایجاد می‌کند و نه از بین می‌برد و فقط state خودش را پیش از فرستادن callbackهای `Finish` پاک می‌کند.
- این نود `17` بایت required left padding اعلام می‌کند: `5` بایت برای TLS-like record header و `12` بایت برای پیشوند nonce.
- bufferهای خالی payload در جهت downstream از chain محافظت‌شده، بدون فرستادن Reality record به pool برگردانده می‌شوند.
- payloadهایی بزرگ‌تر از `max-frame-size` به چند record رمزنگاری‌شده تقسیم می‌شوند.
- هنگام انتقال به حالت authorized، callbackهای downstream ناشی از بستن شاخه visitor نادیده گرفته می‌شوند تا به سمتی که در حال تغییر مسیر است بازتاب پیدا نکنند.

## نکته‌های عملیاتی

- `destination` برای ترافیک عادی visitor است و بهتر است همان visitor domain مربوط به `RealityClient.settings.sni` را سرو یا proxy کند.
- `next` فقط برای ترافیک مجاز واتروال است.
- `password`، `salt`، `kdf-iterations` و `algorithm` باید با `RealityClient` یکی باشند.
- این نود یک stream tunnel است، نه packet tunnel.

## مشخصات نود

| ویژگی | مقدار |
|---|---|
| جایگاه | Middle stream tunnel با visitor branch |
| نیاز به `next` | بله |
| نیاز به `destination` | بله |
| Previous layer | Anything |
| Next layer | Anything |
| Per-line state | دارد |
| ایجاد line | خیر |
| از بین بردن line | خیر |
| Required left padding | `17` |

# RealityServer

`RealityServer` سمت server پیاده‌سازی Reality در WaterWall است. این نود هر line ورودی را ابتدا به عنوان visitor traffic در نظر می‌گیرد، traffic را به شاخه `destination` می‌فرستد، و هم‌زمان recordهای TLS سمت client-to-server را برای پیدا کردن Reality record معتبر بررسی می‌کند. اگر authentication موفق شود، شاخه visitor بسته می‌شود و همان line به chain محافظت‌شده `next` منتقل می‌شود.

این نود TLS visitorها را terminate نمی‌کند؛ فقط به اندازه لازم sniff می‌کند تا بفهمد peer یک Reality client معتبر است یا visitor معمولی.

## جایگاه رایج

```text
TcpListener -> RealityServer -> protected-chain
                 |
                 +-> destination visitor branch
```

نود `next` فقط traffic تاییدشده Reality را می‌گیرد. گزینه `destination` نام نودی است که visitor traffic عادی به آن فرستاده می‌شود؛ معمولاً یک `TcpConnector` برای سایت واقعی visitor.

## نمونه تنظیمات

```json
{
  "name": "reality-server",
  "type": "RealityServer",
  "settings": {
    "destination": "visitor-site",
    "password": "replace-with-a-strong-secret",
    "algorithm": "chacha20-poly1305",
    "sniffing-attempts": 8
  },
  "next": "protected-chain"
}
```

مقصد visitor:

```json
{
  "name": "visitor-site",
  "type": "TcpConnector",
  "settings": {
    "address": "www.example.com",
    "port": 443
  }
}
```

## فیلدهای اجباری

| فیلد | نوع | توضیح |
|---|---|---|
| `type` | string | باید `RealityServer` باشد. |
| `next` | string | نودی که payload decrypt شده و تاییدشده Reality را می‌گیرد. |
| `settings` | object | باید object غیرخالی باشد. |
| `settings.destination` | string | نام node مربوط به visitor traffic. این node باید وجود داشته باشد و نباید خود `RealityServer` یا `next` محافظت‌شده باشد. |
| `settings.password` | string | secret مشترک Reality. باید با client یکی باشد. |

## تنظیمات

| گزینه | پیش‌فرض | توضیح |
|---|---|---|
| `destination` | اجباری | شاخه visitor. handshake، TLS visitor عادی، probe نامعتبر و Reality candidate ناموفق تا قبل از authorization به این شاخه forward می‌شوند. |
| `password` | اجباری | secret مشترک برای key derivation. |
| `algorithm` | `chacha20-poly1305` | یکی از `chacha20-poly1305`، `chacha20poly1305`، `aes-gcm`، `aes-256-gcm` یا `aes256gcm`. |
| `method` | مثل `algorithm` | alias برای `algorithm`، وقتی `algorithm` وجود نداشته باشد. |
| `salt` | `waterwall-reality` | salt برای key derivation. باید با client یکی باشد. |
| `kdf-iterations` | `12000` | تعداد roundهای key derivation. بازه معتبر `1` تا `1000000`. |
| `max-frame-size` | `16356` | حداکثر plaintext هر Reality record. بازه معتبر `1` تا `16356`. downstream payload بزرگ‌تر split می‌شود. |
| `sniffing-attempts` | `8` | تعداد candidateهای Reality ناموفق قبل از اینکه line به صورت دائم visitor فرض شود. بازه معتبر `1` تا `1024`. |
| `sniffing-counter` | مثل `sniffing-attempts` | alias قدیمی، فقط وقتی `sniffing-attempts` وجود نداشته باشد. |

اگر `aes-gcm` انتخاب شود ولی crypto backend فعلی AES-GCM را پشتیبانی نکند، ساخت tunnel fail می‌شود.

## شاخه Visitor و Protected

در upstream `Init`، `RealityServer` state خودش را آماده می‌کند و فوراً شاخه `destination` را init می‌کند. chain محافظت‌شده `next` هنوز init نمی‌شود.

تا قبل از authorization:

1. bytes upstream به عنوان TLS record محتمل parse می‌شوند
2. handshake، alert، change-cipher-spec و recordهای TLS غیر candidate به `destination` می‌روند
3. application-data recordهایی که ممکن است Reality باشند duplicate می‌شوند و authentication روی نسخه duplicate انجام می‌شود
4. اگر authentication شکست بخورد، record اصلی به `destination` forward می‌شود
5. اگر authentication موفق شود، شاخه visitor finish می‌شود و chain محافظت‌شده `next` init می‌شود

بعد از authorization:

| جهت | رفتار |
|---|---|
| Upstream payload | باید Reality record معتبر باشد؛ authenticate و decrypt می‌شود و cleartext به `next` می‌رود. |
| Downstream payload | cleartext از `next` رمزنگاری شده و به صورت TLS-like application-data record به نود قبلی برمی‌گردد. |

اگر بعد از authorization upstream نامعتبر باشد، TLS record غیر Reality برسد، یا authentication شکست بخورد، line از هر دو جهت بسته می‌شود.

## قوانین Visitor Fallback

line در این حالت‌ها visitor می‌شود:

- bytes pending یک TLS record محتمل نباشند
- تعداد Reality candidateهای ناموفق به `sniffing-attempts` برسد

بعد از visitor شدن، upstream به `destination` می‌رود و downstream همان شاخه به نود قبلی برمی‌گردد. chain محافظت‌شده `next` برای آن line init نمی‌شود.

## قالب Record

```text
TLS record header (5 bytes)
nonce             (12 bytes)
ciphertext
AEAD tag          (16 bytes)
```

header شبیه TLS application data با content type `0x17` و version `0x0303` است. header به عنوان AEAD associated data استفاده می‌شود و nonce برای recordهای downstream تصادفی است.

## نکته‌های Buffer و Lifecycle

- `RealityServer` به ازای هر line state نگه می‌دارد که شامل record parser، mode فعلی، state initialization شاخه destination/protected و transition flagها است.
- این نود line معمولی را ایجاد یا destroy نمی‌کند؛ فقط state خودش را قبل از propagate کردن finish callbackها destroy می‌کند.
- این نود `17` بایت required left padding advertise می‌کند: `5` بایت برای TLS-like record header و `12` بایت برای nonce prefix.
- downstream payload bufferهای خالی از chain محافظت‌شده بدون ارسال Reality record recycle می‌شوند.
- payloadهایی بزرگ‌تر از `max-frame-size` به چند record رمزنگاری‌شده تقسیم می‌شوند.
- در زمان authorized transition، downstream callbackهای ناشی از بسته شدن شاخه visitor suppressed می‌شوند تا به سمت switching برنگردند.

## نکته‌های عملیاتی

- `destination` برای visitor traffic عادی است و بهتر است بتواند همان visitor domain مورد استفاده در `RealityClient.settings.sni` را سرو کند یا proxy کند.
- `next` فقط برای traffic تاییدشده WaterWall است.
- `password`، `salt`، `kdf-iterations` و `algorithm` باید با `RealityClient` یکی باشند.
- این نود stream tunnel است، نه packet tunnel.
- `required_padding_left` این نود `17` است.

## مشخصات نود

| ویژگی | مقدار |
|---|---|
| جایگاه | Middle stream tunnel با visitor branch |
| نیاز به `next` | بله |
| نیاز به `destination` | بله |
| Previous layer | Anything |
| Next layer | Anything |
| Per-line state | دارد |
| ایجاد line | خیر |
| destroy کردن line | خیر |
| Required left padding | `17` |

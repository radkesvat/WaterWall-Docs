# ConnectionFisherClient

`ConnectionFisherClient` سمت client برای `ConnectionFisherServer` است. این نود به ازای هر line ورودی، چند child line همزمان به سمت `next` می‌سازد، روی هر کدام probe پنج‌بایتی `FISH?` می‌فرستد و اولین child line را که پاسخ معتبر `FISH!` دریافت کند، نگه می‌دارد.

این نود زمانی مفید است که مسیر خروجی ناپایدار باشد یا بخواهید چند تلاش همزمان انجام شود و اولین مسیری که به `ConnectionFisherServer` متناظر ثابت کند برسد، انتخاب شود.

## جایگاه رایج

طرح‌بندی ساده TCP:

```text
TcpListener -> ConnectionFisherClient -> TcpConnector
TcpListener -> ConnectionFisherServer -> TcpConnector
```

با tunnel‌های stream دیگر در میان:

```text
TesterClient -> ConnectionFisherClient -> MuxClient -> MuxServer -> ConnectionFisherServer -> TesterServer
```

client و server باید در یک مسیر stream منطقی جفت باشند. هر tunnel میانی باید byteهای probe ثابت را سرتاسر حفظ کند.

## این نود چه می‌کند؟

- مقدار `settings.simultaneous-tries-perline` را می‌خواند.
- به ازای هر upstream `Init` روی main line، آن تعداد child line داخلی می‌سازد.
- upstream `Init` را روی هر child line به `next` می‌فرستد.
- probe ثابت `FISH?` را روی هر child line می‌فرستد.
- منتظر پاسخ ثابت `FISH!` می‌ماند.
- payload upstream روی main line را در صف نگه می‌دارد تا یک child انتخاب شود.
- اولین child که پاسخ معتبر دریافت کند را انتخاب می‌کند.
- همه child lineهای انتخاب‌نشده را می‌بندد.
- payloadهای upstream صف‌شده را به ترتیب به child انتخاب‌شده flush می‌کند.
- payloadهای downstream از child انتخاب‌شده را به main line برمی‌گرداند.

`ConnectionFisherClient` یک middle stream tunnel است. socket مستقیم نمی‌سازد و packet line نمی‌سازد.

## نمونه تنظیم

```json
{
  "name": "fisher-client",
  "type": "ConnectionFisherClient",
  "settings": {
    "simultaneous-tries-perline": 3
  },
  "next": "tcp-out"
}
```

سمت server متناظر:

```json
{
  "name": "fisher-server",
  "type": "ConnectionFisherServer",
  "next": "service"
}
```

## فیلدهای اجباری

فیلدهای top-level:

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `name` | string | نام یکتای نود داخل config. |
| `type` | string | باید دقیقاً `"ConnectionFisherClient"` باشد. |
| `next` | string | اجباری. نود stream بعدی که child lineهای candidate را دریافت می‌کند. |

`ConnectionFisherClient` باید نود قبلی هم داشته باشد. chain head یا chain end نیست.

## تنظیمات اختیاری

| گزینه | نوع | پیش‌فرض | توضیح |
| --- | --- | --- | --- |
| `simultaneous-tries-perline` | integer >= 1 | `2` | تعداد child lineهای candidate که به ازای هر main line ورودی ساخته می‌شوند. |

`settings` می‌تواند حذف شود. مقادیر کمتر از `1` رد می‌شوند.

## تبادل Probe

probe ثابت است و secret قابل تنظیمی ندارد:

| جهت | Bytes | معنی |
| --- | --- | --- |
| client به server | `FISH?` | بلافاصله بعد از upstream `Init` روی هر child line فرستاده می‌شود. |
| server به client | `FISH!` | پاسخ اجباری از `ConnectionFisherServer`. |

این marker‌ها فقط ثابت می‌کنند که child line به `ConnectionFisherServer` متناظر رسیده است. authentication، encryption یا حفاظت از integrity ترافیک نیستند.

## مدل Line

`ConnectionFisherClient` از دو نوع line استفاده می‌کند:

| Line | هدف |
| --- | --- |
| main line | line ورودی اصلی از نود قبلی. روی سمت previous باقی می‌ماند. |
| child lines | lineهای candidate داخلی که توسط client ساخته شده و فقط به سمت `next` می‌روند. |

main line اصلی هرگز مستقیم به `next` فرستاده نمی‌شود. child lineها هرگز به سمت `prev` فرستاده نمی‌شوند. بعد از انتخاب یک child، tunnel به صورت دستی payload، `Est`، `Pause`، `Resume` و `Finish` را بین main line و child انتخاب‌شده bridge می‌کند.

## جریان انتخاب

برای هر upstream `Init` روی main line:

1. state مربوط به main line initialize می‌شود.
2. `simultaneous-tries-perline` child line روی همان worker ساخته می‌شود.
3. هر child line به سمت `next` initialize می‌شود.
4. هر child، `FISH?` می‌فرستد.
5. main line یک selection timeout با مدت `5000 ms` schedule می‌کند.
6. payload upstream روی main line در صف نگه داشته می‌شود تا child winner مشخص شود.
7. اولین child که `FISH!` دریافت کند، child انتخاب‌شده می‌شود.
8. child lineهای بازنده بسته می‌شوند.
9. payloadهای upstream صف‌شده به child انتخاب‌شده flush می‌شوند.
10. byteهای downstream اضافه که از قبل بعد از `FISH!` buffer شده‌اند به عنوان downstream payload به نود قبلی فرستاده می‌شوند.

اگر هیچ child قبل از timeout validate نشود، main line بسته می‌شود.

## محدودیت‌ها و Buffer

| محدودیت | مقدار | رفتار |
| --- | --- | --- |
| Selection timeout | `5000 ms` | اگر child‌ای انتخاب نشود، main line بسته می‌شود. |
| Pending upstream payload | `1 MiB` | اگر payload صف‌شده از این حد بگذرد، main line بسته می‌شود. |
| Child handshake buffer | `4096 bytes` | اگر child غیر-انتخاب‌شده داده handshake زیاد جمع کند، main line بسته می‌شود. |
| `required_padding_left` | `0` | نود header protocol به buffer‌های موجود اضافه نمی‌کند. |

probe `FISH?` به عنوان یک buffer کوچک جداگانه اختصاص می‌یابد. payload کاربر به عنوان buffer‌های WaterWall موجود در صف قرار می‌گیرد یا forward می‌شود.

## رفتار Lifecycle

قبل از انتخاب:

- payload upstream از main line در صف قرار می‌گیرد
- payload downstream از child به عنوان داده handshake در نظر گرفته می‌شود
- downstream `Est` child را established علامت می‌زند اما به main line forward نمی‌شود مگر اینکه آن child قبلاً انتخاب شده باشد
- pause و resume تا زمان انتخاب child، به main line منعکس نمی‌شوند

بعد از انتخاب:

- payload upstream روی main line با `tunnelNextUpStreamPayload` به child انتخاب‌شده forward می‌شود
- payload downstream روی child انتخاب‌شده با `tunnelPrevDownStreamPayload` به نود قبلی forward می‌شود
- downstream `Est` از child انتخاب‌شده یک بار به نود قبلی forward می‌شود
- pause و resume فقط از طریق جفت child انتخاب‌شده/main-line bridge می‌شوند

اگر child انتخاب‌شده ببندد، main line بسته می‌شود. اگر همه childها قبل از انتخاب winner ببندند، main line هم بسته می‌شود.

## نکته‌ها

- با `ConnectionFisherServer` متناظر استفاده کنید.
- برای chainهای stream طراحی شده است، نه packet-line.
- افزایش `simultaneous-tries-perline` بار connection را هم افزایش می‌دهد.
- probe ثابت و عمومی است؛ برای مسیرهایی که به امنیت نیاز دارند از TLS، encryption، authentication یا routing node استفاده کنید.
- upstream `Est` و downstream `Init` برای این نود غیرفعال هستند.

# RawSocket

`RawSocket`، WaterWall را به capture کردن packetهای خام IPv4 و inject کردن packetهای خام IPv4 وصل می‌کند. این نود می‌تواند packetها را از networking stack میزبان بگیرد، آن‌ها را وارد یک chain لایه ۳ کند، و packetهای خام IP برگشتی از chain را دوباره به raw output device بنویسد.

در مستندات قدیمی ممکن است این نود با نام `RawDevice` دیده شود. نام فعلی node type برابر `RawSocket` است.

`RawSocket` یک adapter لایه ۳ است، نه یک tunnel connection-oriented. packetهای capture شده روی worker packet lineها forward می‌شوند، و payloadی که از هر سمت chain به `RawSocket` برسد به عنوان یک packet خام IP کامل در نظر گرفته شده و روی raw output device نوشته می‌شود.

## جایگاه رایج

در لبه یک packet chain:

```text
RawSocket -> PacketReceiver
PacketSender -> RawSocket
TunDevice -> IpManipulator -> RawSocket
```

همراه نودهای packet disguise:

```text
TunDevice -> PingClient -> RawSocket
RawSocket -> PingServer -> TunDevice
```

`RawSocket` می‌تواند نود قبلی، نود بعدی، یا هر دو را داشته باشد. جهت packetهای capture شده در startup انتخاب می‌شود:

| جایگاه در chain | packetهای IPv4 capture شده به کجا forward می‌شوند |
| --- | --- |
| `RawSocket` آخرین نود chain است | به نود قبلی، از طریق downstream payload |
| `RawSocket` آخرین نود chain نیست | به نود بعدی، از طریق upstream payload |

Payloadی که از upstream یا downstream به `RawSocket` برسد از همان raw output device inject می‌شود.

## نمونه تنظیم

```json
{
  "name": "raw-ip",
  "type": "RawSocket",
  "settings": {
    "capture-device-name": "capture-in",
    "raw-device-name": "raw-out",
    "capture-filter-mode": "source-ip",
    "capture-ips": [
      "192.0.2.10",
      "198.51.100.0/24"
    ],
    "mark": 10
  },
  "next": "next-node-name"
}
```

## فیلدهای ضروری

فیلدهای سطح بالا:

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `name` | string | نام دلخواه نود. باید داخل فایل config یکتا باشد. |
| `type` | string | باید دقیقاً `"RawSocket"` باشد. |
| `settings` | object | لازم است، چون capture mode و capture rangeها باید تنظیم شوند. |

فیلدهای ضروری داخل `settings`:

| گزینه | نوع | توضیح |
| --- | --- | --- |
| `capture-filter-mode` | string | حالت فیلتر capture. parser مقدارهای `"source-ip"` و `"dest-ip"` را می‌شناسد، اما پیاده‌سازی فعلی فقط `"source-ip"` را قبول می‌کند. |
| `capture-ips` | آرایه string | آرایه غیرخالی از آدرس‌های IPv4 یا CIDRهای IPv4 برای capture. |

هر عضو `capture-ips` می‌تواند یک IPv4 تکی باشد:

```json
"192.0.2.10"
```

یا یک CIDR IPv4:

```json
"198.51.100.0/24"
```

مقادیر IPv6 رد می‌شوند.

## تنظیمات اختیاری

| گزینه | نوع | پیش‌فرض | توضیح |
| --- | --- | --- | --- |
| `capture-device-name` | string | `unnamed-capture-device` | نامی که به capture-device backend داده می‌شود. |
| `raw-device-name` | string | `unnamed-raw-device` | نامی که به raw-output backend داده می‌شود. |
| `mark` | integer | `0` | firewall mark برای raw output device، در platform/backendهایی که پشتیبانی می‌کنند. |

Aliasهای سازگاری:

| Alias | معنا |
| --- | --- |
| `listen-ips` | به عنوان alias برای `capture-ips` پذیرفته می‌شود. |
| `capture-ip` | legacy single-string capture range. به عنوان یک entry شبیه `/32` پذیرفته می‌شود؛ برای config جدید از `capture-ips` استفاده کنید. |

## مسیر Capture

در startup، `RawSocket` این‌ها را می‌سازد:

- یک capture device با rangeهای IPv4 تنظیم‌شده
- یک raw output device برای packet injection

وقتی capture backend یک packet دریافت می‌کند:

1. `RawSocket` بررسی می‌کند packet از نوع IPv4 باشد.
2. packetهای غیر IPv4 recycle می‌شوند و forward نمی‌شوند.
3. worker packet line همان worker از chain گرفته می‌شود.
4. packet IPv4 capture شده به سمت adjacent انتخاب‌شده forward می‌شود.

انتظار می‌رود capture backend فیلتر IP تنظیم‌شده را اعمال کند. `RawSocket` برای هر packet یک line معمولی per-connection نمی‌سازد.

## مسیر Output

وقتی upstream یا downstream payload به `RawSocket` می‌رسد:

1. buffer payload به عنوان raw IP packet در نظر گرفته می‌شود.
2. اگر line مقدار `recalculate_checksum` داشته باشد و packet از نوع IPv4 باشد، WaterWall قبل از نوشتن checksumهای packet را دوباره محاسبه می‌کند.
3. packet از طریق raw output device نوشته می‌شود.
4. اگر raw device down باشد یا write شکست بخورد، buffer recycle می‌شود.

هر دو callback upstream و downstream payload از همین write path استفاده می‌کنند.

## رفتار Checksum

`RawSocket` به metadata مربوط به checksum روی packet-line که از نودهای packet قبلی آمده احترام می‌گذارد.

اگر `line->recalculate_checksum` تنظیم شده باشد و payload از نوع IPv4 باشد:

- تلاش می‌شود checksum کامل packet دوباره محاسبه شود
- flag بعد از recalculation پاک می‌شود
- جزئیات checksum transport در IPv4 fragment شده توسط helper مشترک checksum مدیریت می‌شود

این بعد از نودهایی مثل `IpManipulator` یا `IpOverrider` مفید است که فیلدهای IPv4، TCP، UDP یا ICMP را تغییر می‌دهند و قبل از output نهایی درخواست checksum repair می‌کنند.

## محدودیت‌های Capture Filter

settings parser این مقدارها را می‌شناسد:

```text
source-ip
dest-ip
```

رفتار فعلی سخت‌گیرانه‌تر است:

- `source-ip` پذیرفته می‌شود
- `dest-ip` باعث شکست tunnel creation می‌شود و پیام خطا استفاده از `TunDevice` را برای capture-style خروجی پیشنهاد می‌کند

وقتی virtual-interface behavior یا packet handling خروجی routed می‌خواهید از `TunDevice` استفاده کنید. وقتی به طور مشخص host-stack capture همراه raw IPv4 injection می‌خواهید از `RawSocket` استفاده کنید.

## رفتار Direction و Lifecycle

| Callback | رفتار |
| --- | --- |
| upstream `Payload` | payload را از طریق raw output device inject می‌کند. |
| downstream `Payload` | payload را از طریق raw output device inject می‌کند. |
| captured packet callback | IPv4 capture شده را روی worker packet line به سمت adjacent انتخاب‌شده forward می‌کند. |
| `Init`, `Est`, `Pause`, `Resume`, `Finish` | no-op. `RawSocket` با connection lifecycle هدایت نمی‌شود. |

`RawSocket` یک adapter است و در runtime معمول packet lineها را destroy نمی‌کند. Worker packet lineها متعلق به chain هستند.

## متادیتای نود

Metadata بر اساس source:

| ویژگی | مقدار |
| --- | --- |
| node flags | `kNodeFlagChainHead | kNodeFlagChainEnd` |
| adapter | `true` |
| `can_have_prev` | `true` |
| `can_have_next` | `true` |
| `layer_group` | `kNodeLayer3` |
| `layer_group_prev_node` | `kNodeLayerAnything` |
| `layer_group_next_node` | `kNodeLayerAnything` |
| `required_padding_left` | `0` bytes |

این نود protocol header اضافه نمی‌کند و به left padding نیاز ندارد.

## نکته‌های عملی

- با privilegeهای لازم برای raw/capture backend همان platform اجرا کنید.
- `capture-ips` را صریح تنظیم کنید؛ آرایه خالی رد می‌شود.
- به جای `capture-ip` قدیمی، `capture-ips` را ترجیح دهید.
- receive path فعلی فقط packetهای IPv4 را forward می‌کند.
- رفتار platform به raw socket، capture backend و firewall mark backend موجود وابسته است.

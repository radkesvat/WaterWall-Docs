# RawSocket

`RawSocket` نود فعلی برای capture و injection خام IPv4 است. در بعضی مستندات
قدیمی‌تر ممکن است با نام `RawDevice` دیده شود، اما نوع درست نود در نسخه فعلی
`RawSocket` است.

این نود connection-oriented نیست؛ یک adapter لایه ۳ است. packetهای match شده
را از stack شبکه host می‌گیرد و وارد زنجیره packet می‌کند، و payloadهایی را که
از زنجیره می‌رسند به عنوان raw IP packet از raw output device می‌نویسد.

## جایگاه رایج

```text
RawSocket -> PacketReceiver
PacketSender -> RawSocket
TunDevice -> IpManipulator -> RawSocket
```

همراه با نودهای packet disguise:

```text
TunDevice -> PingClient -> RawSocket
RawSocket -> PingServer -> TunDevice
```

اگر `RawSocket` آخر زنجیره باشد، packet capture شده به سمت previous و با
downstream payload فرستاده می‌شود. اگر آخر زنجیره نباشد، packet capture شده به
سمت next و با upstream payload فرستاده می‌شود.

payloadی که از upstream یا downstream به `RawSocket` برسد، از raw output device
نوشته می‌شود.

## نمونه تنظیم

```json
{
  "name": "raw-ip",
  "type": "RawSocket",
  "settings": {
    "capture-device-name": "capture-in",
    "raw-device-name": "raw-out",
    "capture-filter-mode": "source-ip",
    "capture-ips": [
      "192.0.2.10",
      "198.51.100.0/24"
    ],
    "mark": 10
  },
  "next": "next-node-name"
}
```

## تنظیمات ضروری

| گزینه | نوع | توضیح |
| --- | --- | --- |
| `capture-filter-mode` | string | parser مقدارهای `source-ip` و `dest-ip` را می‌شناسد، اما پیاده‌سازی فعلی فقط `source-ip` را قبول می‌کند. |
| `capture-ips` | array of strings | آرایه غیرخالی از IPv4 address یا IPv4 CIDR برای capture. |

هر عضو `capture-ips` می‌تواند یک IP تکی مثل `192.0.2.10` یا یک CIDR مثل
`198.51.100.0/24` باشد. IPv6 پذیرفته نمی‌شود.

## تنظیمات اختیاری

| گزینه | پیش‌فرض | توضیح |
| --- | --- | --- |
| `capture-device-name` | `unnamed-capture-device` | نامی که به capture backend داده می‌شود. |
| `raw-device-name` | `unnamed-raw-device` | نامی که به raw output backend داده می‌شود. |
| `mark` | `0` | firewall mark برای raw output device در backendهایی که پشتیبانی می‌کنند. |

aliasهای سازگاری:

| alias | معنی |
| --- | --- |
| `listen-ips` | alias برای `capture-ips`. |
| `capture-ip` | ورودی قدیمی تک‌رشته‌ای؛ برای تنظیم جدید از `capture-ips` استفاده کنید. |

## مسیر Capture

در زمان start، `RawSocket` یک capture device و یک raw output device می‌سازد و
هر دو را بالا می‌آورد.

وقتی capture backend یک packet دریافت کند:

1. فقط IPv4 بررسی و forward می‌شود.
2. packetهای غیر IPv4 recycle می‌شوند.
3. worker packet line همان worker از chain گرفته می‌شود.
4. packet به سمت adjacent انتخاب‌شده فرستاده می‌شود.

این نود برای هر packet یا flow یک line معمولی نمی‌سازد.

## مسیر Output

وقتی payload از هر جهت به `RawSocket` برسد:

1. payload به عنوان raw IP packet در نظر گرفته می‌شود.
2. اگر line مقدار `recalculate_checksum` داشته باشد و packet IPv4 باشد،
   checksumها قبل از نوشتن دوباره محاسبه می‌شوند.
3. packet از raw output device نوشته می‌شود.
4. اگر raw device پایین باشد یا write شکست بخورد، buffer recycle می‌شود.

## محدودیت‌ها و نکته‌ها

- receive path فعلی فقط IPv4 را forward می‌کند.
- `capture-filter-mode: "dest-ip"` در parser هست، اما tunnel creation را fail
  می‌کند و پیشنهاد می‌دهد برای capture خروجی از `TunDevice` استفاده کنید.
- `required_padding_left = 0` است؛ این نود header جدید prepend نمی‌کند.
- callbackهای `Init`، `Est`، `Pause`، `Resume` و `Finish` برای این نود no-op
  هستند.
- packet lineهای worker توسط chain ساخته و مدیریت می‌شوند؛ `RawSocket` آن‌ها
  را در runtime destroy نمی‌کند.
- روی Linux و backendهای raw/capture معمولاً به دسترسی مناسب مثل root نیاز
  دارید.

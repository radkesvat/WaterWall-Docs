# Disturber

`Disturber` یک tunnel تست است که رفتار شبکه بد را داخل یک chain WaterWall شبیه‌سازی می‌کند. بدون استفاده از ابزار شبکه خارجی می‌تواند close، payload loss، corruption، duplication، out-of-order، delay و dead-hang ایجاد کند.

از آن برای stress test tunnelهایی استفاده کنید که باید در مسیرهای ناپایدار دوام بیاورند؛ مثل mux، TCP-over-UDP، HTTP، TLS، packet transport، reconnect logic و tunnelهای سفارشی.

:::warning
`Disturber` عمداً traffic را خراب می‌کند. برای تست، debug و اعتبارسنجی مقاومت مناسب است، نه forwarding معمولی production.
:::

## جایگاه رایج

شکل ساده pass-through:

```text
TesterClient -> Disturber -> TesterServer
```

اطراف transport مورد تست:

```text
TesterClient -> TunnelUnderTest -> Disturber -> PeerUnderTest -> TesterServer
```

روی هر دو جهت یک tunnel جفت:

```text
TesterClient -> Disturber -> TunnelClient -> ... -> TunnelServer -> Disturber -> TesterServer
```

`Disturber` socket مخصوص خودش ندارد. به `next` نیاز دارد و معمولاً وسط یک chain stream یا packet قرار می‌گیرد.

## این نود چه می‌کند؟

- callbackهای lifecycle را به صورت جهتی forward می‌کند وقتی هیچ disturbance close-like فعال نشود.
- می‌تواند lineهای عادی را هنگام init فوراً ببندد.
- می‌تواند lineهای عادی را هنگام payload forwarding ببندد.
- می‌تواند payload را drop کند.
- می‌تواند payload را duplicate کند.
- می‌تواند byteهای payload را corrupt کند.
- می‌تواند یک payload را نگه دارد و بعداً آن را release کند تا reordering شبیه‌سازی شود.
- می‌تواند payload را به مدت random در بازه تنظیم‌شده delay کند.
- می‌تواند یک جهت را در حالت dead-hang قرار دهد که payload بی‌سروصدا discard شود.
- lifetime packet-line را با استفاده از dead-hang به جای destroy کردن worker packet line حفظ می‌کند.

همه فیلدهای chance پیش‌فرض `0` دارند، پس یک `Disturber` پیش‌فرض مثل یک transparent pass-through node رفتار می‌کند، به جز تنظیمات جهت پیش‌فرض.

## نمونه تنظیم

تنظیم کامل:

```json
{
  "name": "disturber",
  "type": "Disturber",
  "settings": {
    "disturb-upstream": true,
    "disturb-downstream": true,
    "chance_instant_close": 5,
    "chance_middle_close": 2,
    "chance_payload_corruption": 3,
    "chance_payload_loss": 10,
    "chance_payload_duplication": 2,
    "chance_payload_out_of_order": 4,
    "chance_payload_delay": 15,
    "chance_connection_deadhang": 1,
    "delay_min_ms": 50,
    "delay_max_ms": 300
  },
  "next": "next-node"
}
```

فقط packet loss:

```json
{
  "name": "loss",
  "type": "Disturber",
  "settings": {
    "disturb-upstream": true,
    "disturb-downstream": false,
    "chance_payload_loss": 100
  },
  "next": "receiver"
}
```

## فیلدهای لازم

فیلدهای top-level:

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `name` | string | نام دلخواه node. باید در config file یکتا باشد. |
| `type` | string | باید دقیقاً `"Disturber"` باشد. |
| `next` | string | برای عملکرد مفید لازم است. نود بعدی upstream forwarding را دریافت می‌کند. |

`settings` اختیاری است. اگر حذف شود، همه chanceها مقدار پیش‌فرض می‌گیرند.

## تنظیمات اختیاری

کنترل جهت‌ها:

| گزینه | نوع | پیش‌فرض | توضیح |
| --- | --- | --- | --- |
| `disturb-upstream` | boolean | `true` | فعال کردن disturbance روی upstream init و upstream payload. |
| `disturb-downstream` | boolean | `false` | فعال کردن disturbance روی downstream init و downstream payload. |

فیلدهای chance:

| گزینه | نوع | پیش‌فرض | توضیح |
| --- | --- | --- | --- |
| `chance_instant_close` | درصد integer | `0` | احتمال بستن مسیر هنگام رسیدن init برای جهت فعال. |
| `chance_middle_close` | درصد integer | `0` | احتمال بستن هنگام مدیریت payload جهت فعال. |
| `chance_payload_corruption` | درصد integer | `0` | احتمال mutate کردن byteهای payload قبل از forward. |
| `chance_payload_loss` | درصد integer | `0` | احتمال drop کردن payload فعلی. |
| `chance_payload_duplication` | درصد integer | `0` | احتمال ساخت یک کپی اضافه از payload. |
| `chance_payload_out_of_order` | درصد integer | `0` | احتمال نگه داشتن payload فعلی و release آن اطراف payload بعدی. |
| `chance_payload_delay` | درصد integer | `0` | احتمال delay دادن payload فعلی. |
| `chance_connection_deadhang` | درصد integer | `0` | احتمال قرار دادن جهت در dead-hang mode. |

فیلدهای delay:

| گزینه | نوع | پیش‌فرض | توضیح |
| --- | --- | --- | --- |
| `delay_min_ms` | integer | `0` | حداقل delay وقتی payload delay فعال می‌شود. مقادیر منفی به `0` clamp می‌شوند. |
| `delay_max_ms` | integer | `0` | حداکثر delay وقتی payload delay فعال می‌شود. مقادیر کمتر از `delay_min_ms` به آن clamp می‌شوند. |

مقادیر probability با `roll100` تفسیر می‌شوند: مقادیر `<= 0` هیچ‌وقت trigger نمی‌شوند، مقادیر `>= 100` همیشه trigger می‌شوند و مقادیر `1` تا `99` به عنوان درصد chance عمل می‌کنند.

## رفتار جهت‌ها

به صورت پیش‌فرض فقط upstream disturb می‌شود:

```json
{
  "disturb-upstream": true,
  "disturb-downstream": false
}
```

`disturb-downstream` را `true` کنید وقتی می‌خواهید مسیر پاسخ هم خراب شود. `disturb-upstream` را `false` کنید وقتی فقط downstream باید disturb شود.

اگر یک جهت غیرفعال باشد، payload آن جهت مستقیم forward می‌شود:

| جهت | callback forwarding |
| --- | --- |
| upstream payload | `tunnelNextUpStreamPayload` |
| downstream payload | `tunnelPrevDownStreamPayload` |

`Est`، `Pause` و `Resume` در هر دو جهت به صورت عادی forward می‌شوند.

## پردازش Payload

برای هر payload در جهت فعال، `Disturber` این بررسی‌ها را به ترتیب ارزیابی می‌کند:

1. اگر جهت از قبل dead-hang شده باشد، payload drop می‌شود.
2. `chance_middle_close`
3. `chance_payload_loss`
4. `chance_payload_duplication`
5. `chance_payload_corruption`
6. release payload نگه‌داشته‌شده برای out-of-order
7. `chance_payload_out_of_order`
8. `chance_payload_delay`
9. `chance_connection_deadhang`
10. forwarding عادی

بعضی بررسی‌ها pipeline را همان‌جا متوقف می‌کنند. مثلاً payload loss، buffer را drop و return می‌کند. duplication می‌تواند با بررسی‌های بعدی ترکیب شود چون قبل از ادامه pipeline یک buffer اضافه می‌سازد.

## جزئیات Disturbance

### Instant Close

وقتی upstream init می‌رسد و `disturb-upstream` فعال است، `chance_instant_close` می‌تواند به جای forward کردن init به `next`، سمت قبلی را ببندد.

وقتی downstream init می‌رسد و `disturb-downstream` فعال است، `chance_instant_close` می‌تواند به جای forward کردن init به نود قبلی، سمت next را ببندد.

### Middle Close

وقتی `chance_middle_close` روی یک line عادی trigger می‌شود، payload فعلی drop می‌شود، local Disturber line state destroy می‌شود و هر دو جهت finish می‌شوند.

### Payload Loss

وقتی `chance_payload_loss` trigger می‌شود، buffer payload فعلی recycle می‌شود و forward نمی‌شود.

### Duplication

وقتی `chance_payload_duplication` trigger می‌شود، `Disturber` یک buffer duplicate می‌سازد. duplicate برای forward شدن در همان جهت schedule می‌شود. بررسی‌های بعدی هنوز می‌توانند روی payload اصلی تأثیر بگذارند.

### Corruption

وقتی `chance_payload_corruption` trigger می‌شود، byteهای random در payload فعلی با XOR تغییر می‌کنند. برای payloadهای غیرخالی، پیاده‌سازی تقریباً تا ۱۰ درصد payload را corrupt می‌کند و حداقل یک byte تغییر می‌کند.

### Out-of-Order Delivery

`Disturber` برای هر line برای هر جهت حداکثر یک payload نگه می‌دارد.

وقتی out-of-order trigger می‌شود و payload نگه‌داشته‌شده‌ای وجود ندارد، payload فعلی ذخیره و فوراً forward نمی‌شود. وقتی payload بعدی می‌رسد در حالی که یکی نگه داشته شده، payload نگه‌داشته‌شده اطراف payload فعلی release می‌شود تا یک reordering ساده ایجاد کند.

اگر line state destroy شود در حالی که payload هنوز نگه داشته شده، buffer نگه‌داشته‌شده recycle می‌شود.

### Delay

وقتی `chance_payload_delay` trigger می‌شود، یک delay به صورت random بین `delay_min_ms` و `delay_max_ms` انتخاب می‌شود. payload روی همان line برای forward شدن بعداً schedule می‌شود.

### Dead-Hang

وقتی `chance_connection_deadhang` trigger می‌شود، جهت به عنوان dead-hung علامت‌گذاری می‌شود. payload فعلی drop می‌شود، line از نظر ساختاری باقی می‌ماند و payload بعدی در آن جهت بی‌سروصدا discard می‌شود.

این حالت یک اتصال را شبیه‌سازی می‌کند که هنوز زنده به نظر می‌رسد اما پیشرفتی نمی‌کند.

## رفتار packet-line

`Disturber` نسبت به packet-line آگاه است.

برای lineهای اتصال عادی، disturbanceهای close-like می‌توانند `Finish` ارسال کنند و per-line state این tunnel را destroy کنند. برای worker packet lineها، Disturber در runtime packet line را destroy نمی‌کند. در عوض، رفتار instant-close و middle-close جهت تأثیردیده را dead-hung می‌کند و بدون صدا زدن `lineDestroy()` ادامه می‌دهد.

این کار قوانین lifetime packet-line WaterWall را حفظ می‌کند در حالی که سناریوهای packet loss و packet blackhole همچنان قابل تست هستند.

## نکته‌ها

- ترکیب چند مقدار chance بالا می‌تواند traffic خیلی chaotic ایجاد کند.
- `chance_payload_duplication = 100` برای تست protocolهای duplicate-tolerant مفید است، اما می‌تواند traffic را سریعاً چند برابر کند.
- رفتار delay و out-of-order از scheduled callbackها استفاده می‌کنند، پس می‌توانند باگ‌های re-entrancy و lifetime در tunnelهای اطراف را نشان دهند.
- این نود framing اضافه نمی‌کند و `required_padding_left = 0` دارد.
- API callback فعلاً فقط API message را می‌پذیرد و recycle می‌کند؛ runtime tuning ارائه نمی‌دهد.

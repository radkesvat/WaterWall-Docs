# فهرست همه‌ی node‌ها {#فهرست-همهی-nodeها}

این صفحه فهرست node‌های عمومی WaterWall است که در نسخهٔ فعلی کد می‌توانید در config استفاده کنید.
نام هر node به صفحهٔ مرجع آن پیوند دارد؛ تنظیمات دقیق، حالت‌های پشتیبانی‌شده، جایگاه در chain و مثال‌ها
در همان صفحه آمده‌اند. برای انتخاب بر اساس کاربرد، از [مقدمه](../00-intro.mdx#available-node-families)
یا [انتخاب node‌ها](../01-getting-started/tutorial-part4.mdx) شروع کنید. در build سفارشی ممکن است
بعضی از انواع node غیرفعال باشند.

## راهنمای کوتاه

- node‌های listener و device معمولاً در لبه‌ی chain قرار می‌گیرند و ترافیک را
  ایجاد یا دریافت می‌کنند.
- node‌های connector معمولاً در لبه‌ی خروجی chain هستند و به یک endpoint بیرونی
  متصل می‌شوند.
- node‌های packet با packet‌های خام IP یا buffer‌های datagram سروکار دارند؛ مدل آن‌ها
  با stream معمولی TCP فرق دارد.
- node‌های bridge مدل packet و stream را به هم وصل می‌کنند، یا دو شاخهٔ جداگانهٔ chain
  را به هم متصل می‌کنند.
- بیشتر جفت‌های پروتکلی `Client` / `Server` باید در دو سمت مخالف مسیر تنظیم شوند.

| [WireGuardDevice](./WireGuardDevice.mdx) | رمزنگاری WireGuard، ‏state مربوط به peer و مسیریابی allowed IP را داخل chain پیاده‌سازی می‌کند. | میان دقیقاً یک سمت packet لایه‌ی ۳ و یک سمت انتقال لایه‌ی ۴؛ `UdpStatelessSocket` می‌تواند سمت انتقال ابتدای chain باشد، اما `UdpListener` adapter سازگار این انتقال نیست. |

## انتخاب chain شروع {#انتخاب-زنجیرهی-شروع}

- proxy ساده‌ی TCP: ‏`TcpListener -> ... -> TcpConnector`
- proxy نوع stateful برای UDP: ‏`UdpListener -> ... -> UdpConnector`
- لبه‌ی packet و stateless برای UDP: ‏`UdpStatelessSocket -> ...`
- تونل کامل IP: ‏`TunDevice -> ... -> TunDevice`
- انتقال packet به سبک WireGuard: ‏`UdpStatelessSocket -> WireGuardDevice -> TunDevice`
- پل packet روی stream: ‏`PacketsToStream` در یک سمت و `StreamToPackets` در سمت دیگر
- پل rootless از اتصال به packet: ‏`TcpListener -> Socks5Server -> ConnectionToPackets -> ...` و در سمت راه‌دور، ‏`PacketsToConnection -> TcpUdpConnector`
- انتقال stream به‌صورت multiplex: ‏`MuxClient` در یک سمت و `MuxServer` در سمت دیگر
- تونل HTTP روی TLS: ‏`HttpClient -> TlsClient -> TcpConnector` و در سمت server، ‏`TlsServer -> HttpServer`
- جداسازی visitor/Protected به سبک Reality: ‏`RealityClient` رو به `RealityServer` و `RealityServer.settings.destination` رو به شاخه‌ی visitor

- VMess روی WebSocket/TLS: ‏`VmessClient -> HttpClient -> TlsClient -> TcpConnector` و در سمت server، ‏`TlsServer -> HttpServer -> VmessServer`
- QUIC روی UDP: ‏`TcpListener -> QuicClient -> UdpConnector` و در سمت server، ‏`UdpListener -> QuicServer -> TcpConnector`

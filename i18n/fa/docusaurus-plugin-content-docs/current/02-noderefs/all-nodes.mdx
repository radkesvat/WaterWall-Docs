# فهرست نودها

این صفحه یک نمای سریع از nodeهای قابل تنظیم WaterWall در سورس فعلی است. برای تنظیمات دقیق، lifecycle، محدودیت‌ها و مثال‌ها، صفحه اختصاصی همان node را بخوانید.

## نکته‌های پایه

- نودهای Listener و Device معمولاً لبه chain هستند و traffic را وارد یا خارج می‌کنند.
- نودهای Connector معمولاً انتهای outbound chain هستند و به مقصد بیرونی وصل می‌شوند.
- نودهای packet با IP packet خام یا packet buffer کار می‌کنند، نه stream معمولی TCP.
- نودهای bridge بین مدل packet و stream یا بین چند branch جدا پل می‌زنند.
- بیشتر pairهای `Client` / `Server` باید در دو سمت مسیر روبه‌روی هم قرار بگیرند.

## نودهای قابل تنظیم

| نود | کاربرد اصلی | جایگاه رایج |
|---|---|---|
| `AuthenticationClient` | اضافه کردن identity یا credential برای نودهای authentication-aware. | قبل از نود server/protocol مربوط به authentication. |
| `AuthenticationServer` | authenticate کردن identityهای ورودی و کنترل userهای مجاز. | سمت server قبل از traffic محافظت‌شده. |
| `Bgp4Client` | سمت client برای tunnel pair مربوط به BGP4-style. | همراه `Bgp4Server`. |
| `Bgp4Server` | سمت server برای tunnel pair مربوط به BGP4-style. | همراه `Bgp4Client`. |
| `BlackHole` | drop کردن payload یا terminate کردن traffic برای تست و policy. | وسط یا انتهای chain تست/policy. |
| `Bridge` | وصل کردن دو branch مستقل داخل یک config. | معمولاً برای اتصال branchها. |
| `ConnectionFisherClient` | تست/رقابت چند مسیر client-side و نگه داشتن مسیر مفید. | همراه `ConnectionFisherServer`. |
| `ConnectionFisherServer` | سمت server برای ConnectionFisher. | همراه `ConnectionFisherClient`. |
| `Disturber` | شبیه‌سازی loss، delay یا corruption. | chainهای تست. |
| `DomainResolver` | نود support پیشرفته برای resolve کردن domain موجود در `dest_ctx` قبل از forward کردن `Init`. | معمولاً توسط connector/router/client nodeها به صورت داخلی ساخته می‌شود. |
| `EncryptionClient` | AEAD framing/encryption سمت client. | همراه `EncryptionServer`. |
| `EncryptionServer` | AEAD framing/decryption سمت server. | همراه `EncryptionClient`. |
| `HalfDuplexClient` | مدیریت رفتار half-duplex upload/download. | همراه `HalfDuplexServer`. |
| `HalfDuplexServer` | سمت server برای half-duplex pair. | همراه `HalfDuplexClient`. |
| `HeaderClient` | prepend کردن header یک‌باره port مخصوص WaterWall یا header IPv4 PROXY protocol. | همراه `HeaderServer` برای headerهای WaterWall، mode خواندن source از PROXY در HeaderServer، یا قبل از backendی که PROXY protocol را می‌فهمد. |
| `HeaderServer` | مصرف header port مخصوص WaterWall، خواندن source fields از IPv4 PROXY protocol، یا اعمال destination port ثابت. | همراه `HeaderClient` یا پشت sender قابل اعتماد PROXY. |
| `HttpClient` | کپسوله کردن payload داخل HTTP، HTTP/2، h2c، custom upgrade، split HTTP یا WebSocket. | قبل از `TlsClient` برای HTTPS یا قبل از transport برای HTTP cleartext. |
| `HttpServer` | parse کردن HTTP/WebSocket سمت server و forward کردن body payload. | بعد از `TlsServer` برای HTTPS یا بعد از listener برای HTTP cleartext. |
| `IpManipulator` | اعمال trickهای packet-level برای TCP/TLS/SNI. | chainهای packet. |
| `IpOverrider` | بازنویسی source/destination IP یا port در packet. | chainهای packet. |
| `JunkDatagramSender` | ارسال datagramهای اضافه طبق module/policy. | مسیرهای packet یا UDP-oriented برای تست/عبور. |
| `KeepAliveClient` | ارسال heartbeat برای تشخیص قطع مسیر. | همراه `KeepAliveServer`. |
| `KeepAliveServer` | سمت server برای heartbeat. | همراه `KeepAliveClient`. |
| `LoggerTunnel` | ثبت یا dump کردن payload بدون تغییر رفتار chain. | هر جای مناسب برای debug. |
| `MuxClient` | multiplex کردن چند line منطقی روی transport مشترک. | همراه `MuxServer`. |
| `MuxServer` | demultiplex کردن lineهای منطقی از `MuxClient`. | همراه `MuxClient`. |
| `ObfuscatorClient` | obfuscation سبک payload سمت client. | همراه `ObfuscatorServer`. |
| `ObfuscatorServer` | counterpart سمت server برای obfuscation. | همراه `ObfuscatorClient`. |
| `PacketReceiver` | دریافت packet برای پیدا کردن source IPهای مناسب در محیط‌های restricted. | chainهای packet/IP discovery. |
| `PacketSender` | ارسال packet برای discovery یا تست مسیر packet. | chainهای packet/IP discovery. |
| `PacketSplitStream` | تفکیک رفتار packet/stream بین دو سمت. | مرز packet/stream. |
| `PacketsToConnection` | تبدیل packet traffic از طریق lwIP به lineهای connection معمولی WaterWall. | پل packet به stream. |
| `PacketsToStream` | حمل packetهای IPv4 خام روی stream-facing line. | همراه `StreamToPackets`. |
| `PingClient` | encapsulate کردن packet payload داخل IPv4 ICMP-style traffic. | chainهای packet همراه `PingServer`. |
| `PingServer` | decapsulate کردن payload سمت مقابل Ping tunnel. | chainهای packet همراه `PingClient`. |
| `RawSocket` | ارسال و دریافت IP packet خام. | لبه packet. |
| `RealityClient` | TLS handshake visitor و سپس Reality payload داخل recordهای شبیه TLS. | سمت client قبل از transport به `RealityServer`. |
| `RealityServer` | ارسال visitor traffic به destination و انتقال client معتبر Reality به `next` محافظت‌شده. | سمت server بعد از listener. |
| `ReverseClient` | ساخت سمت client برای reverse tunnel و عبور از NAT/firewall. | همراه `ReverseServer`. |
| `ReverseServer` | سمت server برای reverse tunnel. | همراه `ReverseClient`. |
| `Router` | route کردن lineها بر اساس context، filter یا branch rules. | وسط chainهای پیچیده. |
| `SniffRouter` | route کردن بر اساس metadata sniff شده. | وسط chainهای sniff/routing. |
| `Socks5Client` | صحبت با SOCKS5 server بالادستی. | قبل از proxy/transport مقصد. |
| `Socks5Server` | پذیرش requestهای SOCKS5 و forward کردن traffic قبول‌شده. | بعد از listener یا wrapperهای TLS/protocol. |
| `SpeedLimit` | محدود کردن throughput. | وسط chain. |
| `SpeedTestClient` | تولید traffic برای speed test. | chainهای تست همراه `SpeedTestServer`. |
| `SpeedTestServer` | پاسخ به traffic مربوط به speed test. | chainهای تست همراه `SpeedTestClient`. |
| `StreamToPackets` | بازسازی IPv4 packet از stream-facing line. | همراه `PacketsToStream`. |
| `TcpConnector` | باز کردن TCP connection خروجی. | انتهای chain. |
| `TcpListener` | پذیرش TCP connection ورودی و ساخت line معمولی. | ابتدای chain. |
| `TcpOverUdpClient` | حمل stream-like TCP data روی UDP-style packet transport. | همراه `TcpOverUdpServer`. |
| `TcpOverUdpServer` | سمت server برای TCP-over-UDP. | همراه `TcpOverUdpClient`. |
| `TcpUdpConnector` | ترکیب رفتار TCP و UDP connector داخل یک node. | انتهای chain برای routing ترکیبی TCP/UDP. |
| `TcpUdpListener` | ترکیب رفتار TCP و UDP listener داخل یک node. | ابتدای chain برای ورودی ترکیبی TCP/UDP. |
| `TesterClient` | تولید traffic deterministic و verify کردن responseها. | chain head تست. |
| `TesterServer` | پاسخ به traffic مربوط به tester. | chain end تست. |
| `TlsClient` | TLS واقعی سمت client. | قبل از `TcpConnector` یا transport دیگر. |
| `TlsServer` | TLS واقعی سمت server. | بعد از `TcpListener` و قبل از نودهای cleartext. |
| `TrojanClient` | نوشتن Trojan request/auth framing سمت client. | همراه `TrojanServer`، معمولاً داخل TLS. |
| `TrojanServer` | parse و authenticate کردن Trojan traffic. | همراه `TrojanClient`، معمولاً داخل TLS. |
| `TunDevice` | خواندن/نوشتن packet از طریق TUN سیستم‌عامل. | لبه packet. |
| `UdpConnector` | ارسال UDP خروجی با destination selection/resolution اختیاری. | انتهای chain. |
| `UdpListener` | پذیرش UDP peerها و ساخت stateful line برای هر peer. | ابتدای chain. |
| `UdpOverTcpClient` | حمل UDP-style packet روی stream transport. | همراه `UdpOverTcpServer`. |
| `UdpOverTcpServer` | سمت server برای UDP-over-TCP. | همراه `UdpOverTcpClient`. |
| `UdpStatelessSocket` | ارسال/دریافت UDP datagram با routing context به جای per-peer line. | لبه UDP packet، معمولاً کنار `WireGuardDevice`. |
| `UserController` | نود support پیشرفته برای enforce کردن limitهای userهای authenticated از طریق `AuthenticationClient`. | معمولاً توسط server nodeهای authenticated به صورت داخلی ساخته می‌شود. |
| `VlessClient` | نوشتن plain VLESS v0 client request framing. | همراه `VlessServer`، معمولاً داخل TLS/Reality transport. |
| `VlessServer` | parse و authenticate کردن plain VLESS v0 traffic. | همراه `VlessClient`. |
| `WireGuardDevice` | پیاده‌سازی WireGuard داخل chain با crypto، peer state و allowed-IP routing. | بین سمت packet و `UdpStatelessSocket`. |

| نود | نقش |
|---|---|
| `Template` | scaffold توسعه‌دهنده برای ساخت tunnel جدید. |

## شروع سریع برای انتخاب chain

- TCP ساده: `TcpListener -> ... -> TcpConnector`
- UDP stateful: `UdpListener -> ... -> UdpConnector`
- UDP stateless: `UdpStatelessSocket -> ...`
- تونل IP کامل: `TunDevice -> ... -> TunDevice`
- WireGuard-style packet transport: `TunDevice -> WireGuardDevice -> UdpStatelessSocket`
- packet روی stream: `PacketsToStream` در یک سمت و `StreamToPackets` در سمت دیگر
- transport چنداتصالی: `MuxClient` در یک سمت و `MuxServer` در سمت دیگر
- مسیر شبیه HTTPS: `HttpClient -> TlsClient -> TcpConnector` و سمت server با `TlsServer -> HttpServer`
- Reality visitor/protected split: `RealityClient` به سمت `RealityServer`، و `RealityServer.settings.destination` برای visitor branch

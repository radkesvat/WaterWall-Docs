# BlackHole

## نمای کلی {#overview}

`BlackHole` یک adapter نهایی برای دور ریختن داده است. در انتهای زنجیره قرار می‌گیرد، ترافیک upstream را از گره قبلی می‌گیرد و بدون ساخت socket، اتصال به peer راه دور یا ارسال به گره‌ای دیگر، آن را دور می‌ریزد.

دو رفتار پشتیبانی می‌شود:

- حالت `passive` line را می‌پذیرد، `Est` را در جهت downstream به سمت قبلی گزارش می‌دهد و payloadِ upstream را بی‌سروصدا دور می‌ریزد.
- حالت `active` به‌محض دریافت `Init` در جهت upstream، یک `Finish` در جهت downstream به سمت قبلی می‌فرستد.

از آنجا که `BlackHole` یک adapter است، callback‌های downstream در رابط runtime آن معتبر نیستند. پس از آن گره دیگری قرار ندهید.

## جایگاه معمول در زنجیره {#typical-placement}

<a id="جایگاه-رایج"></a>

نقطه نهایی دور ریختن داده در حالت passive:

```text
TcpListener -> BlackHole
```

تست زنجیره UDP:

```text
UdpListener -> BlackHole
```

در زنجیره‌های سیاست یا تست می‌توان از `BlackHole` استفاده کرد؛ زمانی که ترافیک پذیرفته‌شده باید در انتهای زنجیره مصرف یا دور ریخته شود.

`BlackHole` تونل میانی نیست. برای ساختاری مانند `TcpListener -> BlackHole -> TcpConnector` باید از تونل دیگری برای سیاست یا مسیریابی استفاده کنید.

## نمونهٔ کاربردی ساده {#minimal-practical-example}

این نمونه‌ها بخش‌هایی از پیکربندی گره هستند. یک listener یا گره upstream دیگر اضافه کنید که این مقصد را در `next` خود نام ببرد؛ برای `BlackHole` مقدار `next` تنظیم نکنید.

### نمونهٔ پیکربندی {#configuration-example}

<a id="نمونه-تنظیم"></a>

حالت passive:

```json
{
  "name": "dropper",
  "type": "BlackHole",
  "settings": {
    "mode": "passive"
  }
}
```

حالت active:

```json
{
  "name": "rejector",
  "type": "BlackHole",
  "settings": {
    "mode": "active"
  }
}
```

## پیکربندی {#configuration}

### فیلدهای لازم {#required-fields}

<a id="فیلدهای-لازم"></a>

فیلدهای سطح اصلی:

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `name` | string | نام دلخواه گره که باید در فایل پیکربندی یکتا باشد. |
| `type` | string | باید دقیقاً `"BlackHole"` باشد. |
| `settings` | object | باید `mode` داشته باشد. |

فیلدهای اجباری `settings`:

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `mode` | string | انتخاب میان دور ریختن بی‌سروصدای payload و بستن فوری اتصال. |

`mode` اجباری است. پیاده‌سازی فعلی مقدار پیش‌فرض ندارد.

### فیلدهای اختیاری {#optional-fields}

<a id="فیلدهای-اختیاری"></a>

فیلد اختیاری در `settings` وجود ندارد.

فیلد `next` را در سطح گره تنظیم نکنید. `BlackHole` adapter انتهای زنجیره است.

### مرجع حالت‌ها {#mode-reference}

<a id="مرجع-حالتها"></a>

#### حالت passive {#passive-mode}

<a id="حالت-passive"></a>

مقادیر قابل قبول:

| مقدار | معنی |
| --- | --- |
| `passive` | نام اصلی حالت passive. |
| `drop` | نام مستعار حالت passive. |
| `packet-drop` | نام مستعار حالت passive؛ گره همچنان داده را مصرف و دور می‌ریزد و به تونل بسته‌ای تبدیل نمی‌شود. |
| `silent` | نام مستعار حالت passive. |
| `calm` | نام مستعار حالت passive. |

در حالت passive:

- با دریافت `Init` در upstream، یک `Est` در downstream به سمت قبلی فرستاده می‌شود.
- payloadِ upstream دور ریخته می‌شود و buffer آن برای استفاده مجدد برمی‌گردد.
- `Est`، `Finish`، `Pause` و `Resume` در upstream کاری انجام نمی‌دهند.
- callback‌های downstream در لبه adapter غیرفعال‌اند.

حالت passive خودش line را نمی‌بندد؛ فقط payload را مصرف می‌کند و منتظر می‌ماند تا سمت قبلی line را ببندد.

#### حالت active {#active-mode}

<a id="حالت-active"></a>

مقادیر قابل قبول:

| مقدار | معنی |
| --- | --- |
| `active` | نام اصلی حالت active. |
| `close` | نام مستعار حالت active. |
| `aggressive` | نام مستعار حالت active. |
| `kill` | نام مستعار حالت active. |
| `kill-connection` | نام مستعار حالت active. |

در حالت active:

- با دریافت `Init` در upstream، یک `Finish` در downstream به سمت قبلی فرستاده می‌شود و callback بلافاصله برمی‌گردد.
- اگر payloadِ upstream به گره برسد، همچنان دور ریخته می‌شود و buffer آن برای استفاده مجدد برمی‌گردد.
- callback‌های downstream در لبه adapter غیرفعال‌اند.

این حالت اتصال را در انتهای زنجیره بی‌درنگ رد می‌کند.

## کاربرد و رفع اشکال {#usage-and-troubleshooting}

### رد کردن یک مقصد انتخاب‌شده در proxy {#reject-a-selected-proxy-destination}

<a id="رد-کردن-یک-مقصد-انتخابشده-در-proxy"></a>

برای رد اتصال بر اساس سیاست بدون باز کردن socket خروجی، `BlackHole` را یکی از
شاخه‌های Router قرار دهید:

```text
TcpListener -> Socks5Server -> Router
                                 |-- blocked destination -> BlackHole(active)
                                 `-- default -> TcpConnector
```
حالت شاخه مسدودشده را `mode: "active"` قرار دهید و آدرس و پورت connector مستقیم
را از context مقصد درخواست بخوانید.
[پیکربندی کامل Router](./Router.mdx#complete-example) تمام گره‌ها و rule رد کردن
بر اساس پورت را نشان می‌دهد. حالت `passive` line را باز نگه می‌دارد و داده را
مصرف می‌کند؛ برای آزمایش sink مناسب است ولی پاسخ عادی برنامه را تولید نمی‌کند.

### نکته‌ها و محدودیت‌ها {#notes-and-caveats}

<a id="نکتهها"></a>

- در فراداده، گره `BlackHole` به لایه خاصی محدود نیست؛ با این حال stream و packet را به یکدیگر تبدیل نمی‌کند.
- برای زنجیره‌هایی که به پاسخ برنامه نیاز دارند مناسب نیست، زیرا هیچ payload‌ی از آن عبور نمی‌کند.
- حالت passive تا وقتی سمت قبلی line را باز نگه دارد، می‌تواند آن را برای مدت نامحدود باز بگذارد.
- حالت active برای endpointای مناسب است که باید اتصال را عمداً رد یا قطع کند.
- این گره تنظیمی برای پروتکل، مشخصات ورود، آدرس راه دور، پورت یا فریم‌بندی ندارد.

## جزئیات پیاده‌سازی {#implementation-details}

### کارکرد گره {#what-it-does}

<a id="این-نود-چه-میکند"></a>

- می‌تواند آخرین گره در زنجیره باشد.
- پیکربندی دارای `next` را نمی‌پذیرد.
- هر payloadِ upstream را که دریافت کند دور می‌ریزد.
- buffer payload دورریخته‌شده را با `lineReuseBuffer()` برای استفاده مجدد برمی‌گرداند.
- payload را prepend، فریم‌بندی، رمزنگاری، decode یا بازنویسی نمی‌کند.
- برای هر line، state جداگانه‌ای به تونل اختصاص نمی‌دهد.
- به left padding اضافه نیاز ندارد.
- packet line نمی‌سازد و آزاد نمی‌کند.

### پردازش payload {#payload-handling}

<a id="پردازش-payload"></a>

برای هر payloadِ upstream، تابع `lineReuseBuffer()` روی buffer ورودی فراخوانی می‌شود و سپس callback برمی‌گردد.

هیچ بایتی از payload از گره عبور نمی‌کند. چون header‌ای prepend و فریمی ساخته نمی‌شود، مقدار `required_padding_left` در `BlackHole` برابر `0` است.

### رفتار چرخهٔ حیات {#lifecycle-behavior}

<a id="رفتار-lifecycle"></a>

`BlackHole` از قواعد جهت‌دهی adapter انتهای downstream پیروی می‌کند:

| جهت callback | رفتار |
| --- | --- |
| upstream `Init` در حالت passive | `tunnelPrevDownStreamEst()` می‌فرستد. |
| upstream `Init` در حالت active | `tunnelPrevDownStreamFinish()` می‌فرستد. |
| upstream payload | buffer را با `lineReuseBuffer()` برای استفاده مجدد برمی‌گرداند. |
| upstream `Est` / `Finish` / `Pause` / `Resume` | بدون عمل. |
| callback‌های downstream | در این لبه adapter نامعتبرند و `adapterCreate()` آن‌ها را مسدود می‌کند. |

چون گره بعدی وجود ندارد، هیچ‌گاه `tunnelNextUpStream*()` را فراخوانی نمی‌کند.

### پشتیبانی splice {#splice-support}

<a id="پشتیبانی-splice"></a>

مصرف‌کنندهٔ upstream buffer ورودی را بازیافت و باقی‌ماندهٔ بدنهٔ pipe خصوصی را تخلیه می‌کند. pipe سالم و خالی ممکن است برای استفادهٔ مجدد در cache بماند. حالت passive داده را مصرف می‌کند؛ حالت active در Init، line را می‌بندد و پس از بسته‌شدن line عادی، payload دیگری نمی‌پذیرد. handler برای payload در downstream وجود ندارد.

buffer‌های عادیِ fallback همچنان پذیرفته می‌شوند. splice به build پشتیبانی‌شدهٔ Linux، فعال‌بودن `misc.splice`، نبود گره بسته‌ای و پشتیبانی همهٔ گره‌های زنجیرهٔ نهایی پس از گسترش و ادغام نیاز دارد. flag قابلیت این بررسی‌ها را دور نمی‌زند. بدون اندازه‌گیری، بهبود کارایی تضمین نمی‌شود.

پیکربندی بسته‌ای این گره دولایه همچنان splice را فعال نمی‌کند.

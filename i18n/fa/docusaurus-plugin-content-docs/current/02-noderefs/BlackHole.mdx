# BlackHole

`BlackHole` یک adapter sink انتهایی است. در انتهای یک chain قرار می‌گیرد، traffic upstream را از نود قبلی می‌گیرد و آن را بدون ایجاد socket، اتصال به peer remote یا forwarding به نود دیگری drop می‌کند.

دو رفتار پشتیبانی می‌شود:

- حالت `passive` line را قبول می‌کند، downstream `Est` را به سمت قبلی گزارش می‌دهد و payload upstream را بی‌سروصدا drop می‌کند
- حالت `active` در زمان upstream `Init` بلافاصله downstream `Finish` را به سمت قبلی می‌فرستد

چون `BlackHole` یک adapter است، callbackهای downstream بخشی از runtime surface معتبر آن نیستند. نود دیگری بعد از آن قرار ندهید.

## این نود چه می‌کند؟

- می‌تواند آخرین نود در chain باشد.
- config با `next` را رد می‌کند.
- هر payload upstream که دریافت کند را drop می‌کند.
- bufferهای payload drop‌شده را با `lineReuseBuffer()` recycle می‌کند.
- payload را prepend، frame، encrypt، decode یا rewrite نمی‌کند.
- per-line tunnel state اختصاص نمی‌دهد.
- به left padding اضافه نیاز ندارد.
- packet line ایجاد یا destroy نمی‌کند.

## جایگاه رایج

نقطه drop passive انتهایی:

```text
TcpListener -> BlackHole
```

تست chain UDP:

```text
UdpListener -> BlackHole
```

chainهای policy یا test می‌توانند از `BlackHole` استفاده کنند وقتی traffic قبول‌شده باید در انتهای chain مصرف یا رد شود.

`BlackHole` یک tunnel میانی نیست. برای chain‌هایی مثل `TcpListener -> BlackHole -> TcpConnector`، از tunnel policy یا routing دیگری استفاده کنید.

## نمونه تنظیم

حالت passive:

```json
{
  "name": "dropper",
  "type": "BlackHole",
  "settings": {
    "mode": "passive"
  }
}
```

حالت active:

```json
{
  "name": "rejector",
  "type": "BlackHole",
  "settings": {
    "mode": "active"
  }
}
```

## فیلدهای لازم

فیلدهای top-level:

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `name` | string | نام دلخواه node. باید در config file یکتا باشد. |
| `type` | string | باید دقیقاً `"BlackHole"` باشد. |
| `settings` | object | باید `mode` داشته باشد. |

فیلدهای اجباری `settings`:

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `mode` | string | انتخاب بین drop passive payload یا بستن فوری اتصال. |

`mode` اجباری است. پیاده‌سازی فعلی مقدار پیش‌فرض ندارد.

## فیلدهای اختیاری

فیلد اختیاری در `settings` وجود ندارد.

فیلد `next` در سطح node تنظیم نکنید. `BlackHole` یک chain-end adapter است.

## مرجع حالت‌ها

### حالت Passive

مقادیر قابل قبول:

| مقدار | معنی |
| --- | --- |
| `passive` | نام canonical حالت passive. |
| `drop` | alias حالت passive. |
| `packet-drop` | alias حالت passive. نود را به packet tunnel تبدیل نمی‌کند. |
| `silent` | alias حالت passive. |
| `calm` | alias حالت passive. |

در حالت passive:

- upstream `Init` یک downstream `Est` به سمت قبلی می‌فرستد
- upstream payload drop و recycle می‌شود
- upstream `Est`، `Finish`، `Pause` و `Resume` بدون عمل هستند
- callbackهای downstream توسط adapter edge غیرفعال شده‌اند

حالت passive به تنهایی line را نمی‌بندد. payload را مصرف می‌کند تا سمت قبلی line را ببندد.

### حالت Active

مقادیر قابل قبول:

| مقدار | معنی |
| --- | --- |
| `active` | نام canonical حالت active. |
| `close` | alias حالت active. |
| `aggressive` | alias حالت active. |
| `kill` | alias حالت active. |
| `kill-connection` | alias حالت active. |

در حالت active:

- upstream `Init` یک downstream `Finish` به سمت قبلی می‌فرستد و بلافاصله برمی‌گردد
- upstream payload اگر به نود برسد همچنان drop و recycle می‌شود
- callbackهای downstream توسط adapter edge غیرفعال شده‌اند

این حالت مثل reject فوری اتصال در انتهای chain عمل می‌کند.

## پردازش Payload

upstream payload روی buffer دریافتی `lineReuseBuffer()` اجرا و برمی‌گردد.

هیچ byte از payload از نود عبور نمی‌کند. چون هیچ header prepend نمی‌شود و frame اختصاص نمی‌یابد، `BlackHole` مقدار `required_padding_left = 0` دارد.

## رفتار Lifecycle

`BlackHole` از قوانین جهت adapter downstream-end پیروی می‌کند:

| جهت callback | رفتار |
| --- | --- |
| upstream `Init` در حالت passive | `tunnelPrevDownStreamEst()` می‌فرستد. |
| upstream `Init` در حالت active | `tunnelPrevDownStreamFinish()` می‌فرستد. |
| upstream payload | buffer را با `lineReuseBuffer()` recycle می‌کند. |
| upstream `Est` / `Finish` / `Pause` / `Resume` | بدون عمل. |
| callbackهای downstream | برای این adapter edge نامعتبر هستند و توسط `adapterCreate()` block می‌شوند. |

هیچ‌وقت `tunnelNextUpStream*()` صدا نمی‌زند چون نود بعدی وجود ندارد.

## نکته‌ها

- `BlackHole` از نظر metadata نود layer-agnostic است، اما بین stream و packet تبدیل انجام نمی‌دهد.
- برای chainهایی که نیاز به پاسخ application دارند مناسب نیست، چون payload هیچ‌وقت از آن عبور نمی‌کند.
- حالت passive می‌تواند سمت قبلی را برای مدت نامعینی باز بگذارد اگر آن سمت line را باز نگه دارد.
- حالت active بهترین استفاده به عنوان endpoint reject یا kill عمدی است.
- این نود تنظیمات protocol، credential، آدرس remote، port یا framing ندارد.

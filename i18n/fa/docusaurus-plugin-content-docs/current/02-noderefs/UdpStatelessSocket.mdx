# UdpStatelessSocket

`UdpStatelessSocket` یک UDP edge adapter دوطرفه است. این نود یک UDP socket bind می‌کند، datagram را از peerهای مختلف دریافت می‌کند، و برای flowهای ورودی peerها line معمولی واتروال می‌سازد.

کاربرد اصلی آن کنار nodeهایی مثل `WireGuardDevice` است؛ جایی که یک UDP socket باید هم به peerهای تنظیم‌شده ارسال کند و هم packetهایی را بپذیرد که peerها ابتدا به socket می‌فرستند. datagramهای ورودی بر اساس هویت endpoint peer/local گروه‌بندی می‌شوند، ولی lineهایی که متعلق به این نود نیستند همچنان برای ارسال خروجی از routing context استفاده می‌کنند.

## جایگاه رایج

```text
WireGuardDevice -> UdpStatelessSocket
UdpStatelessSocket -> WireGuardDevice
TunDevice -> WireGuardDevice -> UdpStatelessSocket
UdpStatelessSocket -> WireGuardDevice -> TunDevice
```

از این نود در edge سمت UDP یک packet chain استفاده کنید وقتی نود کناری به یک UDP socket مشترک برای send/receive نیاز دارد، و peerهای دریافتی باید lifetime جداگانه در lineهای واتروال داشته باشند. مثال اصلی `WireGuardDevice` است: قبل از ارسال datagramهای رمزنگاری‌شده، endpoint peer را در destination routing context می‌نویسد، در حالی که datagramهای دریافتی peer می‌توانند روی lineهای per-peer وارد chain شوند.

## نمونه تنظیم

```json
{
  "name": "wg-udp-socket",
  "type": "UdpStatelessSocket",
  "settings": {
    "listen-address": "0.0.0.0",
    "listen-port": 51820,
    "interface": "eth0",
    "fwmark": 10,
    "large-send-buffer": true,
    "large-recv-buffer": true,
    "source-ip": "192.0.2.10",
    "verbose": false
  }
}
```

## تنظیمات ضروری

| فیلد | نوع | توضیح |
|---|---|---|
| `listen-address` | string | آدرس IP محلی برای bind. باید IP معتبر باشد. |
| `listen-port` | integer | پورت UDP محلی. بازه معتبر `0` تا `65535` است. |

آبجکت `settings` باید وجود داشته باشد و خالی نباشد.

## تنظیمات اختیاری

| فیلد | پیش‌فرض | توضیح |
|---|---|---|
| `interface` | ندارد | socket را به یک network device محلی محدود یا pin می‌کند، اگر پلتفرم پشتیبانی کند. |
| `fwmark` | ندارد | socket mark در پلتفرم‌هایی که `SO_MARK` دارند؛ عمدتا Linux. |
| `source-ip` | ندارد | آدرس bind موثر را override می‌کند و برای این نود جایگزین `listen-address` می‌شود. |
| `large-send-buffer` | `true` | اگر `true` باشد از buffer بزرگ پیش‌فرض واتروال استفاده می‌کند؛ اگر عدد مثبت باشد همان اندازه درخواست می‌شود. |
| `large-recv-buffer` | `true` | مثل send buffer، ولی برای receive. |
| `verbose` | `false` | log debug برای datagramهای دریافتی و ارسالی. |

اندازه buffer بزرگ پیش‌فرض فعلی `4194304` بایت است.

## رفتار interface و source-ip

`interface` قبل از bind اعمال می‌شود. روی Linux معمولا device binding انجام می‌شود. اگر پلتفرم bind by device نداشته باشد و `source-ip` تنظیم نشده باشد، واتروال سعی می‌کند socket را روی IPv4 address همان interface bind کند.

`source-ip` برای این نود override مستقیم `listen-address` است، چون همان socket هم دریافت می‌کند و هم ارسال.

اگر `TunDevice` loop protection یک egress pin خودکار منتشر کرده باشد، `source-ip` به تنهایی آن pin را override نمی‌کند. برای انتخاب interface متفاوت، `interface` را صریح تنظیم کنید.

## مسیر دریافت

وقتی UDP datagram برسد:

1. worker مالک socket datagram را دریافت می‌کند
2. `UdpStatelessSocket` از endpoint peer، endpoint محلی، و هویت tunnel یک flow key می‌سازد
3. اگر flow متناظر وجود نداشته باشد، یک line معمولی می‌سازد و `Init` را به سمت متصل chain می‌فرستد
4. آدرس و پورت فرستنده داخل `routing_context.src_ctx` نوشته می‌شود و local listener port هم ثبت می‌شود
5. body datagram روی line همان peer forward می‌شود

اگر این نود آخر chain باشد، datagramهای دریافتی از سمت next/tail شروع می‌شوند و downstream به سمت previous می‌روند. در غیر این صورت از سمت previous/head شروع می‌شوند و upstream به سمت next می‌روند.

lineهای idle peer برای init timeout برابر `30 seconds` و keepalive timeout برابر `300 seconds` استفاده می‌کنند.

## مسیر ارسال

وقتی payload از هر جهت به این نود برسد:

1. اگر line یک inbound peer line متعلق به همین tunnel باشد، datagram به endpoint ذخیره‌شده همان peer ارسال می‌شود
2. در غیر این صورت مقصد از `line->routing_context.dest_ctx` خوانده می‌شود
3. اگر مقصد domain resolve نشده باشد، async DNS شروع می‌شود
4. اگر مقصد IP و port آماده باشد، به socket address تبدیل می‌شود
5. datagram با همان UDP socket ارسال می‌شود

اگر destination context آماده نباشد یا port نداشته باشد، datagram drop می‌شود و warning/error log می‌شود.

برای domainهای resolve نشده، نتیجه DNS به مدت `30 minutes` بر اساس domain، port و domain strategy cache می‌شود. این موضوع مهم است چون routing context در packet lineها metadata موقت است و ممکن است با packet بعدی بازنویسی شود.

## Worker Ownership

UDP socket فقط متعلق به یک worker loop است. اگر payload برای ارسال از worker دیگری برسد، send روی worker مالک socket schedule می‌شود و `sendto()` همان‌جا انجام می‌شود.

## چرا UdpListener یا UdpConnector نه؟

در WireGuard و سناریوهای مشابه، یک socket باید هم به peer ارسال کند و هم از هر peer دریافت کند. `UdpListener` listener-oriented است و `UdpConnector` connector-oriented. `UdpStatelessSocket` مدل adapter تک-socket را نگه می‌دارد، برای datagramهای دریافتی lineهای per-peer اضافه می‌کند، و ارسال بر اساس routing context را برای lineهایی که متعلق به خودش نیستند حفظ می‌کند.

## Packet-Line Semantics

`UdpStatelessSocket` یک adapter اطراف UDP datagramهاست. datagramهای دریافتی به جای packet-line payload callback، lineهای معمولی peer می‌سازند.

Packet lineها هنوز برای ارسال‌های outbound بر اساس routing context پشتیبانی می‌شوند، و این tunnel در runtime packet lineها را نابود نمی‌کند.

## متادیتای نود

| ویژگی | مقدار |
|---|---|
| Runtime model | UDP edge adapter با inbound lineهای per-peer |
| Socket count | یک UDP socket bound به ازای هر node instance |
| Per-peer state | line معمولی به ازای هر inbound peer flow |
| Packet-line use | سازگاری outbound با routing context |
| Required left padding | `0` |
| DNS cache freshness | `30 minutes` |

## خطاهای رایج

- ارسال payload قبل از اینکه `dest_ctx` مقصد IP/domain و port داشته باشد.
- در نظر گرفتن lineهای peer دریافتی به عنوان packet line.
- استفاده از این نود مثل stream adapter عمومی.
- تکیه به `source-ip` برای override کردن loop-protection؛ در این حالت `interface` را صریح تنظیم کنید.
- فراموش کردن وابستگی `fwmark` و interface binding به پلتفرم.

# TrojanClient

`TrojanClient` تونل سمت client برای پروتکل Trojan در WaterWall است. این نود password hash استاندارد Trojan، command
درخواست، و destination header را می‌نویسد و سپس traffic برنامه را از طریق نود stream-facing بعدی forward می‌کند.

این نود از Trojan TCP `CONNECT` و Trojan UDP `UDP ASSOCIATE` پشتیبانی می‌کند. خودش TLS نمی‌سازد و خودش اتصال به سرور
remote را باز نمی‌کند.

## جایگاه رایج

Trojan client برای TCP:

```text
TcpListener -> TrojanClient -> TlsClient -> TcpConnector
```

Trojan client برای UDP:

```text
UdpListener -> TrojanClient -> TlsClient -> TcpConnector
```

destination داینامیک از proxy یا router:

```text
Socks5Server -> TrojanClient -> TlsClient -> TcpConnector
SniffRouter -> TrojanClient -> TlsClient -> TcpConnector
```

`TcpConnector` معمولا به address و port سرور Trojan وصل می‌شود. مقصد واقعی service داخل Trojan request یا داخل هر
Trojan UDP packet encode می‌شود.

## نمونه TCP

```json
[
  {
    "name": "trojan-client",
    "type": "TrojanClient",
    "settings": {
      "password": "secret-password",
      "address": "example.com",
      "port": 443,
      "protocol": "tcp",
      "domain-strategy": "do-not-resolve-domains",
      "verbose": false
    },
    "next": "tls-client"
  },
  {
    "name": "tls-client",
    "type": "TlsClient",
    "settings": {
      "sni": "trojan.example.net",
      "verify": true
    },
    "next": "server-out"
  },
  {
    "name": "server-out",
    "type": "TcpConnector",
    "settings": {
      "address": "trojan.example.net",
      "port": 443,
      "nodelay": true
    }
  }
]
```

این request به این شکل ارسال می‌شود:

```text
hex(SHA224("secret-password")) CRLF
command 01
destination example.com:443
CRLF
```

## نمونه Dynamic Destination

```json
{
  "name": "trojan-client",
  "type": "TrojanClient",
  "settings": {
    "sha224": "7e240de74fb1ed08fa08d38063f6a6a91462a815c15d3f6abf1d7e0b",
    "address": "dest_context->address",
    "port": "dest_context->port",
    "protocol": "dest_context->protocol"
  },
  "next": "tls-client"
}
```

وقتی نمی‌خواهید raw password داخل config باشد، از `sha224` استفاده کنید. مقدار آن باید digest هگز 56 کاراکتری SHA224
باشد.

## نمونه UDP

```json
{
  "name": "trojan-client-udp",
  "type": "TrojanClient",
  "settings": {
    "password": "secret-password",
    "address": "dest_context->address",
    "port": "dest_context->port",
    "protocol": "udp"
  },
  "next": "tls-client"
}
```

در حالت UDP، سمت قبلی همچنان UDP-facing می‌ماند. `TrojanClient` یک TCP carrier line داخلی می‌سازد، روی آن Trojan
`UDP ASSOCIATE` می‌فرستد، و هر UDP payload محلی را داخل framing مربوط به Trojan UDP قرار می‌دهد.

## فیلدهای اجباری

فیلدهای top-level:

| Field | Type | توضیح |
| --- | --- | --- |
| `name` | string | نام دلخواه node. باید داخل config یکتا باشد. |
| `type` | string | باید دقیقا `"TrojanClient"` باشد. |
| `settings` | object | تنظیمات Trojan client و نباید خالی باشد. |
| `next` | string | نود stream-facing که bytes پروتکل Trojan را حمل می‌کند. در استفاده عادی required است. |

فیلدهای اجباری داخل `settings`:

| Field | نام‌های قابل قبول | توضیح |
| --- | --- | --- |
| password material | `password`, `pass`, `sha224`, `password-sha224`, `password_sha224` | یا raw password بدهید یا SHA224 hex آماده؛ هر دو با هم مجاز نیستند. |
| target address | `target-address`, `address`, `target` | مقصد نهایی host/IP، یا `"dest_context->address"` / `"line->dest_ctx->address"`. |
| target port | `port` | پورت مقصد نهایی، یا `"dest_context->port"` / `"line->dest_ctx->port"`. پورت ثابت باید در بازه `1..65535` باشد. |

`password` و `pass` raw Trojan password هستند. `TrojanClient` مقدار `SHA224(password)` را حساب می‌کند و فرم lowercase hex
را می‌فرستد. aliasهای `sha224` باید دقیقا 56 کاراکتر hexadecimal باشند؛ حروف بزرگ به lowercase normalize می‌شوند.

## تنظیمات اختیاری

| Field | Default | توضیح |
| --- | --- | --- |
| `protocol` | `"tcp"` | Trojan command را انتخاب می‌کند. alias آن `proto` است. |
| `verbose` | `false` | لاگ‌های اضافی tunnel را فعال می‌کند. |
| `domain-strategy` | `"do-not-resolve-domains"` | مشخص می‌کند domain target قبل از نوشتن request به صورت local resolve شود یا نه. |

مقادیر قابل قبول `protocol`:

| Value | رفتار |
| --- | --- |
| `"tcp"` یا `"connect"` | Trojan command `0x01` برای TCP `CONNECT` ارسال می‌شود. |
| `"udp"` یا `"udp-associate"` | Trojan command `0x03` برای UDP `ASSOCIATE` ارسال می‌شود و UDP datagramها روی carrier داخلی TCP حمل می‌شوند. |
| `"dest_context->protocol"` یا `"line->dest_ctx->protocol"` | protocol از destination context ورودی خوانده می‌شود. TCP دقیق `0x01` و UDP دقیق `0x03` را انتخاب می‌کند. |

اگر `dest_context->protocol` انتخاب شود ولی protocol ورودی missing، ambiguous، یا غیر TCP/UDP باشد، client یک warning
لاگ می‌کند و به TCP fallback می‌کند.

## Domain Strategy

`domain-strategy` آدرس نهایی encode شده داخل Trojan request و UDP packet headerها را کنترل می‌کند.

| Value | رفتار |
| --- | --- |
| `"do-not-resolve-domains"` | domain target به همان شکل domain باقی می‌ماند. سمت Trojan server آن را resolve می‌کند. |
| `"resolve-domains-and-accept-dns-returned-order"` | local resolve انجام می‌شود و اولین جواب قابل استفاده DNS انتخاب می‌شود. |
| `"resolve-domains-and-prefer-ipv4"` | local resolve انجام می‌شود، IPv4 ترجیح داده می‌شود، و در صورت نیاز IPv6 استفاده می‌شود. |
| `"resolve-domains-and-prefer-ipv6"` | local resolve انجام می‌شود، IPv6 ترجیح داده می‌شود، و در صورت نیاز IPv4 استفاده می‌شود. |
| `"resolve-domains-and-use-only-ipv4"` | local resolve انجام می‌شود و IPv4 الزامی است. اگر IPv4 وجود نداشته باشد line بسته می‌شود. |
| `"resolve-domains-and-use-only-ipv6"` | local resolve انجام می‌شود و IPv6 الزامی است. اگر IPv6 وجود نداشته باشد line بسته می‌شود. |
| `"resolve-domains-with-core-settings"` | local resolve با تنظیمات `dns` داخل `core.json` انجام می‌شود. |

وقتی local resolution فعال باشد، `TrojanClient` یک `DomainResolver` داخلی می‌سازد که prepare hook آن قبل از DNS
resolution، target تنظیم‌شده را اعمال می‌کند. resolve وقتی انجام می‌شود که آدرس نهایی Trojan یک domain باشد؛ هم برای
target ثابت JSON و هم برای targetهای destination-context. آدرس‌های literal IP بدون تغییر می‌مانند.

## فرمت Request

درخواست اولیه Trojan:

```text
password:     56 ASCII hex bytes, hex(SHA224(password))
separator:    CRLF
command:      01 CONNECT or 03 UDP ASSOCIATE
destination:  ATYP + address + port
separator:    CRLF
```

فرمت destination:

```text
ATYP 01: IPv4 address, 4 bytes, then 2-byte big-endian port
ATYP 03: domain length, domain bytes, then 2-byte big-endian port
ATYP 04: IPv6 address, 16 bytes, then 2-byte big-endian port
```

در حالت UDP، request اولیه `UDP ASSOCIATE` از `0.0.0.0:0` به عنوان associate address استفاده می‌کند. مقصد واقعی remote
داخل هر Trojan UDP packet بعدی حمل می‌شود.

فرمت Trojan UDP packet:

```text
destination:  ATYP + address + port
length:       2 bytes big-endian
separator:    CRLF
payload:      length bytes
```

## رفتار Runtime در TCP

در upstream `Init`، آماده‌سازی target قبل از شروع protocol core انجام می‌شود؛ یا از طریق prepare hook داخلی resolver
یا مستقیما در init خود client وقتی local DNS resolution غیرفعال است. سپس `TrojanClient` همان line را به نود بعدی
forward می‌کند.

وقتی transport سمت downstream established شد، `TrojanClient`:

1. Trojan request header را upstream ارسال می‌کند
2. Trojan stream را established علامت می‌زند
3. downstream `Est` را به نود قبلی forward می‌کند
4. payloadهای upstream queue شده را flush می‌کند
5. bytes downstream که قبل از establish رسیده‌اند را forward می‌کند

Trojan response header موفقیت ندارد، بنابراین client منتظر چنین پاسخی نمی‌ماند.

## رفتار Runtime در UDP

در حالت UDP دو line وجود دارد:

| Line | کاربرد |
| --- | --- |
| UDP app line | line قابل مشاهده برای نود UDP-facing قبلی. |
| TCP carrier line | line داخلی که `TrojanClient` می‌سازد و به نود stream-facing بعدی می‌فرستد. |

بعد از established شدن carrier:

- carrier، Trojan password و request مربوط به `UDP ASSOCIATE` را ارسال می‌کند
- app line یک downstream `Est` دریافت می‌کند
- UDP payloadهای local queue شده wrap شده و از carrier عبور می‌کنند
- Trojan UDP frameهای downstream parse و strip می‌شوند و به شکل UDP payload خام به app line برمی‌گردند

payloadهای UDP محلی بزرگ‌تر از 8192 بایت drop می‌شوند، بدون اینکه کل association بسته شود. Trojan UDP frameهای inbound
بزرگ‌تر از 8192 بایت، headerهای خراب، CRLF نامعتبر، یا input buffering بیشتر از 1 MiB باعث بسته شدن line مربوطه می‌شوند.

client تا 1 MiB داده upstream application را هنگام انتظار برای establish شدن مسیر transport/request queue می‌کند.

## رفتار Finish

`TrojanClient` قبل از propagate کردن `Finish` واقعی، line state خودش را destroy می‌کند. برای lineهای external معمولی
`lineDestroy()` صدا نمی‌زند.

در حالت UDP، TCP carrier line داخلی که خودش ساخته را مالک است. اگر app line یا carrier line بسته شود، سمت paired را هم
می‌بندد و carrier line مالکیت‌دار را امن destroy می‌کند.

## Padding

`TrojanClient` ممکن است بزرگ‌ترین Trojan UDP packet header را prepend کند:

```text
required_padding_left = 263
```

این مقدار `ATYP + domain length + 255-byte domain + port + payload length + CRLF` را پوشش می‌دهد.

## Metadata نود

| Property | Value |
| --- | --- |
| Node flag | `kNodeFlagNone` |
| Previous node | مجاز، در استفاده عادی required |
| Next node | مجاز، در استفاده عادی required |

## قابلیت‌های پشتیبانی‌نشده

این implementation خودش این موارد را ایجاد یا مدیریت نمی‌کند:

- TLS
- WebSocket، HTTP، gRPC یا transport wrapperهای دیگر
- fallback سمت server
- extensionهای غیر استاندارد Trojan

وقتی به این layerها نیاز دارید، از نودهای جداگانه WaterWall مثل `TlsClient`، `HttpClient`، `MuxClient` یا
`TcpConnector` استفاده کنید.

## اشتباه‌های رایج

- انتظار نداشته باشید `TrojanClient` خودش به سرور Trojan وصل شود؛ بعد از آن `TlsClient` و connector بگذارید.
- برای deployment عمومی Trojan، `TlsClient` را حذف نکنید مگر اینکه عمدا Trojan plain روی wire بخواهید.
- آدرس سرور Trojan را با آدرس مقصد نهایی اشتباه نگیرید.
- حالت UDP را با نود بعدی غیر stream-facing استفاده نکنید.

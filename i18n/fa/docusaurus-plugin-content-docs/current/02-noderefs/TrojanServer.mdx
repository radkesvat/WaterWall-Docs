# TrojanServer

`TrojanServer` تونل سمت server برای پروتکل Trojan در WaterWall است. این نود stream پروتکل Trojan را از نود قبلی parse
می‌کند، password hash استاندارد SHA224 را authenticate می‌کند، destination درخواستی TCP یا UDP را استخراج می‌کند، و
traffic پذیرفته‌شده را به `next` تنظیم‌شده forward می‌کند.

این نود هم local password allowlist و هم کاربران مبتنی بر `AuthenticationClient` را پشتیبانی می‌کند. همچنین fallback
اختیاری برای probeهای invalid و unauthenticated دارد.

این نود جایگزین setup قدیمی دو نودی `TrojanAuthServer` و `TrojanSocksServer` شده است.

## جایگاه رایج

Trojan server عادی:

```text
TcpListener -> TlsServer -> TrojanServer -> TcpUdpConnector
```

خروجی فقط TCP:

```text
TcpListener -> TlsServer -> TrojanServer -> TcpConnector
```

routing بعد از authentication:

```text
TcpListener -> TlsServer -> TrojanServer -> Router
```

`TrojanServer` خودش TLS terminate نمی‌کند. برای deployment عمومی Trojan، قبل از آن `TlsServer` بگذارید. بدون TLS،
password hash و metadata مقصد روی wire دیده می‌شوند.

## نمونه Minimal با Local Password

```json
[
  {
    "name": "tls-in",
    "type": "TlsServer",
    "settings": {
      "cert-file": "/etc/waterwall/fullchain.pem",
      "key-file": "/etc/waterwall/privkey.pem"
    },
    "next": "trojan-server"
  },
  {
    "name": "trojan-server",
    "type": "TrojanServer",
    "settings": {
      "password": "secret-password",
      "connect": true,
      "udp": true,
      "verbose": false
    },
    "next": "outbound"
  },
  {
    "name": "outbound",
    "type": "TcpUdpConnector",
    "settings": {
      "address": "dest_context->address",
      "port": "dest_context->port"
    }
  }
]
```

## چند User محلی

```json
{
  "name": "trojan-server",
  "type": "TrojanServer",
  "settings": {
    "users": [
      "secret-password",
      {
        "username": "alice",
        "password": "another-secret"
      }
    ],
    "connect": true,
    "udp": true
  },
  "next": "outbound"
}
```

در local allowlist mode، `TrojanServer` raw password match شده را روی line ذخیره می‌کند تا `Router` بتواند ruleهای
password را match کند. اگر object match شده `username` داشته باشد، آن username هم برای routing مبتنی بر username روی
line ذخیره می‌شود.

## حالت AuthenticationClient

```json
{
  "name": "trojan-server",
  "type": "TrojanServer",
  "settings": {
    "auth-client-node-name": "auth-client",
    "connect": true,
    "udp": true,
    "verbose": false
  },
  "next": "outbound"
}
```

در این mode، `AuthenticationClient` تنظیم‌شده مرجع اصلی authentication است. Trojan password هر user را به صورت plaintext
در فیلد `password` همان user ذخیره کنید؛ `AuthenticationClient` داده lookup مربوط به SHA224 را internally آماده می‌کند.
فیلد `name` کاربر، account name است و خود Trojan password نیست.

وقتی `auth-client-node-name` تنظیم شده باشد، تنظیمات local password reject می‌شوند. `TrojanServer` به صورت داخلی یک
`UserController` قبل از نود outbound تنظیم‌شده قرار می‌دهد، پس نباید یک `UserController` دستی مستقیم بعد از آن بگذارید.

## نمونه Fallback

```json
{
  "name": "trojan-server",
  "type": "TrojanServer",
  "settings": {
    "password": "secret-password",
    "fallback-node-name": "fallback-service",
    "fallback-intentional-delay-ms": 7,
    "fallback-intentional-delay-jitter-ms": 1,
    "connect": true,
    "udp": true
  },
  "next": "outbound"
}
```

Fallback برای مقاومت در برابر active probing است. traffic نامعتبر و unauthenticated می‌تواند به جای close فوری، به یک
نود دیگر handoff شود.

## فیلدهای اجباری

فیلدهای top-level:

| Field | Type | توضیح |
| --- | --- | --- |
| `name` | string | نام دلخواه node. باید داخل config یکتا باشد. |
| `type` | string | باید دقیقا `"TrojanServer"` باشد. |
| `settings` | object | تنظیمات Trojan server و نباید خالی باشد. |
| `next` | string | required است. Trojan traffic پذیرفته‌شده به این نود forward می‌شود. |

دقیقا یکی از authentication modeها را انتخاب کنید.

## تنظیمات Local Authentication

برای local authentication، `auth-client-node-name` را حذف کنید و حداقل یک raw password تنظیم کنید.

| Field | Type | توضیح |
| --- | --- | --- |
| `password` | string | یک raw Trojan password. |
| `pass` | string | alias برای `password`. فقط یکی از `password` یا `pass` را استفاده کنید. |
| `passwords` | array of strings | چند raw Trojan password. |
| `users` | array | password stringها یا objectهایی با `password` یا `pass`. objectها می‌توانند `username` داشته باشند. |
| `clients` | array | alias برای `users`. فقط یکی از `users` یا `clients` را استفاده کنید. |

password stringها باید non-empty باشند. password تکراری خطای fatal configuration است، حتی اگر entryهای تکراری usernameهای
متفاوت داشته باشند.

## تنظیمات Database Authentication

| Field | Type | توضیح |
| --- | --- | --- |
| `auth-client-node-name` | string | نام یک نود موجود `AuthenticationClient` داخل همان config file. |

نود referenced باید وجود داشته باشد، باید `AuthenticationClient` باشد، و نباید به خود `TrojanServer` اشاره کند. در
database mode، `password`، `pass`، `passwords`، `users` یا `clients` را تنظیم نکنید.

## تنظیمات اختیاری

| Field | Default | توضیح |
| --- | --- | --- |
| `connect` | `true` | Trojan TCP `CONNECT` با command `0x01` را فعال می‌کند. |
| `udp` | `true` | Trojan UDP `ASSOCIATE` با command `0x03` را فعال می‌کند. |
| `verbose` | `false` | diagnostics متمرکز authentication را فعال می‌کند. |
| `fallback-node-name` | تنظیم نشده | fallback branch برای probeهای invalid و unauthenticated. aliasها: `fallback-node`, `fallback`. |
| `fallback-intentional-delay-ms` | `7` | delay برای upstream payloadهایی که به fallback فرستاده می‌شوند. مقدار `0` آن را غیرفعال می‌کند. نباید منفی باشد. |
| `fallback-intentional-delay-jitter-ms` | `1` | jitter تصادفی اطراف زمان‌بندی fallback payload. وقتی delay برابر `0` باشد ignore می‌شود. نباید منفی باشد. |
| `sweep-interval-ms` | `1000` | تنظیم اختیاری که در database mode به `UserController` داخلی forward می‌شود. |

حداقل یکی از `connect` یا `udp` باید فعال باشد.

## فرمت Request

درخواست قابل قبول Trojan:

```text
password:     56 ASCII hex bytes, hex(SHA224(password))
separator:    CRLF
command:      01 CONNECT or 03 UDP ASSOCIATE
destination:  ATYP + address + port
separator:    CRLF
body:         TCP stream bytes or Trojan UDP packets
```

فرمت destination:

```text
ATYP 01: IPv4 address, 4 bytes, then 2-byte big-endian port
ATYP 03: domain length, domain bytes, then 2-byte big-endian port
ATYP 04: IPv6 address, 16 bytes, then 2-byte big-endian port
```

فرمت Trojan UDP packet:

```text
destination:  ATYP + address + port
length:       2 bytes big-endian
separator:    CRLF
payload:      length bytes
```

## جریان Authentication

Trojan clientها مقدار `hex(SHA224(password))` را به شکل 56 بایت ASCII hex می‌فرستند. `TrojanServer` این مقدار را decode
می‌کند و بر اساس mode انتخاب‌شده authenticate می‌کند.

در local mode، server برای هر raw password تنظیم‌شده SHA224 را precompute می‌کند. در database mode، از API lookup مبتنی
بر SHA224 در `AuthenticationClient` استفاده می‌کند و بعد از parse شدن request، user handle برگشتی را روی line record
می‌کند.

hash کامل 56 بایتی password باید در اولین upstream payload callback وجود داشته باشد. اگر اولین payload شامل hash کامل
نباشد، line به عنوان probe نامعتبر و unauthenticated در نظر گرفته می‌شود. اگر fallback تنظیم شده باشد، bytes به fallback
می‌روند؛ در غیر این صورت line بسته می‌شود. فیلدهای بعدی request، شامل CRLF، command، destination و early body bytes،
بعد از موجود بودن password hash کامل می‌توانند در payload callbackهای بعدی برسند.

حالت Trojan بدون authentication وجود ندارد.

## رفتار Runtime برای TCP CONNECT

برای command `0x01`، server:

1. password hash را authenticate می‌کند
2. destination درخواستی را parse می‌کند
3. destination را داخل `line->routing_context.dest_ctx` می‌نویسد
4. credentialهای local یا database را برای routing downstream روی line record می‌کند
5. نود `next` تنظیم‌شده را initialize می‌کند
6. TCP body byteهایی که در همان payload همراه request header آمده‌اند را forward می‌کند
7. downstream `Est` را فقط بعد از established شدن مسیر outbound انتخاب‌شده forward می‌کند

نود `next` معمولا `TcpConnector`، `TcpUdpConnector`، `Router` یا نود دیگری است که destination context را می‌فهمد.

## رفتار Runtime برای UDP ASSOCIATE

برای command `0x03`، آدرس داخل request اولیه فقط metadata مربوط به association است. مقصد واقعی remote داخل هر Trojan UDP
packet حمل می‌شود.

برای هر destination یکتای UDP packet، `TrojanServer` یک backend UDP line داخلی ایجاد یا reuse می‌کند. آن backend line
destination packet را داخل `line->routing_context.dest_ctx` می‌گیرد، credentialهای authenticated user را حمل می‌کند، و
UDP payload خام را به `next` تنظیم‌شده forward می‌کند.

replyهای backend UDP lineها دوباره داخل Trojan UDP packet framing wrap می‌شوند و به stream اصلی Trojan client برمی‌گردند.
در نتیجه یک Trojan UDP association می‌تواند با چند endpoint مختلف UDP صحبت کند.

UDP packet header خراب، domain name با طول صفر، port missing، CRLF نامعتبر، یا UDP payload بزرگ‌تر از 8192 بایت باعث
بسته شدن Trojan line مربوطه می‌شود. pending downstream reply data تا 1 MiB محدود است.

## رفتار Fallback

Fallback فقط قبل از authentication موفق استفاده می‌شود. بعد از موفق شدن authentication، داده Trojan protocol خراب باعث
close شدن line می‌شود و به fallback replay نمی‌شود.

Fallback ممکن است در این حالت‌ها انتخاب شود:

- invalid password prefix bytes
- password hash که در اولین upstream payload split شده باشد
- password CRLF نامعتبر قبل از authentication
- password hex نامعتبر قبل از authentication
- lookup ناموفق password
- آماده نبودن `AuthenticationClient`
- prefix ناقص unauthenticated که از initial-buffer limit بزرگ‌تر شود

وقتی fallback انتخاب شود:

- fallback branch بلافاصله `Init` دریافت می‌کند
- bytes اولیه ذخیره‌شده و upstream payloadهای بعدی به fallback forward می‌شوند
- upstream fallback payloadها می‌توانند با `fallback-intentional-delay-ms` به علاوه jitter delay شوند
- upstream `Finish` تا تحویل payloadهای delayed fallback صبر می‌کند
- responseهای downstream fallback عمدا delay نمی‌شوند

default fallback delay عمدا کوچک است. delay و jitter را بر اساس رفتار public که fallback باید شبیه آن باشد تنظیم کنید؛
این‌ها mitigation هستند، نه اثبات indistinguishability زمانی.

## رفتار Finish

`TrojanServer` قبل از propagate کردن `Finish` واقعی، line state خودش را destroy می‌کند.

client stream line توسط adapter قبلی ساخته شده و `TrojanServer` آن را destroy نمی‌کند. backend UDP lineهای داخلی توسط
`TrojanServer` ساخته می‌شوند؛ این نود مالک آن lineهاست و هنگام بسته شدن client stream یا backend UDP line، آن‌ها را امن
destroy می‌کند.

## Padding

`TrojanServer` ممکن است بزرگ‌ترین Trojan UDP reply header را prepend کند:

```text
required_padding_left = 263
```

این مقدار `ATYP + domain length + 255-byte domain + port + payload length + CRLF` را پوشش می‌دهد.

## Metadata نود

| Property | Value |
| --- | --- |
| Node flag | `kNodeFlagChainHead` |
| Previous node | مجاز، در استفاده عادی required |
| Next node | required |
| Layer group | `kNodeLayerAnything` |
| `required_padding_left` | `263` |
| Line state | authentication state، phase، read stream، pending queueها، fallback state، map مربوط به UDP backend lineها |

## قابلیت‌های پشتیبانی‌نشده

این implementation خودش این موارد را ایجاد یا مدیریت نمی‌کند:

- TLS termination
- WebSocket، HTTP، gRPC یا transport wrapperهای دیگر
- composition قدیمی `TrojanAuthServer` به علاوه `TrojanSocksServer`
- extensionهای غیر استاندارد Trojan

وقتی به این layerها نیاز دارید، از نودهای جداگانه WaterWall مثل `TlsServer`، `HttpServer`، `MuxServer`،
`TcpUdpConnector` یا `Router` استفاده کنید.

## اشتباه‌های رایج

- `TrojanServer` را مستقیم روی TCP listener عمومی expose نکنید مگر اینکه عمدا Trojan plain روی wire بخواهید؛ برای حالت
  عادی قبل از آن `TlsServer` بگذارید.
- local passwordها را همراه `auth-client-node-name` تنظیم نکنید.
- `next` را روی یک `UserController` دستی نگذارید؛ database mode خودش `UserController` داخلی می‌سازد.
- برای configهای جدید از node nameهای قدیمی `TrojanAuthServer` و `TrojanSocksServer` استفاده نکنید.
- انتظار نداشته باشید آدرس اولیه UDP ASSOCIATE مقصد نهایی UDP را تعیین کند؛ هر Trojan UDP packet آدرس مقصد خودش را حمل
  می‌کند.

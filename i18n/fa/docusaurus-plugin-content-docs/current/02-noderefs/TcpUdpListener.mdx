# TcpUdpListener

`TcpUdpListener` یک wrapper از نوع chain-head روی `TcpListener` و `UdpListener` است. این نود یک listener داخلی TCP و یک listener داخلی UDP با همان تنظیمات می‌سازد تا یک entry واحد WaterWall بتواند هم ترافیک TCP و هم UDP را روی همان address و port set بپذیرد.

این نود TCP را به UDP تبدیل نمی‌کند و UDP را هم به TCP تبدیل نمی‌کند. فقط به هر دو adapter ترافیک ورودی اجازه می‌دهد به یک نود بعدی مشترک تغذیه کنند.

## جایگاه رایج

از `TcpUdpListener` وقتی استفاده کنید که همان سرویس entry باید هم TCP و هم UDP را بپذیرد:

```text
TcpUdpListener -> SpeedTestServer
TcpUdpListener -> SniffRouter -> TcpUdpConnector
TcpUdpListener -> Router -> ...
```

نود بعدی باید برای ترافیکی که در واقع دریافت می‌کنید مناسب باشد. اگر در production هم TCP و هم UDP وارد می‌شود، نود بعدی باید هم TCP lineهای معمولی و هم UDP peer lineها را بفهمد یا آن‌ها را بر اساس protocol route کند.

## نمونه ساده

```json
[
  {
    "name": "mixed-in",
    "type": "TcpUdpListener",
    "settings": {
      "address": "0.0.0.0",
      "port": 443,
      "nodelay": true,
      "large-send-buffer": true,
      "large-recv-buffer": true
    },
    "next": "mixed-out"
  },
  {
    "name": "mixed-out",
    "type": "TcpUdpConnector",
    "settings": {
      "address": "127.0.0.1",
      "port": 8443,
      "reuseaddr": true,
      "nodelay": true
    }
  }
]
```

در این مثال، TCP ورودی روی port `443` از child داخلی `TcpListener` forward می‌شود و UDP ورودی روی همان port از child داخلی `UdpListener`. `TcpUdpConnector` مشترک در انتهای chain بر اساس protocol metadata line انتخاب می‌کند که خروجی TCP باشد یا UDP.

## نمونه multiport

```json
{
  "name": "mixed-public-entry",
  "type": "TcpUdpListener",
  "settings": {
    "address": "0.0.0.0",
    "port": [
      443,
      8443
    ],
    "nodelay": true,
    "large-send-buffer": true,
    "large-recv-buffer": true,
    "interface": "eth0",
    "fwmark": 10,
    "balance-group": "public-mixed",
    "balance-interval": 30000,
    "multiport-backend": "socket",
    "whitelist": [
      "192.0.2.0/24",
      "2001:db8::/64"
    ],
    "blacklist": [
      "192.0.2.99/32"
    ]
  },
  "next": "next-node"
}
```

همین port list برای TCP و UDP استفاده می‌شود. TCP port `443` و UDP port `443` دو socket protocol جداگانه هستند و می‌توانند همزمان bind شوند.

## فیلدهای ضروری

فیلدهای سطح بالا:

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `name` | string | نام دلخواه نود. باید داخل فایل config یکتا باشد. |
| `type` | string | باید دقیقاً `"TcpUdpListener"` باشد. |
| `settings` | object | تنظیمات مشترک که به هر دو listener داخلی داده می‌شوند. باید object غیرخالی باشد. |
| `next` | string | نودی که هم TCP lineها و هم UDP peer lineها را دریافت می‌کند. |

فیلدهای ضروری داخل `settings`:

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `address` | string | آدرس bind محلی برای هر دو child listener. |
| `port` یا `port-range` | عدد، آرایه، یا آرایه بازه | تعریف port که هم توسط TCP و هم UDP listener استفاده می‌شود. دقیقاً یکی از این دو لازم است. |

## تنظیم پورت

`TcpUdpListener` syntax پورت listener را از `TcpListener` و `UdpListener` به ارث می‌برد.

### یک پورت

```json
{
  "settings": {
    "address": "0.0.0.0",
    "port": 443
  }
}
```

### لیست پورت مشخص

```json
{
  "settings": {
    "address": "0.0.0.0",
    "port": [
      443,
      8443,
      2083
    ]
  }
}
```

این حالت فقط روی پورت‌های لیست‌شده برای هر دو TCP و UDP گوش می‌دهد.

### بازه پیوسته

```json
{
  "settings": {
    "address": "0.0.0.0",
    "port-range": [
      40000,
      40100
    ]
  }
}
```

`port-range` باید یک آرایه دو عضوی باشد: `[min, max]`.

## تنظیمات اختیاری

چون همان object `settings` به هر دو child listener داده می‌شود، بیشتر گزینه‌ها همان گزینه‌های مستند‌شده روی `TcpListener` و `UdpListener` هستند.

| گزینه | روی کدام child اثر دارد | توضیح |
| --- | --- | --- |
| `nodelay` | TCP child | فعال‌سازی `TCP_NODELAY` روی socketهای TCP پذیرفته‌شده. |
| `large-send-buffer` | TCP و UDP children | تنظیم `SO_SNDBUF` در صورت پشتیبانی. |
| `large-recv-buffer` | TCP و UDP children | تنظیم `SO_RCVBUF` در صورت پشتیبانی. |
| `interface` | TCP و UDP children | محدود کردن socketها به یک interface محلی در صورت پشتیبانی. |
| `fwmark` | TCP و UDP children | اعمال socket mark به سبک Linux در صورت پشتیبانی. |
| `balance-group` | TCP و UDP children | گروه‌بندی listenerهای سازگار هم‌پورت برای توزیع sticky. |
| `balance-interval` | TCP و UDP children | مدت sticky بودن clientها یا peerهای تکراری در یک balance group. |
| `initial-idle-timeout-ms` | TCP child | timeout اولیه idle قبل از فعالیت payload TCP سمت listener. |
| `active-idle-timeout-ms` | TCP child | timeout idle بعد از شروع فعالیت TCP. |
| `multiport-backend` | TCP و UDP children | backend برای `port-range` پیوسته: `"iptables"` یا `"socket"`. |
| `whitelist` | TCP و UDP children | IPها و محدوده‌های CIDR مجاز برای client یا peer. |
| `blacklist` | TCP و UDP children | IPها و محدوده‌های CIDR مسدود برای client یا peer. |

برای جزئیات دقیق socket، پیش‌فرض‌های timeout و multiport، صفحه‌های `TcpListener` و `UdpListener` را ببینید.

## جریان runtime

در startup، `TcpUdpListener` دو tunnel داخلی می‌سازد:

- `TcpListener` با نامی شبیه `<node-name>.tcp-listener`
- `UdpListener` با نامی شبیه `<node-name>.udp-listener`

هر دو child داخل chain درج می‌شوند. آن‌ها مالک socketهای واقعی و lifecycle line هستند:

- child داخلی `TcpListener` TCP socketها را accept می‌کند و TCP lineها می‌سازد
- child داخلی `UdpListener` UDP peer lineها می‌سازد
- callbackهای upstream از هر کدام از childها وارد `TcpUdpListener` می‌شوند
- `TcpUdpListener` upstream `Init`، `Payload`، `Pause`، `Resume`، `Est` و `Finish` را به `next` forward می‌کند

در مسیر downstream، نود بعدی به `TcpUdpListener` callback می‌زند. wrapper source protocol line را بررسی می‌کند:

| metadata protocol source | child downstream |
| --- | --- |
| TCP | child داخلی `TcpListener` |
| UDP | child داخلی `UdpListener` |
| missing یا TCP/UDP flag ابهام‌آمیز | خطای fatal در config یا routing |

به همین دلیل نودهای بعد از `TcpUdpListener` باید source protocol metadata line را حفظ کنند.

## مالکیت line

`TcpUdpListener` خودش هیچ per-line state ندارد. هیچ‌وقت line نمی‌سازد و هیچ‌وقت `lineDestroy()` صدا نمی‌زند.

مالکیت line با child adaptori که line را ساخته می‌ماند:

- TCP lineها متعلق به child داخلی `TcpListener` هستند
- UDP peer lineها متعلق به child داخلی `UdpListener` هستند

## متادیتای نود

| ویژگی | مقدار |
| --- | --- |
| Node flag | `kNodeFlagChainHead` |
| نود قبلی | مجاز نیست |
| نود بعدی | لازم است |
| layer group | `kNodeLayer4` |
| `required_padding_left` | `0` |
| اندازه line state | `0` |

## اشتباه‌های رایج

- از `TcpUdpListener` به عنوان protocol converter استفاده نکنید. هر دو protocol را می‌پذیرد، اما بین آن‌ها تبدیل نمی‌کند.
- آن را به نود بعدی که فقط TCP را می‌فهمد وصل نکنید اگر ترافیک UDP هم ممکن است بیاید.
- port set‌های متفاوت TCP و UDP روی این wrapper تنظیم نکنید؛ هر دو child listener همان settings را دریافت می‌کنند.
- source protocol metadata را قبل از اینکه callbackها به صورت downstream به این نود برگردند حذف یا خراب نکنید.

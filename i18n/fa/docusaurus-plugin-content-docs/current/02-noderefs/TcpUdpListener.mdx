# TcpUdpListener

`TcpUdpListener` یک wrapper از نوع chain-head روی `TcpListener` و `UdpListener` است. این نود یک listener داخلی TCP و یک
listener داخلی UDP با همان settings می‌سازد، تا یک entry واحد بتواند هم TCP و هم UDP را روی همان address و port set
قبول کند.

این نود TCP را به UDP تبدیل نمی‌کند و UDP را هم به TCP تبدیل نمی‌کند. فقط دو adapter ورودی را به یک نود بعدی مشترک وصل
می‌کند.

## جایگاه رایج

```text
TcpUdpListener -> SpeedTestServer
TcpUdpListener -> SniffRouter -> TcpUdpConnector
TcpUdpListener -> Router -> ...
```

نود بعدی باید برای ترافیکی که واقعا دریافت می‌کنید مناسب باشد. اگر در production هم TCP و هم UDP وارد می‌شود، نود بعدی
باید هر دو مدل line را بفهمد یا بر اساس protocol آنها را route کند.

## نمونه ساده

```json
[
  {
    "name": "mixed-in",
    "type": "TcpUdpListener",
    "settings": {
      "address": "0.0.0.0",
      "port": 443,
      "nodelay": true,
      "large-send-buffer": true,
      "large-recv-buffer": true
    },
    "next": "mixed-out"
  },
  {
    "name": "mixed-out",
    "type": "TcpUdpConnector",
    "settings": {
      "address": "127.0.0.1",
      "port": 8443,
      "reuseaddr": true,
      "nodelay": true
    }
  }
]
```

در این مثال، TCP ورودی روی port `443` از child داخلی `TcpListener` عبور می‌کند و UDP ورودی روی همان port از child داخلی
`UdpListener`. نود `TcpUdpConnector` در انتهای chain بر اساس protocol metadata انتخاب می‌کند که خروجی TCP باشد یا UDP.

## نمونه Multiport

```json
{
  "name": "mixed-public-entry",
  "type": "TcpUdpListener",
  "settings": {
    "address": "0.0.0.0",
    "port": [
      443,
      8443
    ],
    "nodelay": true,
    "large-send-buffer": true,
    "large-recv-buffer": true,
    "interface": "eth0",
    "fwmark": 10,
    "balance-group": "public-mixed",
    "balance-interval": 30000,
    "multiport-backend": "socket",
    "whitelist": [
      "192.0.2.0/24",
      "2001:db8::/64"
    ],
    "blacklist": [
      "192.0.2.99/32"
    ]
  },
  "next": "next-node"
}
```

همین port list برای TCP و UDP استفاده می‌شود. TCP port `443` و UDP port `443` دو protocol socket جدا هستند و همزمان bind
می‌شوند.

## فیلدهای لازم

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `name` | string | نام یکتای نود داخل config. |
| `type` | string | باید دقیقا `"TcpUdpListener"` باشد. |
| `settings` | object | settings مشترک برای هر دو listener داخلی. باید object غیرخالی باشد. |
| `next` | string | نودی که TCP lineها و UDP peer lineها را دریافت می‌کند. |

فیلدهای لازم داخل `settings`:

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `address` | string | آدرس bind محلی برای هر دو child listener. |
| `port` یا `port-range` | number, array, range array | تعریف port برای هر دو listener. دقیقا یکی از این دو باید وجود داشته باشد. |

## Port Configuration

`TcpUdpListener` همان syntax مربوط به `TcpListener` و `UdpListener` را استفاده می‌کند.

### یک Port

```json
{
  "settings": {
    "address": "0.0.0.0",
    "port": 443
  }
}
```

### لیست Port

```json
{
  "settings": {
    "address": "0.0.0.0",
    "port": [
      443,
      8443,
      2083
    ]
  }
}
```

این حالت فقط روی portهای لیست‌شده برای هر دو TCP و UDP listen می‌کند.

### بازه Port

```json
{
  "settings": {
    "address": "0.0.0.0",
    "port-range": [
      40000,
      40100
    ]
  }
}
```

`port-range` باید array دو عضوی `[min, max]` باشد.

## تنظیمات اختیاری

چون همان `settings` به هر دو child listener داده می‌شود، بیشتر optionها همان optionهای `TcpListener` و `UdpListener`
هستند.

| setting | روی کدام child اثر دارد | توضیح |
| --- | --- | --- |
| `nodelay` | TCP child | فعال‌سازی `TCP_NODELAY` روی socketهای TCP پذیرفته‌شده. |
| `large-send-buffer` | TCP و UDP | تنظیم `SO_SNDBUF` در صورت پشتیبانی. |
| `large-recv-buffer` | TCP و UDP | تنظیم `SO_RCVBUF` در صورت پشتیبانی. |
| `interface` | TCP و UDP | محدود کردن socketها به interface محلی در صورت پشتیبانی. |
| `fwmark` | TCP و UDP | اعمال mark لینوکسی در صورت پشتیبانی. |
| `balance-group` | TCP و UDP | sticky distribution بین listenerهای سازگار روی port مشترک. |
| `balance-interval` | TCP و UDP | مدت sticky بودن client یا peer در balance group. |
| `initial-idle-timeout-ms` | TCP child | timeout اولیه قبل از دیدن payload سمت listener. |
| `active-idle-timeout-ms` | TCP child | timeout بعد از شروع activity در TCP. |
| `multiport-backend` | TCP و UDP | backend برای `port-range`: مقدار `"iptables"` یا `"socket"`. |
| `whitelist` | TCP و UDP | IP یا CIDRهای مجاز. |
| `blacklist` | TCP و UDP | IP یا CIDRهای مسدود. |

برای جزئیات دقیق socketها، timeoutها و multiport، صفحه‌های `TcpListener` و `UdpListener` را ببینید.

## جریان Runtime

در startup، این نود دو tunnel داخلی می‌سازد:

- `TcpListener` با نامی شبیه `<node-name>.tcp-listener`
- `UdpListener` با نامی شبیه `<node-name>.udp-listener`

هر دو child داخل chain قرار می‌گیرند و مالک socket و lifecycle واقعی هستند:

- child داخلی `TcpListener` اتصال TCP را accept می‌کند و TCP line می‌سازد
- child داخلی `UdpListener` برای peerهای UDP line می‌سازد
- callbackهای upstream از هر دو child وارد `TcpUdpListener` می‌شوند
- `TcpUdpListener` callbackهای upstream شامل `Init`, `Payload`, `Pause`, `Resume`, `Est`, و `Finish` را به `next` forward می‌کند

در مسیر downstream، نود بعدی به `TcpUdpListener` callback می‌زند. wrapper از source protocol line استفاده می‌کند:

| metadata پروتکل source | child downstream |
| --- | --- |
| TCP | child داخلی `TcpListener` |
| UDP | child داخلی `UdpListener` |
| missing یا ambiguous | خطای fatal در config یا routing |

پس نودهای بعد از `TcpUdpListener` باید source protocol metadata را حفظ کنند.

## مالکیت Line

خود `TcpUdpListener` line state ندارد، line نمی‌سازد، و `lineDestroy()` صدا نمی‌زند.

مالک line همان child adapter است:

- TCP lineها را child داخلی `TcpListener` می‌سازد و مدیریت می‌کند
- UDP peer lineها را child داخلی `UdpListener` می‌سازد و مدیریت می‌کند

## متادیتای نود

| ویژگی | مقدار |
| --- | --- |
| Node flag | `kNodeFlagChainHead` |
| previous node | مجاز نیست |
| next node | لازم است |
| layer group | `kNodeLayer4` |
| `required_padding_left` | `0` |
| line state size | `0` |

## اشتباه‌های رایج

- این نود protocol converter نیست؛ فقط هر دو protocol را accept می‌کند.
- اگر UDP ممکن است وارد شود، آن را به نودی وصل نکنید که فقط TCP را می‌فهمد.
- برای TCP و UDP روی این wrapper port set جدا تعریف نکنید؛ settings مشترک است.
- source protocol metadata را قبل از برگشت downstream خراب یا حذف نکنید.

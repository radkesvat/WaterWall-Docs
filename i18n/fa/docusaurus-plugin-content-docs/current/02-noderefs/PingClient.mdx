# PingClient

`PingClient` یک pure packet tunnel لایه ۳ است که packetها را به شکل ICMP disguise می‌کند. این نود ping latency یا health-check نیست و per-connection line state ندارد.

## جهت جریان

| جهت | رفتار |
|---|---|
| upstream `Payload` | packet را براساس `strategy` wrap یا rewrite می‌کند و به سمت `next` می‌فرستد |
| downstream `Payload` | packetهای matching سمت مقابل را unwrap یا restore می‌کند و به سمت قبلی برمی‌گرداند |

`PingServer` هم همین مدل callback را دارد: upstream wrap و downstream unwrap.

## strategyها

| strategy | توضیح |
|---|---|
| `wrap-in-new-ip-and-icmp-header` | کل packet داخلی IPv4 را داخل outer IPv4 + ICMP echo قرار می‌دهد. `source` و `dest` اختیاری هستند؛ اگر نباشند از packet داخلی کپی می‌شوند. |
| `wrap-in-icmp-header-and-reuse-ipv4-addresses` | header IPv4 موجود را نگه می‌دارد، protocol را ICMP می‌کند، transport bytes را داخل ICMP payload می‌گذارد و trailer پنج‌بایتی اضافه می‌کند. پیش‌فرض فعلی. |
| `wrap-in-only-icmp-header` | ورودی را raw bytes فرض می‌کند و فقط ICMP echo header اضافه می‌کند؛ خروجی IP packet کامل نیست. |
| `change-only-ipv4-protocol-number` | فقط protocol number را از `swap-protocol` به ICMP تغییر می‌دهد و در برگشت دوباره restore می‌کند. |

## نمونه تنظیم

```json
{
  "name": "icmp-client",
  "type": "PingClient",
  "settings": {
    "strategy": "wrap-in-new-ip-and-icmp-header",
    "identifier": 4660,
    "check-identifier": true,
    "source": "198.51.100.10",
    "dest": "203.0.113.20",
    "xor-byte": 90,
    "roundup-size": true,
    "sequence-start": 0,
    "ttl": 64
  },
  "next": "raw-out"
}
```

## تنظیمات

| گزینه | پیش‌فرض | توضیح |
|---|---|---|
| `strategy` | `wrap-in-icmp-header-and-reuse-ipv4-addresses` | روش disguise |
| `identifier` | `44975` / `0xAFAF` | ICMP echo identifier |
| `check-identifier` | `true` | اگر فعال باشد، decapsulation فقط برای identifier برابر انجام می‌شود |
| `sequence-start` | `0` | sequence اولیه ICMP |
| `ipv4-id-start` | `0` | ID اولیه outer IPv4 در strategy اول |
| `ttl` | `64` | TTL outer IPv4 در strategy اول |
| `tos` | `0` | TOS outer IPv4 در strategy اول |
| `xor-byte` | غیرفعال | XOR روی ICMP payload در modeهای ICMP |
| `roundup-size` | `false` | padding تصادفی payload در modeهای ICMP |
| `roundup` | `false` | alias قدیمی `roundup-size` |
| `source` | از packet داخلی | اختیاری برای outer source در strategy اول |
| `dest` | از packet داخلی | اختیاری برای outer destination در strategy اول |
| `swap-protocol` | لازم برای protocol-swap | `TCP`، `UDP`، `ICMP` یا عدد `0..255` |
| `swap-identifier` | - | alias قدیمی `swap-protocol` |

## نکته‌ها

- `required_padding_left = 28` است، یعنی worst-case prepend برابر IPv4 header بیست‌بایتی + ICMP header هشت‌بایتی.
- این نود line state ندارد و روی worker packet line کار می‌کند.
- در reuse-header mode، fragmented IPv4 packet بدون تغییر عبور می‌کند.
- اگر `check-identifier` فعال باشد و identifier نخورد، packet بدون تغییر عبور می‌کند.
- `source` و `dest` هنگام decapsulation بررسی نمی‌شوند.
- legacy aliasهایی مثل `warp-*` و `change-only-ip4-packet-identifier-number` هنوز پذیرفته می‌شوند، ولی بهتر است config جدید از نام‌های canonical استفاده کند.

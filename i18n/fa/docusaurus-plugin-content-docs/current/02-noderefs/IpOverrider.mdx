# IpOverrider

`IpOverrider` آدرس‌های source و destination IP را داخل raw packet payload rewrite
می‌کند.

این نود یک packet tunnel لایه ۳ است. socket نمی‌سازد، line اتصال معمولی ایجاد
نمی‌کند و packet را buffer نمی‌کند. فقط packetهایی را که از یک chain packet عبور
می‌کنند بررسی می‌کند و fieldهای تنظیم‌شده IPv4 header را درجا تغییر می‌دهد.

## جایگاه رایج

نمونه chain packet:

```text
TunDevice -> IpOverrider -> RawSocket
```

```text
TunDevice -> WireGuardDevice -> IpOverrider -> UdpStatelessSocket
```

هر جایی در chain packet که بخواهید packet با source یا destination IP متفاوت از
نود خارج شود، می‌توانید از این نود استفاده کنید.

## عملکرد

- در upstream، IPv4 source را در صورت وجود rule تغییر می‌دهد.
- در upstream، IPv4 destination را در صورت وجود rule تغییر می‌دهد.
- در downstream، IPv4 source را در صورت وجود rule تغییر می‌دهد.
- در downstream، IPv4 destination را در صورت وجود rule تغییر می‌دهد.
- برای هر rule گزینه‌هایی مثل `chance` و `only120` دارد.
- برای هر rule می‌تواند یک IPv4 یا یک array غیرخالی از IPv4ها بگیرد.
- بعد از rewrite IPv4، packet را برای checksum recalculation علامت می‌زند.
- upstream را به `next` و downstream را به نود قبلی forward می‌کند.

نسخه فعلی می‌تواند در یک instance برای هر دو جهت و هر دو field rule مستقل داشته
باشد؛ بنابراین برای خیلی از سناریوهایی که قبلا چند `IpOverrider` پشت سر هم لازم
بود، حالا یک نود کافی است.

## نمونه تنظیم

قالب جدید چند-rule:

```json
{
  "name": "ip-rewrite",
  "type": "IpOverrider",
  "settings": {
    "up": {
      "source-ip": {
        "ipv4": "10.0.0.10"
      },
      "dest-ip": {
        "ipv4": "198.51.100.10",
        "only120": true
      }
    },
    "down": {
      "source-ip": {
        "ipv4": "203.0.113.10",
        "chance": 100
      },
      "dest-ip": {
        "ipv4": "10.0.0.20"
      }
    }
  },
  "next": "next-packet-node"
}
```

نمونه IPv4 array:

```json
{
  "name": "source-pool",
  "type": "IpOverrider",
  "settings": {
    "up": {
      "source-ip": {
        "ipv4": ["10.0.0.10", "10.0.0.11", "10.0.0.12"]
      }
    }
  },
  "next": "next-packet-node"
}
```

## قالب قدیمی

قالب قدیمی تک-rule هنوز پذیرفته می‌شود:

```json
{
  "name": "ip-rewrite-old",
  "type": "IpOverrider",
  "settings": {
    "direction": "up",
    "mode": "dest-ip",
    "ipv4": "198.51.100.10",
    "chance": 100,
    "only120": false
  },
  "next": "next-packet-node"
}
```

## فیلدهای لازم

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `name` | string | نام دلخواه و یکتا برای node. |
| `type` | string | باید دقیقا `"IpOverrider"` باشد. |
| `settings` | object | اجباری است و باید حداقل یک rewrite rule داشته باشد. |
| `next` | string | برای upstream forwarding معمولی لازم است. |

در چیدمان مفید، این نود باید یک packet node قبلی هم داشته باشد.

## قالب جدید چند-Rule

قالب پیشنهادی فعلی از objectهای `up` و/یا `down` استفاده می‌کند:

| مسیر rule | معنی |
| --- | --- |
| `settings.up.source-ip` | تغییر IPv4 source در مسیر upstream. |
| `settings.up.dest-ip` | تغییر IPv4 destination در مسیر upstream. |
| `settings.down.source-ip` | تغییر IPv4 source در مسیر downstream. |
| `settings.down.dest-ip` | تغییر IPv4 destination در مسیر downstream. |

حداقل یکی از این rule objectها باید وجود داشته باشد. اگر کلید `up` یا `down`
وجود داشته باشد، parser قالب جدید را انتخاب می‌کند و دیگر object را به عنوان
legacy settings نمی‌خواند.

هر rule باید `ipv4` یا `ipv6` داشته باشد.

## فیلدهای آدرس هر Rule

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `ipv4` | string یا array از string | آدرس IPv4 جایگزین یا لیست غیرخالی از IPv4ها. مقدارها باید IPv4 literal باشند، نه CIDR یا hostname. |
| `ipv6` | string | parse و ذخیره می‌شود، اما rewrite IPv6 در runtime فعلی غیرفعال است. |

اگر `ipv4` یک array باشد، هر packetی که rule روی آن apply می‌شود IPv4 بعدی آن
array را به صورت round-robin استفاده می‌کند. cursor برای هر rule جداست.

اگر در یک rule هم `ipv4` و هم `ipv6` باشد، `ipv4` استفاده می‌شود، چون parser اول
آن را بررسی می‌کند.

## گزینه‌های هر Rule

هر rule می‌تواند این گزینه‌ها را هم داشته باشد:

| فیلد | نوع | پیش‌فرض | توضیح |
| --- | --- | --- | --- |
| `chance` | درصد integer از `0` تا `100` | همیشه apply | احتمال apply شدن rule روی packet واجد شرایط. `100` یعنی همیشه، `0` یعنی هیچ‌وقت. |
| `only120` | boolean | `false` | اگر `true` باشد فقط روی IPv4 packetهایی اعمال می‌شود که total IP length آن‌ها `120` بایت یا کمتر است. |

ruleها مستقل ارزیابی می‌شوند. مثلا ممکن است `up.source-ip` روی یک packet اعمال
شود ولی `up.dest-ip` همان packet به خاطر `chance` یا `only120` skip شود.

## قالب Legacy

در قالب قدیمی یک rule مستقیم داخل `settings` تعریف می‌شود:

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `direction` | string | باید `"up"` یا `"down"` باشد. |
| `mode` | string | باید `"source-ip"` یا `"dest-ip"` باشد. |
| `ipv4` / `ipv6` | string، یا array برای `ipv4` | آدرس جایگزین برای rule انتخاب‌شده. |
| `chance` | integer percent | مثل قالب جدید. |
| `only120` | boolean | مثل قالب جدید. |

برای configهای جدید بهتر است از قالب جدید استفاده کنید، چون تا چهار rule را در
یک node پوشش می‌دهد.

## رفتار جهت‌ها

upstream payload:

1. `up.source-ip` بررسی می‌شود
2. `up.dest-ip` بررسی می‌شود
3. packet با `tunnelNextUpStreamPayload()` به `next` می‌رود

downstream payload:

1. `down.source-ip` بررسی می‌شود
2. `down.dest-ip` بررسی می‌شود
3. packet با `tunnelPrevDownStreamPayload()` به نود قبلی برمی‌گردد

اگر برای یک جهت rule وجود نداشته باشد، packet بدون تغییر عبور می‌کند.
`IpOverrider` chain را terminate نمی‌کند و packet را نگه نمی‌دارد.

## Checksum

وقتی IPv4 address rewrite شود، نود flag مربوط به checksum recalculation را روی
line set می‌کند. packet writer بعدی مسئول rebuild کردن checksumهای IPv4 و
transport است.

## Packet Line

`IpOverrider` یک pure packet tunnel است:

- lifecycle اتصال per-packet ندارد
- line ایجاد یا destroy نمی‌کند
- payload callbackها مسیر runtime اصلی هستند
- callbackهای stream-style مثل `Finish`، `Pause`، `Resume` و `Est` برای استفاده
  عادی معتبر نیستند

پیاده‌سازی برای packet lineها per-line state اختصاصی allocate نمی‌کند.

## محدودیت‌ها و Padding

| مقدار | اندازه |
| --- | --- |
| `required_padding_left` | `0 bytes` |
| بازه `chance` | `0` تا `100` |
| شرط `only120` | IPv4 total length برابر یا کمتر از `120` بایت |

این نود فقط fieldهای موجود در header را درجا rewrite می‌کند و به left padding
نیاز ندارد.

## نکته‌ها

- runtime فعلی فقط IPv4 header را rewrite می‌کند.
- IPv6 در config parse و ذخیره می‌شود، اما block مربوط به rewrite آن در سورس
  فعلا غیرفعال است.
- مقدارهای `ipv4` باید literal IPv4 باشند. CIDR و hostname reject می‌شوند.
- برای source IP spoofing واقعی باید شبکه و دیتاسنتر اجازه خروج packet با source
  غیرمحلی را بدهند؛ بسیاری از providerها چنین trafficی را drop می‌کنند.
- `IpOverrider` فقط IP address را تغییر می‌دهد و TCP/UDP port را rewrite نمی‌کند.

# StreamToPackets

`StreamToPackets` سمت معکوس `PacketsToStream` است. این نود یک stream معمولی را می‌گیرد، byteها را به عنوان concat خام packetهای IPv4 می‌خواند، مرز packet را از فیلد IPv4 `total-length` پیدا می‌کند، و هر packet را به نود packet-oriented بعدی می‌دهد.

:::warning
فرمت فعلی دیگر `2 bytes length + packet` نیست. فرمت فعلی raw concatenation از packetهای IPv4 است و هیچ length-prefix جداگانه‌ای ندارد.
:::

نام قدیمی این مفهوم در بعضی مستندات `DataAsPacket` بود، اما نوع فعلی نود `StreamToPackets` است.

## جایگاه رایج

```text
TcpListener -> StreamToPackets -> TunDevice
```

سناریوی دو سرور:

```text
server1: TunDevice -> PacketsToStream -> TcpConnector
server2: TcpListener -> StreamToPackets -> TunDevice
```

## نمونه تنظیم

```json
{
  "name": "stream-to-packet",
  "type": "StreamToPackets",
  "settings": {
    "sensitive-mode": true,
    "packet-validation-level": "hard"
  },
  "next": "packet-node"
}
```

## تنظیمات

| گزینه | پیش‌فرض | توضیح |
|---|---|---|
| `sensitive-mode` | `false` | پاسخ دادن به heartbeatهای `PacketsToStream` |
| `packet-validation-level` | `none` | اعتبارسنجی packetهای decode شده از stream؛ مقدارهای `none`، `loose` یا `hard` |

`StreamToPackets` تنظیم `interval-ms` یا `tolerance-ms` ندارد؛ timerها در سمت `PacketsToStream` هستند.

## رفتار

- فقط IPv4 را پشتیبانی می‌کند؛ IPv6 و non-IPv4 drop می‌شوند.
- از سمت stream byteها را buffer می‌کند تا یک packet کامل براساس IPv4 total-length برسد.
- اگر stream خراب یا garbage باشد، parser تلاش می‌کند روی header معتبر IPv4 بعدی resync کند.
- برای هر worker یک active stream line نگه می‌دارد تا packetهای برگشتی را به همان stream line بفرستد.
- اگر active stream line وجود نداشته باشد، pause باشد یا dead باشد، packet برگشتی drop می‌شود.
- اگر `line->recalculate_checksum` فعال باشد، checksum کامل IPv4 قبل از ارسال به stream تعمیر می‌شود.

## Sensitive Mode

اگر packet decode شده heartbeat ping باشد، یعنی IPv4 با protocol `0xFD` و payload پنج‌بایتی `0xFF`، این نود آن را به packet side نمی‌فرستد و روی همان stream line یک pong با payload پنج‌بایتی `0xDD` برمی‌گرداند.

## نکته‌ها

- این نود را معمولا با `PacketsToStream` در سمت مقابل جفت کنید.
- parser تا `65536 * 2` بایت buffer نگه می‌دارد و در overflow buffer را خالی می‌کند.
- برای بازسازی flowهای TCP/UDP به lineهای عادی WaterWall از `PacketsToConnection` استفاده کنید.

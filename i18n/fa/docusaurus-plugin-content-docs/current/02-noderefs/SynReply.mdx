# SynReply

`SynReply` یک node داخلی و قابل تنظیم برای میانهٔ یک chain لایهٔ ۳ است.
آن را بین دو node لایهٔ ۳ قرار دهید که از packet line همان worker استفاده می‌کنند.
این packet line متعلق به chain است.

```text
RawSocket -> SynReply -> TunDevice
```

این node هر بستهٔ اصلی را بدون تغییر عبور می‌دهد. فقط یک SYN آغازگر IPv4 TCP
که از مسیر upstream می‌رسد و کامل، بدون قطعه‌بندی و بدون payload است، در صورت
معتبر بودن header‌ها، گزینه‌ها و checksumهای IPv4 و TCP پاسخ می‌گیرد. وجود
گزینه‌های معتبر یا پرچم‌های ECN مانع پاسخ نیست. اعتبار checksum بر اساس
بایت‌های دریافتی سنجیده می‌شود و هر درخواست در انتظار ترمیم checksum روی بستهٔ
اصلی حفظ می‌شود.

اگر آدرس مبدأ یا مقصد، آدرس نامعین (`0.0.0.0`)، آدرس پخش محدود
(`255.255.255.255`) یا یک آدرس multicast (`224.0.0.0/4`) باشد، بسته بدون
پاسخ عبور می‌کند.

SynReply برای هر SYN واجد شرایط، از جمله هر بار ارسال مجدد، ابتدا بستهٔ اصلی را
به upstream می‌سپارد و سپس تا وقتی مسیر همان worker باز است، یک SYN-ACK تازه
در مسیر downstream می‌فرستد. مقصد پاسخ همان فرستندهٔ مشاهده‌شده است. ترافیک
downstream، از جمله پاسخ‌های یک listener واقعی TCP، بدون تغییر عبور می‌کند.

با تحویل SYN-ACK، کار SynReply برای آن پاسخ تمام می‌شود. وضعیت اتصال TCP و
مراحل بعدی handshake بر عهدهٔ دو سر اتصال هستند. این node به‌طور پیش‌فرض با
`INCLUDE_SYN_REPLY` در build فعال است.

## تنظیمات

| تنظیم | رفتار |
| --- | --- |
| `reply-source-ip` | آدرس صریح IPv4 اختیاری که مبدأ همهٔ SYN-ACKهای تولیدشده است. در حالت پیش‌فرض، مبدأ هر پاسخ آدرس مقصد همان SYN است. |

آدرس تنظیم‌شده در `reply-source-ip` باید متعلق به سروری باشد که SynReply را
اجرا می‌کند. node در زمان startup آدرس نامعین، پخش محدود و multicast را برای
این تنظیم رد می‌کند. رشتهٔ خالی،
`null`، نام میزبان، آدرس IPv6، CIDR و تنظیم‌های ناشناخته یا تکراری باعث رد
پیکربندی در startup می‌شوند.

## نمونه‌ها

این نمونه‌ها قطعه‌هایی از پیکربندی node هستند. در پیکربندی کامل، `packet-out`
را به‌عنوان node بعدی لایهٔ ۳ تعریف کنید.

اگر `settings` را حذف کنید یا آن را برابر `{}` بگذارید، به SYN مسیر upstream
با مقصد `192.0.2.10` از آدرس `192.0.2.10` پاسخ داده می‌شود.

```json
{
  "name": "syn-reply",
  "type": "SynReply",
  "next": "packet-out"
}
```

با تنظیم آدرس صریح، پاسخ همان SYN از `192.0.2.20` فرستاده می‌شود. در
پیکربندی عملی، آدرس اختصاص‌یافته به سرور خودتان را وارد کنید.

```json
{
  "name": "syn-reply",
  "type": "SynReply",
  "next": "packet-out",
  "settings": {
    "reply-source-ip": "192.0.2.20"
  }
}
```

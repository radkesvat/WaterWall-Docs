# Disturber

`Disturber` نود مخصوص تست است و رفتار شبکه خراب را داخل زنجیر شبیه‌سازی می‌کند:
قطع ناگهانی، loss، corruption، duplication، out-of-order، delay و dead-hang.

این نود برای تست مقاومت `Mux`، `TcpOverUdp`، `Http`، `Tls`، تونل‌های packet یا
تونل‌های سفارشی مفید است، چون می‌تواند شرایط شبکه بد را بدون ابزار خارجی داخل
خود WaterWall ایجاد کند.

:::warning
این نود عمداً کیفیت مسیر را خراب می‌کند. برای تست و debug مناسب است، نه
forwarding عادی production.
:::

## جایگاه رایج

```text
TesterClient -> Disturber -> TesterServer
```

یا اطراف تونلی که می‌خواهید تست کنید:

```text
TesterClient -> TunnelUnderTest -> Disturber -> PeerUnderTest -> TesterServer
```

`Disturber` خودش socket باز نمی‌کند و برای استفاده مفید به `next` نیاز دارد.

## نمونه تنظیم

```json
{
  "name": "disturber",
  "type": "Disturber",
  "settings": {
    "disturb-upstream": true,
    "disturb-downstream": true,
    "chance_instant_close": 5,
    "chance_middle_close": 2,
    "chance_payload_corruption": 3,
    "chance_payload_loss": 10,
    "chance_payload_duplication": 2,
    "chance_payload_out_of_order": 4,
    "chance_payload_delay": 15,
    "chance_connection_deadhang": 1,
    "delay_min_ms": 50,
    "delay_max_ms": 300
  },
  "next": "next-node"
}
```

## فیلدهای لازم

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `name` | string | نام node در config. |
| `type` | string | باید `"Disturber"` باشد. |
| `next` | string | نود بعدی برای forwarding upstream. |

`settings` اختیاری است. اگر حذف شود، chanceها مقدار پیش‌فرض خود را می‌گیرند.

## تنظیمات

| گزینه | نوع | پیش‌فرض | توضیح |
| --- | --- | --- | --- |
| `disturb-upstream` | boolean | `true` | فعال کردن disturbance روی upstream init و payload. |
| `disturb-downstream` | boolean | `false` | فعال کردن disturbance روی downstream init و payload. |
| `chance_instant_close` | درصد integer | `0` | احتمال بستن مسیر هنگام init. |
| `chance_middle_close` | درصد integer | `0` | احتمال بستن اتصال هنگام عبور payload. |
| `chance_payload_corruption` | درصد integer | `0` | احتمال تغییر بایت‌های payload. |
| `chance_payload_loss` | درصد integer | `0` | احتمال drop شدن payload. |
| `chance_payload_duplication` | درصد integer | `0` | احتمال ساخت یک کپی اضافه از payload. |
| `chance_payload_out_of_order` | درصد integer | `0` | احتمال نگه داشتن payload و ارسال آن کنار payload بعدی. |
| `chance_payload_delay` | درصد integer | `0` | احتمال delay دادن payload. |
| `chance_connection_deadhang` | درصد integer | `0` | احتمال dead-hang شدن یک جهت. |
| `delay_min_ms` | integer | `0` | حداقل delay. مقدار منفی به `0` تبدیل می‌شود. |
| `delay_max_ms` | integer | `0` | حداکثر delay. اگر از min کمتر باشد به min تبدیل می‌شود. |

مقادیر chance با `roll100` تفسیر می‌شوند: مقدار `<= 0` هرگز trigger نمی‌شود،
مقدار `>= 100` همیشه trigger می‌شود و عددهای `1` تا `99` درصد احتمال هستند.

## رفتار جهت‌ها

به صورت پیش‌فرض فقط upstream خراب می‌شود:

```json
{
  "disturb-upstream": true,
  "disturb-downstream": false
}
```

اگر می‌خواهید مسیر پاسخ هم خراب شود، `disturb-downstream` را `true` کنید.

اگر یک جهت غیرفعال باشد، payload همان جهت مستقیم forward می‌شود. callbackهای
`Est`، `Pause` و `Resume` هم به صورت عادی forward می‌شوند.

## ترتیب پردازش payload

برای هر payload در جهت فعال، Disturber این مراحل را به ترتیب بررسی می‌کند:

1. اگر جهت dead-hang شده باشد، payload drop می‌شود.
2. `chance_middle_close`
3. `chance_payload_loss`
4. `chance_payload_duplication`
5. `chance_payload_corruption`
6. آزاد کردن payload نگه‌داشته‌شده برای out-of-order
7. `chance_payload_out_of_order`
8. `chance_payload_delay`
9. `chance_connection_deadhang`
10. forwarding عادی

بعضی حالت‌ها مثل loss یا close پردازش را همان‌جا تمام می‌کنند. duplication
می‌تواند با حالت‌های بعدی ترکیب شود، چون قبل از ادامه پردازش یک buffer اضافه
می‌سازد.

## رفتار packet-line

`Disturber` نسبت به packet-line آگاه است. در lineهای عادی، close-like behavior
می‌تواند `Finish` بفرستد و state این نود را destroy کند. اما برای worker
packet-lineها، Disturber در runtime packet line را destroy نمی‌کند؛ به جای آن
جهت مربوط را dead-hang می‌کند و payloadهای بعدی را drop می‌کند.

این کار قانون lifetime مربوط به packet-lineهای WaterWall را حفظ می‌کند.

## نکته‌ها

- ترکیب چند chance بالا می‌تواند مسیر را خیلی سریع بسیار آشفته کند.
- corruption روی payload غیرخالی حداقل یک بایت و حداکثر حدود ۱۰ درصد payload را
  تغییر می‌دهد.
- برای delay، مقدار random بین `delay_min_ms` و `delay_max_ms` انتخاب می‌شود.
- `required_padding_left` این نود `0` است.
- API فعلی فقط پیام API را recycle می‌کند و runtime tuning ارائه نمی‌دهد.

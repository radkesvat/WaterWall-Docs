# UdpListener

`UdpListener` آداپتور سرور UDP است. روی یک آدرس و پورت UDP محلی گوش می‌دهد، datagramهای ورودی را بر اساس remote peer گروه‌بندی می‌کند، برای هر peer یک line در WaterWall می‌سازد و payloadها را به نود بعدی می‌فرستد.

جایگاه رایج:

```text
client -> UdpListener -> ... -> UdpConnector -> سرویس UDP راه دور
```

این نود معمولاً در ابتدای یک UDP stream-style chain قرار می‌گیرد.

## قابلیت‌ها

- گوش دادن روی یک پورت UDP، چند پورت مشخص، یا یک بازه پیوسته.
- دریافت datagramهای UDP ورودی از طریق socket manager WaterWall.
- اعمال فیلترهای اختیاری listener مثل `whitelist`، `blacklist` و گروه‌های balance.
- ساختن یک line برای هر remote peer address و port.
- ارسال datagramهای ورودی به عنوان payload upstream به نود بعدی.
- ارسال payload downstream به آدرس peer به‌خاطرسپاری‌شده.
- ردیابی peer lineها با idle timeout.

UDP ذاتاً connectionless است، اما `UdpListener` برای بقیه chain یک abstraction line پایدار به ازای هر peer فراهم می‌کند.

## نمونه تنظیم

```json
{
  "name": "udp-listener",
  "type": "UdpListener",
  "settings": {
    "address": "0.0.0.0",
    "port": [
      5353,
      853,
      123
    ],
    "large-send-buffer": true,
    "large-recv-buffer": true,
    "interface": "eth0",
    "fwmark": 10,
    "balance-group": "udp-public",
    "balance-interval": 30000,
    "multiport-backend": "socket",
    "whitelist": [
      "192.168.1.0/24",
      "2001:db8::/64"
    ],
    "blacklist": [
      "192.168.1.50/32"
    ]
  },
  "next": "next-node-name"
}
```

## فیلدهای ضروری

فیلدهای سطح بالا:

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `name` | string | نام دلخواه نود. باید داخل فایل config یکتا باشد. |
| `type` | string | باید دقیقاً `"UdpListener"` باشد. |
| `next` | string | نودی که UDP peer lineها و payloadها را دریافت می‌کند. |

فیلدهای ضروری داخل `settings`:

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `address` | string | آدرس bind محلی، مثل `"0.0.0.0"`، `"::"` یا یک IP محلی مشخص. |
| `port` یا `port-range` | عدد، آرایه، یا آرایه بازه | تعریف پورت گوش دادن. دقیقاً یکی از این دو فیلد لازم است. |

`settings` باید یک object غیرخالی باشد.

## تنظیم پورت

`UdpListener` سه حالت پورت دارد.

### یک پورت

```json
{
  "settings": {
    "address": "0.0.0.0",
    "port": 5353
  }
}
```

### لیست پورت مشخص

```json
{
  "settings": {
    "address": "0.0.0.0",
    "port": [
      5353,
      853,
      123
    ]
  }
}
```

این حالت فقط روی پورت‌های لیست‌شده گوش می‌دهد. بازه‌ای از `123` تا `5353` نیست.

### بازه پیوسته

```json
{
  "settings": {
    "address": "0.0.0.0",
    "port-range": [
      20000,
      20100
    ]
  }
}
```

`port-range` باید آرایه‌ای با دقیقاً دو پورت عدد صحیح مثبت باشد: `[min, max]`. مقدار کمینه باید کوچک‌تر یا برابر بیشینه باشد.

قوانین:

| قانون | رفتار |
| --- | --- |
| استفاده همزمان از `port` و `port-range` | شروع با خطا. |
| `port` عددی | روی یک پورت UDP گوش می‌دهد. |
| `port` آرایه | روی پورت‌های مشخص داخل آرایه گوش می‌دهد. |
| `port-range` آرایه | روی هر پورت UDP از کمینه تا بیشینه گوش می‌دهد. |
| پورت نامعتبر، صفر، منفی یا بزرگ‌تر از `65535` | شروع با خطا. |

:::warning
از فرم‌های قدیمی string مثل `"20000-20100"` استفاده نکنید. parser فعلی انتظار دارد `port-range` یک آرایه دو عضوی باشد.
:::

## تنظیمات اختیاری

| گزینه | نوع | پیش‌فرض | توضیح |
| --- | --- | --- | --- |
| `large-send-buffer` | boolean یا عدد مثبت | `true` | تنظیم `SO_SNDBUF` روی socket‌های UDP listener. |
| `large-recv-buffer` | boolean یا عدد مثبت | `true` | تنظیم `SO_RCVBUF` روی socket‌های UDP listener. |
| `interface` | string | تنظیم نشده | محدود کردن listener به یک interface محلی. |
| `fwmark` | integer | تنظیم نشده | اعمال socket mark به سبک Linux در صورت پشتیبانی. |
| `balance-group` | string | تنظیم نشده | گروه‌بندی listenerهای سازگار هم‌پورت برای توزیع sticky. |
| `balance-interval` | integer، میلی‌ثانیه | پیش‌فرض socket manager | مدت sticky بودن peerهای تکراری در یک balance group. |
| `multiport-backend` | string | پیش‌فرض runtime برای `port-range` | backend برای بازه‌های پیوسته: `"iptables"` یا `"socket"`. |
| `whitelist` | آرایه string | تنظیم نشده | IPها یا محدوده‌های CIDR مجاز برای peer. |
| `blacklist` | آرایه string | تنظیم نشده | IPها یا محدوده‌های CIDR مسدود برای peer. |

### گزینه‌های socket buffer

`large-send-buffer` و `large-recv-buffer` مقادیر زیر را می‌پذیرند:

| مقدار | معنا |
| --- | --- |
| `true` | استفاده از buffer socket بزرگ پیش‌فرض WaterWall که فعلاً `4194304` بایت است. |
| `false` | عدم تنظیم صریح این socket buffer؛ استفاده از پیش‌فرض kernel. |
| عدد مثبت | درخواست مستقیم آن تعداد بایت. |

هر دو گزینه پیش‌فرض buffer socket بزرگ WaterWall را برای UDP listenerها به‌کار می‌برند.

### interface و `fwmark`

`interface` listener را به یک network device محلی محدود می‌کند.

در Linux، WaterWall از `SO_BINDTODEVICE` استفاده می‌کند. روی platformهایی که device binding ندارند، WaterWall در صورت امکان از bind کردن به آدرس IPv4 interface استفاده می‌کند.

`fwmark` از `SO_MARK` روی platformهایی که آن را ارائه می‌دهند استفاده می‌کند. به platform وابسته است و روی Windows در دسترس نیست.

## فیلتر و توزیع

فیلتر و توزیع در socket manager مشترک قبل از تحویل datagram به `UdpListener` انجام می‌شوند.

| گزینه | رفتار |
| --- | --- |
| `whitelist` | در صورت تنظیم، فقط peer IPهای match‌شده پذیرفته می‌شوند. |
| `blacklist` | peer IPهای match‌شده رد می‌شوند. |
| `balance-group` | توزیع sticky peer را بین listenerهای سازگار روی همان پورت فعال می‌کند. |
| `balance-interval` | مدت زمانی را که یک peer به listener انتخاب‌شده sticky می‌ماند کنترل می‌کند. |
| `multiport-backend` | نحوه پیاده‌سازی یک listener `port-range` پیوسته را کنترل می‌کند. |

وقتی هر دو لیست ACL تنظیم شده‌اند، peer باید با whitelist مطابقت داشته باشد و با blacklist مطابقت نداشته باشد.

نمونه:

```json
{
  "settings": {
    "address": "0.0.0.0",
    "port": 5353,
    "whitelist": [
      "10.0.0.0/8",
      "203.0.113.10/32",
      "2001:db8::/64"
    ],
    "blacklist": [
      "10.0.0.99/32"
    ]
  }
}
```

## مدل line per-peer

UDP اتصال transport ندارد، بنابراین `UdpListener` یک مدل pseudo-connection برای chain می‌سازد.

برای هر remote peer address و port یکتا روی یک socket گوش‌دهنده:

1. یک line جدید WaterWall روی اولین datagram پذیرفته‌شده ساخته می‌شود.
2. آدرس peer در وضعیت line listener ذخیره می‌شود.
3. datagramهای بعدی از همان peer تا انقضا از همان line استفاده می‌کنند.
4. payloadهای downstream روی آن line به peer به‌خاطرسپاری‌شده برگشت داده می‌شوند.

این اجازه می‌دهد نودهای stream-style بعدی با ترافیک UDP با استفاده از callbackهای معمولی WaterWall line کار کنند.

## جریان داده

از peer به chain:

```text
datagram UDP -> UdpListener -> payload upstream -> نود بعدی
```

از chain به peer:

```text
payload downstream قبلی -> UdpListener -> ارسال UDP به peer به‌خاطرسپاری‌شده
```

source context line از آدرس socket peer پر می‌شود و به عنوان UDP علامت‌گذاری می‌شود.

## معناشناسی establishment

یک peer line جدید روی اولین datagram پذیرفته‌شده ساخته می‌شود. line فقط وقتی یک callback downstream `est` از نود بعدی به `UdpListener` برسد established می‌شود.

## رفتار pause

`UdpListener` datagramهای ورودی را در حالی که یک peer line در pause است صف نمی‌کند.

اگر یک datagram از یک peer line paused برسد:

- datagram drop می‌شود
- line زنده می‌ماند
- بعد از resume، datagramهای جدید از آن peer می‌توانند دوباره forward شوند

این با backpressure سبک TCP متفاوت است. برای این نود، pause یعنی drop، نه buffer.

## idle timeout

هر peer line در یک جدول idle ردیابی می‌شود.

timeout‌های فعلی:

| وضعیت | timeout |
| --- | --- |
| peer line تازه ساخته‌شده | حدود `30 ثانیه` |
| peer فعال بعد از ادامه ترافیک | حدود `300 ثانیه` |

اگر peer line منقضی شود، `UdpListener` upstream `finish` می‌فرستد و line ساخته‌شده را از بین می‌برد.

## نکات و هشدارها

- `UdpListener` یک نود UDP chain-head است و به `next` نیاز دارد.
- آرایه‌های `port` لیست‌های مشخص هستند، نه بازه.
- از `port-range` برای بازه‌های پیوسته استفاده کنید.
- `whitelist` و `blacklist` از string‌های CIDR IPv4 و IPv6 پشتیبانی می‌کنند.
- `fwmark` و device binding به platform وابسته هستند.
- peer lineهای paused datagramهای ورودی را به جای buffer کردن drop می‌کنند.
- برای رفتار UDP stateless در سطح packet، `UdpStatelessSocket` ممکن است مناسب‌تر از `UdpListener` باشد.

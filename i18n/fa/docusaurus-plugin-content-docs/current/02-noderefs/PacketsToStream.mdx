# PacketsToStream

`PacketsToStream` یک bridge از سمت packet به سمت stream است. این نود packetهای IPv4 را از سمت قبلی می‌گیرد، برای هر worker یک line سمت stream می‌سازد یا reuse می‌کند، و packet را بدون header اضافه روی stream می‌فرستد.

:::warning
فرمت فعلی دیگر `2 bytes length + packet` نیست. فرمت فعلی raw concatenation از packetهای IPv4 است و مرز هر packet از فیلد IPv4 `total-length` خوانده می‌شود.
:::

نام قدیمی این مفهوم در بعضی مستندات `PacketAsData` بود، اما نوع فعلی نود `PacketsToStream` است.

## جایگاه رایج

```text
TunDevice -> PacketsToStream -> TcpConnector
TcpListener -> StreamToPackets -> TunDevice
```

`PacketsToStream` معمولا با `StreamToPackets` در سمت مقابل جفت می‌شود.

## نمونه تنظیم

```json
{
  "name": "packet-to-stream",
  "type": "PacketsToStream",
  "settings": {
    "sensitive-mode": true,
    "interval-ms": 50,
    "tolerance-ms": 150,
    "packet-validation-level": "hard"
  },
  "next": "stream-node"
}
```

## تنظیمات

| گزینه | پیش‌فرض | توضیح |
|---|---|---|
| `sensitive-mode` | `false` | فعال‌سازی heartbeat روی line سمت stream |
| `interval-ms` | `50` | فاصله ارسال heartbeat؛ حداقل `1` |
| `tolerance-ms` | `150` | حداکثر زمان انتظار برای pong؛ حداقل `1` |
| `packet-validation-level` | `none` | اعتبارسنجی packetهای decode شده از stream؛ مقدارهای `none`، `loose` یا `hard` |

## رفتار

- فقط IPv4 را پشتیبانی می‌کند؛ IPv6 و non-IPv4 drop می‌شوند.
- packet باید self-consistent باشد و طول buffer با IPv4 total-length برابر باشد.
- اگر `line->recalculate_checksum` فعال باشد، checksum کامل IPv4 قبل از ارسال تعمیر می‌شود.
- مسیر برگشت stream را buffer می‌کند و با IPv4 total-length دوباره packetها را جدا می‌کند.
- اگر line سمت stream بسته شود یا heartbeat timeout شود، line جدید ساخته و init می‌شود.
- packet line مشترک worker در runtime بسته نمی‌شود.

## Sensitive Mode

در این حالت heartbeat هم خودش یک packet معتبر IPv4 است:

- ping با protocol `0xFD` و payload پنج‌بایتی `0xFF`
- pong با protocol `0xFD` و payload پنج‌بایتی `0xDD`

این packetهای کنترل به سمت packet side ارسال نمی‌شوند.

## نکته‌ها

- این نود length-prefix اضافه نمی‌کند.
- parser برگشت تا `65536 * 2` بایت buffer نگه می‌دارد و در overflow buffer را خالی می‌کند.
- برای تبدیل transport flow به lineهای عادی WaterWall از `PacketsToConnection` استفاده کنید، نه این نود.
